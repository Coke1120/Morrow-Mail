# Synthetic MBOX import evidence

Proposed #521 implementation, dependent on the Local Folders foundation
[PR #524](https://github.com/Coke1120/Morrow-Mail/pull/524), whose head was verified
as `6fcfce38200ad8bfa41ff4fa652040a06545d44e` before implementation. The feature
branch incorporates dev `e0ca1151e8fbf08929266463afbda6a382583786`; the PR targets
dev and requires that dependency review. No merge or release is included.

All data is generated by the checked-in scripts. Tests use temporary databases,
synthetic `.invalid` addresses, fake provider/credential adapters and a loopback
browser server. No real mailbox, Thunderbird profile, AI or live provider was used.

## Checks

```sh
node scripts/check-mbox-import.js
node scripts/check-mbox-import-ui.js
node scripts/check-mbox-import-host.js
CI=1 npm run check
MORROW_UI_OUTPUT=/tmp/morrow-mbox-browser node scripts/check-mbox-import-browser.js
```

The browser check needs local Playwright and Chromium; set
`MORROW_PLAYWRIGHT_MODULE` or `CHROMIUM_PATH` for other local installations.
Host, storage and DOM checks are registered in the standard Linux/Windows suite.

The 25 focused storage/parser cases cover explicit mboxrd/mboxo, LF/CRLF and
one-byte chunk boundaries, no final newline, ordinary/escaped From lines,
ambiguous separators, extensionless Thunderbird sources, Unicode and legacy or
unknown charsets, binary/inline MIME attachments and thread/date headers,
deleted/Partial/queued status handling, duplicate imports after rename/move,
distinct same-ID and missing-ID content, separate destinations, empty/multiple
files, unsupported MSF/SBD/EML/Content-Length, malformed/truncated MIME and bounded
oversized entries/lines/headers. Worker cancellation/deadlines, byte-budget pause,
source changes/replacement, corrupt snapshots and byte-identical snapshot restore
with a changed filesystem identity are exercised.

Storage fault checks exercise real SQLite FULL, transaction rollback of message
and progress, corrupt progress checksums, read/fsync/rename faults during snapshot
publication, and abrupt child-process exits during staging and immediately
before/after the SQLite commit. Reopen/Continue checks counts, offsets and stored
MIME, without automatic work or duplicate acknowledgement. Explicit snapshot
removal retains original sources, local mail and duplicate receipts.

The streaming fixture writes 41,949,400 bytes of synthetic input (40 bounded
messages) to disk. The largest returned message is 1,048,703 bytes and interval
heartbeats advance during reading. This demonstrates cooperative bounded input
processing, not a native frame-time or whole-process RSS guarantee. Production
limits remain the ones documented in [MBOX_IMPORT.md](../../MBOX_IMPORT.md).

The actual first-party preload and engine test uses the native-picker-shaped
mock, ignores renderer-supplied paths, participates in updater admission and
verifies original MIME, search and binary attachments after provider account
removal and archive reopen. Credential/provider call counts stay zero. Unreviewed
snapshot removal and unknown invoke channels are rejected.

Two DOM cases run the real renderer and temporary archive/import service. They
cover destination creation, file/format/duplicate review, frozen choices while
running, accurate results, Stop/Escape, restart choices, stale dialog close
events, focus return, and the rendered Features/CLI descriptions.

Chromium checks 1440/390px, both light/dark themes, keyboard Escape/focus return,
reduced motion, successful import/result and the existing offline reader. Imported
script markup stays inert and remote images make no external request in the
blocked-content fixture. No page errors or external requests were observed.

## Limits of this evidence

Native Windows/macOS picker behavior, real Thunderbird export/profile variants,
screen-reader acceptance and power loss are unverified. Configured Windows CI
provides synthetic host/storage/DOM coverage, not native UI certification.
Private snapshot space and full verification passes are an intentional cost.
SQLite, JSON/checksum work and commits are synchronous per bounded message.
There is no claim of semantic deduplication of rewritten mail, recursive profile
import, all possible MBOX dialects, CLI/bot access or automatic restart import.
Use the explicit format/limit and failure details in the import dialog and docs.
