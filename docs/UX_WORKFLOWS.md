# Workflow recovery and receipts

Agent and Brain reply proposals resolve their own source message and mailbox. Missing or mismatched sources block review. Opening a proposal never sends or schedules it. Bot proposals retain their separate account-bound seed and human Send gate.

Close discards unsaved compose changes after a confirm and does not save. The compose window's close button uses that same confirm. Save draft is a separate action and leaves the composer open. Discard leaves a previously saved copy unchanged. Drafts have a Resume draft action; saving again uses the same ID. Undo Send reopens the pending composition, and an unconfirmed delivery reopens it with its recipients, account, reply headers, quote, and text intact. Check Sent before retrying an uncertain delivery. The local Undo delay cannot recall a send once provider delivery begins. A queued composition becomes a scheduled receipt and locks delivery and editing controls, including late AI updates. Mail → Scheduled opens the all-account queue without starting a composition. Each item shows its mailbox, local date/time and timezone, and pending/sending/failed state. Unknown queue reads offer Retry. Edit/reschedule explicitly removes the queued delivery and atomically saves a local draft; the user must review and authorize a new schedule. Failed deliveries warn to check Sent before retrying. Cancellation/editing cannot recall a delivery already in progress; the pump rechecks later due rows after awaiting another send. Queued attachments are deliberately refused by this composer without changing the queue.

Mail changes return per-message `outcomes`: `completed`, `failed`, `unknown`, or `not_attempted`. Remote exceptions are conservatively unknown. Only confirmed moves with a verified destination identity receive Undo IDs. Undo verifies the current destination and never substitutes a local snapshot for a failed remote restore. An uncertain Undo is consumed rather than automatically retried. Receipts retain their errors beside Undo, and unresolved rows remain selected when still loaded. Sync events update the sync control instead of replacing an action receipt.

Freshness is scoped to an account and folder. Empty profiles show No account connected; page refreshes do not update mail freshness. Search covers downloaded subject, sender, and available message text, up to 100 results. A second list filter is visible and removable. Select shown counts loaded visible rows. Account-limited moves and labels explain excluded rows. Conversation removal resolves cached members and freezes the reviewed IDs before confirmation.

Bot access proceeds through four numbered steps: bot creation and account/permission selection, one-time secret copy, turning on local access, optional remote address setup, and bot setup. Activity stays separate from setup. Saved enable intent is separate from actual listening. Last successful use is evidence of bot use; valid access alone is not. Turning access off stops the listener without revoking bots. Sending requires the Send mail from these mailboxes permission and a confirmation that lists the selected mailboxes. Secrets are cleared on dialog close and cannot be redisplayed. A saved remote address stays Not checked until Check connection. A foreign answer shows a guided Serve fix and does not run Tailscale. Delete removes a bot row after confirm; Revoke only invalidates the secret.

Rules have a dedicated mailbox selector, generation checks on loads, and account-bound save/delete/grant operations. Dirty account changes and broad/destructive rule saves are reviewed. Out of Office confirmation describes server replies, audience, effective dates, timezone, and reply excerpts; IMAP review shows the actual whole UTC days. Existing purpose-specific grants and Sieve guards are unchanged.

Validation:

- `npm run check` runs offline host and renderer-function checks, including `bot-bridge-ok`, `operation-receipts-ok`, `compose-recovery-ok`, `dialog-feedback-ok`, `search-scope-ok`, `rules-context-ok`, and `ui-path-ok`.
- `npx electron scripts/check-ux-renderer.cjs` runs the isolated renderer fixture. Linux CI can use `xvfb-run -a npx electron --no-sandbox scripts/check-ux-renderer.cjs`. It uses a temporary profile, mocked IPC, and blocked HTTP(S); it loads no production host modules. Set `MORROW_UX_EVIDENCE_DIR` to save synthetic screenshots and a result summary.

Settings has an explicit mailbox selector, a per-feature permission summary, named Reconnect, and an existing-user recovery explanation. Reconnect checks the selected address before saving credentials and retains cached work. Signatures bind to the editor mailbox, rules keep their own dirty-switch guard, and Out of Office rejects stale loads and confirms discarding unsaved edits before a mailbox switch. Mail selection stays independent. An empty profile is not evidence that older local data was migrated; the help route explains this and points to support logs.

Mail shows observed Out of Office state for its selected account, including unknown/unavailable/permission-needed states and a checked timestamp. A failed start or account fetch rechecks a few times and shows Retrying… until a read succeeds or those rechecks are done; further automatic reads wait until Refresh or a later selection. Refresh rereads; Manage/disable opens Settings for that mailbox. Provider dates are shown in the local timezone; IMAP summaries show the effective whole UTC days. The original separate grants, provider conflict checks, and active Sieve script guards remain intact. This is observed status, not a real-time subscription to provider changes.

Agent explains questions and reviewed actions; Brain explains the profile, preferences, skills, categories, and rules. Missing AI/mailbox setup has direct buttons. Manage Skills offers Return to Agent. The Todos hint is once. Done and Dismiss only update the local Agent list. Peek does not send mail. Skill schedules distinguish on demand, scheduled, and paused, with observed next run and app-open/missed-run behavior. Draft cards verify their source to display account and recipients; opening them does not authorize delivery. Filing cards show source, mailbox, destination, action, and state and require a separate provider confirmation.

Shortcuts sits above Debug log. Delete and Backspace move the open message to Trash when you are not typing. R, A, and F reply, reply all, and forward. Ctrl or ⌘N opens New Mail. Ctrl or ⌘Enter sends and Ctrl or ⌘S saves a draft while compose is open. Ctrl or ⌘F, or /, focuses mail search when you are not typing elsewhere. Esc still closes the compose window and overlays, and still clears a selection when that already applied. Ctrl or ⌘, opens Settings. Reply does not use Ctrl+R or ⌘R, because View → Reload keeps that chord. Zoom stays on the View menu.

Settings links to Debug log and About & updates. Both updater surfaces paint the same observed state: not checked, last successfully checked, and Restart and install, with auto-install-on-quit disclosure when ready. A failed check does not record a successful check. Logs combine up to 200 recent host/renderer session lines, filter by source, include date/timezone, and offer a redacted preview before copy. Known patterns are removed, including quoted credentials and modern key prefixes; addresses and other diagnostic context may remain. Copy failure keeps the preview available for manual copying.

New profiles start with rail labels visible, then respect the existing saved collapse choice. AI write opens from the formatting toolbar. Send later stays its own control. The AI-on-reply preference still opens AI tools. Preview hiding never omits the quoted original. Empty states describe downloaded/local scope and mark-read failures remain visible while the message stays readable. Search help describes word prefixes, without inventing Gmail query syntax. Motion, icons, reduced motion, green branding, and Bot boundaries are preserved.

Additional offline checks: `scheduled-management-ok` exercises durable queue-to-draft conversion, attachment refusal, and cancellation/edit races; `ux-remainder-ok` exercises Settings account/dirty/stale-response rules, OOO dates, proposal provenance, setup copy, update observations, redaction, saved rail preferences, and nonblocking read failures. Account-recovery tests cover mismatched reconnect consent. The expanded Electron fixture covers the new visible flows and screenshots.

Remaining out-of-scope work: real attachment forwarding and migration of older profiles. Native packaged updates, OS credential stores, and live provider behavior need separate validation; this pass uses no live mailbox writes or credentials.
