## Accounts with a clear settings target

Settings → Accounts opens on Your accounts with a prominent Add account action.
Account cards show the full identity, provider/transport and connection or sign-in
status. Settings appear immediately for the current account, with a first-account
fallback and a clear empty state. Reconnect, Inbox Automation, Signatures,
Out of Office, permissions and reviewed removal stay beneath that account's
identity. Credential help and the computer-wide optional Google client remain
separate; sender names and aliases stay in Compose.

Settings selection is pinned independently of Mail. Unsaved Out of Office edits
still require discard confirmation before switching. Removed targets and late
permission replies cannot retarget the current settings; keyboard focus moves to
the surviving account card or Add account after removal.

## Folder chips without duplicates

Mailbox folder chips show one canonical name per enabled role (Inbox, Sent,
Drafts, Starred, Unread, Trash, Junk, Archived, plus All Mail or Important when
enabled). Sent Items, Sent Mail and casing variants share one Sent chip. Chips
stay in a fixed order and belong to the selected mailbox—they never merge every
account's raw folder names. Selecting another folder with the same role keeps
that real folder selected; all server folders remain available in the sidebar.

All Account Mail keeps its Inbox, Outbox, Starred and Unread sidebar views.
Cross-account Sent, Drafts, Trash, Junk and Archived chips remain unavailable.

## Consistent colorful sidebar icons

Expanded IMAP, Gmail and Outlook accounts share the same colorful folder icons
for known roles (including wellKnown / wellKnownName aliases). Custom folders
keep a generic folder icon. Saved account expansion choices are unchanged.

## Integration and validation limits

Synthetic checks cover account switching, empty/single/multiple account states,
unsaved-edit and stale-response protections, keyboard focus, chip role dedupe,
sidebar icon aliases, Features catalog parity and related mail-view / folder
scripts. Chromium checks cover five viewport sizes in light/dark themes with
no horizontal overflow or axe WCAG A/AA violations. The standalone Linux
Electron navigation runner crashed before assertions in the display-less
container; native Windows/macOS UI validation has not been performed.
Publication uses the existing
Windows-then-macOS pipeline. Windows remains unsigned; macOS remains ad hoc
signed without Developer ID or notarization. Live mail accounts and installed
updater transitions remain unverified. No signing roots, secrets or release
gates are changed.
