# Morrow Mail 0.7.2

This release repairs gaps in downloaded mail, makes incomplete content visible and recoverable, and improves native reader, composer and paging recovery. Windows keeps the current mailbox, page and reader context while restoring keyboard focus, with macOS as the behavioral reference.

## Changes

- **IMAP import dates and retries:** recent and older history use the server's INTERNALDATE consistently, including timezone boundaries, while preserving the sender date separately. Recognized transient read failures retain their checkpoint and persisted backoff. Missing FETCH data is skipped only after the server confirms that the UID was expunged; unresolved data keeps its checkpoint and reports an error.
- **Outlook catch-up and bounded content:** expired delta checkpoints retain the original live-sync boundary and the approved import range. Lists fetch metadata before individually bounded bodies, so one oversized body no longer stops healthy messages on the same page. Graph JSON and raw reads share a process-wide four-request limit. Missing or invalid applicable provider dates stop the page safely instead of advancing its checkpoint.
- **Gmail labels and older content:** reading supports up to 10,000 labels independently of the 1,000-entry organization-destination limit. Older incomplete caches receive full content when reconciled, including missing Reply-To metadata. Recognized MIME/response-size limits produce an explicit incomplete record while healthy messages continue; other failures remain errors.
- **Keep downloaded content and expose recovery:** immutable cached bodies and attachments survive later size-limit placeholders for the same provider identity; mutable drafts still refresh. Account settings and CLI status show the current number of incomplete messages. Use the reader's content/attachment loading action, or CLI `fetch`, to request full MIME; only successful recovery clears the incomplete state. Failed downloads preserve the cache and reviewed account ownership.
- **Native reading and composer return:** loading/error readers offer Back and reject late responses. macOS adds Escape and restores native-list keyboard navigation; older reads and mark-read completions cannot replace newer selections. Windows returns from the composer to its original mailbox/page/query and a mounted keyboard-focus target in both right and Focus layouts, including interrupted reads. General preferences retain serialized field-diff saves, keep edits made during a save, and show Retry only after a failed save.
- **Windows arrival and paging recovery:** service revisions refresh the visible mail/search page and selected reader while retaining the page, owner and selection where possible, including the active Unread row. Expired signed mail/search cursors recover once at their existing numeric position. The response status and body survive the WinRT async boundary; ordinary HTTP errors keep the normal failure path and restore usable controls. Reader-only inline-image copies and stale detail/download guards remain intact.
- **Backup and local maintenance:** an existing backup destination reports a conflict and asks for a new folder, preserving the existing files. The optional manual checkout-cleanup tool previews eligible generated outputs before an explicit apply step; it is not scheduled or attached to releases and preserves current candidates, backups, evidence and private workspaces.

## Validation and limits

[PR #23's completed paired native run](https://github.com/Coke1120/Morrow-Mail/actions/runs/38048327870) passed on source `13d5822164a95a235fc8051036425726be21c0b1`: macOS passed **273 Rust tests**, **six Python fixtures**, SwiftUI packaging, reader isolation/network-zero, window/keyboard recovery and held-response/service integration. Windows passed **272 Rust tests**, WinUI packaging, fresh/owned/restarted UI walkthroughs, General retry, all four composer-return cases, mail/search cursor recovery, relocated PowerShell 5.1 deployment checks and the 1,000/10,000/50,000-message fictional-mail benchmark. Rust totals have zero failed or ignored tests. These are native-platform results; Linux checks alone are not UI acceptance.

The tagged release must separately pass the existing paired native gates before either download becomes public. The publisher requires same-run/same-attempt artifacts and signs the update manifest with the existing pinned key. No test waiver applies. See VERIFICATION.md for tagged checks and public-download verification.

Sync remains bounded polling, not a complete mailbox mirror or push synchronization. Persistent invalid provider dates or unresolved data require manual recovery; MIME, JSON, part and attachment limits remain. An old oversized Outlook full-body cursor requires explicit import restart, and a newest oversized body may be read again within the cap. IMAP cache identities still lack a server-origin namespace: reconnecting the same email to another server can collide with old rows when Message-ID is absent or reused. These cases are not resolved by content preservation. Failed provider writes and uncertain sends are never automatically replayed.

The Windows status-preserving response change is limited to mail/search paging. Custom `ApiError` details can still be lost across the existing async path used by other callers, including send/schedule/AI; that issue remains outside this repair and needs separate validation. This release does not claim those error-specific recovery paths are fixed.

The first PR run hit the existing **30-second macOS adversarial-reader timeout**. Subsequent runs of the same Mac sources passed within the unchanged limit; the latest took **24.624 seconds**. Those passes do not establish that the intermittent timeout is resolved. Windows owned/restart resource observation remained **incomplete** despite successful functional acceptance and the separate service benchmark, so complete UI resource measurements are not claimed. The previously observed intermittent Windows reader initialization timeout is likewise not declared resolved by passing fixtures.

**macOS is ad-hoc signed without Apple notarization; Windows is unsigned.** Full manual same-source Mac/Windows UX comparison, real-provider/model use, a separately provisioned clean Windows VM, complete keyboard/screen-reader/physical-pointer coverage and installed-updater restart/rollback remain unverified. Tests use isolated fictional mailboxes without real sends, calendar events or paid model calls. These fixes and checks do not establish production readiness.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs and checksums, or the explicit in-app update flow. Extract the whole Windows folder. Keep the separate mailbox workspace backed up and run one client against it. Older clients using the retired repository URL need a manual download.
