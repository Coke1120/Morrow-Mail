## Attachment ZIP preparation and saves

Save as ZIP prepares compression, checksums and archive bytes in a cancellable
worker. The transfer panel shows Creating ZIP and Waiting to save. One archive
is prepared at a time, with bounded waiting input and the existing 64 MiB/file
and 128 MiB/archive limits. Attachment writes are asynchronous and stay in order,
including concurrent saves to the same path. Cancelled or stale requests cannot
start a waiting write or open an external application after a write completes.
A write already started may finish after cancellation; files are not rolled back.

## Folder sidebar refresh

Unchanged folder trees reuse folder lookups and retain their existing nodes,
unread badges and selection. Refresh no longer copies the entire folder list
once per visible folder.

## Evidence and remaining limits

This release includes [PR #444](https://github.com/Coke1120/Morrow-Mail/pull/444).
The [Cloud review](../performance/2026-11-02-cloud-review.md) and
[raw samples](../performance/2026-11-02-cloud-review.json) retain the methodology,
prioritized remaining findings and regression recommendations.

In three Linux Node samples, 128 MiB of synthetic incompressible ZIP input delayed
the next host callback by 67–72 ms after the change, versus 3.35–3.55 seconds before.
Total archive preparation was slightly longer; large input cloning still pauses
the host. At 1,000 folders, retained refresh copied 2,000 folder elements instead
of 1,001,000. These are synthetic Cloud measurements, not macOS/Windows Electron
frame-time or live-provider throughput results. Exact local search, IMAP
scheduling and the other open findings in the review are not fixed by this release.

## Validation and distribution

The full offline check and focused regressions cover worker output/CRC, heartbeat,
bounded admission, cancellation/retry, stale identity, ordered writes and actual
renderer/help behavior. Release publication additionally requires both platform
builds and the final artifact verification in the existing workflow. Native
mailbox interactions and end-to-end updater transitions remain unverified.

Windows x64 remains unsigned. macOS ARM64 remains ad hoc signed, without Apple
Developer ID signing or notarization. The Ed25519 manifest authenticates the
release download; it does not grant Gatekeeper trust. Existing manual-install
and updater recovery limits remain; see [packaging](../PACKAGING.md).
