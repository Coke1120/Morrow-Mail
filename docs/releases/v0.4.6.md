# v0.4.6 — Local MCP agent access

## New in this release

Settings → Agent access / MCP provides a local stdio adapter for compatible agent
clients on the computer running Morrow Mail. Installed Windows and macOS builds
include `resources/morrow-mcp.cjs`; users must supply a separate Node.js 20+
runtime and keep Morrow open with Agent access enabled. Settings supplies the
actual adapter path, token-file path and installation ID. It does not install
Node, write client configuration or automatically enable access.

MCP projects the existing authenticated bridge catalog. Current mailbox and
operation grants, expiration, rotation, revocation, budgets, audit and durable
write receipts remain authoritative. Existing HTTP API, CLI, Grok/Hermes
integrations and proactive webhooks remain supported. Opening setup or copying
configuration does not grant capabilities or start a webhook.

The adapter supports the documented 2025-03-26, 2025-06-18 and 2025-11-25
handshakes, tools and cancellation. It does not advertise remote HTTP/SSE MCP,
resources, prompts, sampling, subscriptions or 2026 stateless support. Write
request UUIDs are separate from MCP correlation IDs; unknown outcomes require
review rather than automatic retry. Cancellation cannot recall a submitted
operation or data already delivered to a client.

## Setup and data access

Create or review an agent in Morrow, deliberately select its mailboxes and
operations, and keep the one-time secret in a private local file. Never put it in
chat, command arguments or shared client configuration. On macOS, restrict the
file to the owner (0600); on Windows, review its ACL yourself. A client running
as the same user can read that file and may forward results to its model provider
under its own policies. Configure only trusted clients.

Use the explicit executable and argument paths from Settings. GUI applications
may need an absolute Node path, and portable Windows extraction paths can change.
See [MCP setup and protocol limits](../MCP.md) for the full procedure.

## Included source and verification limits

This release includes PR #544 and preserves the previously released v0.4.5 app
changes, release notes and browser-test synchronization fix. Existing main and
dev ancestry is retained rather than dropping previous release metadata.

Automated tests exercise the actual bridge and standalone bundled adapter with
synthetic accounts, temporary stores and mocked providers, including grants,
rotation/revocation, budgets, bounded transport failures, inert proposals and
shared write receipts with the old CLI. Renderer/preload and Chromium fixtures
cover setup, compatibility controls, Features/CLI help and accessibility.

Actual agent-client interoperability, native Windows token-file ACLs and GUI
Node PATH, live providers/AI, and installed updater transitions remain unverified.
No real mailbox, credential store, grant or client configuration was changed as
part of release preparation. Package verification does not establish real-client
acceptance or authorize a new agent connection.

Windows remains unsigned. macOS is ad hoc signed, without Apple Developer ID or
notarization. The paired release workflow verifies provenance, asset hashes,
updater feeds, native Mac archive integrity and the Ed25519 update manifest
before publication. Download authentication does not grant OS execution trust;
existing manual bridge installation requirements remain. Prior releases and
assets are preserved.
