## Local Folders, MBOX import and Case Timeline

This release contains the reviewed #524–#527 batch. Existing mail, Calendar,
Graph, sending and update-trust settings retain their established boundaries.

### Local Folders and mailbox imports

- Local Folders appears below connected accounts and owns complete original MIME,
  headers, bodies and inline/file attachment bytes in `local-folders.sqlite`.
  Nested folders, offline reading/attachments, local read/star flags, copy/move,
  Trash/restore, separate search and original EML export survive account removal.
- Copy verifies the durable local archive before reporting success. Move then
  submits recoverable provider Trash; Gmail Trash affects the message across all
  labels, while IMAP requires MOVE and confirmed destination identity. Failed or
  uncertain remote moves retain the local copy. Uncertain writes are never
  replayed after restart or a destination change. Review freezes the selection;
  Stop after this message finishes the current operation before stopping later
  messages. There is no permanent local delete, provider restore/upload, local
  sending/reply/AI or bot/CLI enumeration.
- Entering a local folder selects its separate search default. An explicit All
  connected accounts or individual connected-account scope survives later
  searches and metadata refreshes. Local phrase search applies the same Unicode
  NFKC normalization and lowercasing to saved subject, sender, To, plain text and
  the query; accents remain significant. Existing archives need no data rewrite.
  The local reader Trash button follows all reviewed selections, including
  filter-hidden rows, while independent readers retain their own message target.
- Import MBOX explicitly reviews exported or stopped mailbox files, including
  extensionless Thunderbird mailboxes, destination, mboxrd/legacy mboxo format and
  exact-content duplicates. It creates verified private input snapshots. Complete
  mail/attachments, duplicate receipt, job offset and committed counters share
  one native SQLite transaction. Stop, crash and write errors retain acknowledged
  mail and failed input; restart never resumes automatically. Byte-identical
  snapshot backups are verified completely before adopting changed filesystem
  identity. Original files are unchanged, and provider/AI/sending paths are not
  entered. Read/star/reply/forward flags are mapped; Expunged is skipped, Partial
  fails explicitly and queued/draft metadata remains inert. Focus returns after
  completion rebuilds the sidebar.

Before relying on a local archive, back up `local-folders.sqlite` with Morrow
closed. Retain `mbox-imports` too if import recovery is needed. Removing private
snapshots is an explicit review and ends recovery for failed input; it does not
remove saved mail or original files. Local copies need free disk space. Remote
images retain the existing image policy and need a network connection.

Local server copies are limited to 64 MiB original MIME (Gmail's existing API
limit is 35 MiB). MBOX accepts up to 20 files / 100 GiB per job, 32 MiB original
messages, 256 KiB lines/header blocks and 256 attachments / 32 MiB decoded
attachment bytes. One parser worker has a 20-second deadline and 256 MiB V8
old-generation limit. Runs pause after 512 MiB committed input or 10 minutes;
inputs that cannot finish a snapshot pass within 10 minutes need smaller exports.
MSF/SBD/profile recursion, Maildir/EML, alternate envelopes and Content-Length
variants are unsupported. Exact byte identity does not semantically deduplicate
rewritten exports. Archive search, checksums and SQLite commits remain synchronous.

### Reviewed Case Timeline

- Keep This downloaded thread for lightweight chronology. Case / client mode
  searches the current account's downloaded mail across threads; accumulate
  explicit selections, assign Main / Background roles, then review sources,
  omissions and destination and confirm before Generate. A body-free account/
  message context permits a smaller case when initial thread capture exceeds its
  limits; that context cannot authorize generation or download.
- Case reports add source-cited current status, review follow-ups, unresolved gaps
  and mentioned events/deadlines, separately from mail dates. The full mail-date
  chronology and phase filters remain available. Cached source evidence is inert
  and fingerprint-checked; it does not download, load remote content or mark read.
  Changed/deleted sources can become unavailable. Suggestions do not automatically
  complete tasks, and unread/silence does not establish completion.
- **AI data permission needs renewed explicit review in Settings → AI.**
  Disclosure version 4 keeps background permission separate. Generate may send
  reviewed bodies/quoted history, subjects, sender names/addresses, mail timestamps/
  provenance, attachment names, optional focus and Main/Background choices to the
  saved AI destination. Independent To/Cc headers remain local evidence, but body
  text and focus can still contain addresses. Search, evidence, saved history and
  exports make no AI request. Source/account/consent checks, one-use authorization,
  sequential run budgets, cancellation and atomic persistence remain. Closing
  stops later calls; data already delivered cannot be recalled.
- Immutable public JSON 1.0.0 remains readable. Case uses separately bundled
  1.1.0. Reviewed HTML/PDF/Markdown/JSON exports preserve evidence and uncertainty.

Search is local token-prefix matching, not exhaustive mailbox discovery or Gmail
syntax/independent To/Cc search. Each query shows at most 100 matches and the body
index covers at most 200,000 characters per message. Selections have 1,000-message /
200-thread ceilings; smaller runs can hit request/usage/time budgets. The estimate
covers initial extraction while synthesis/retries share the total budget. Case
overview sections contain at most 12 points and need human review. Mentioned dates
must occur verbatim in cited bodies during generation; that does not prove their
meaning or a task's completion.

### Search and background work

Exact connected-account search uses complete adaptive candidates before ranking
and the result limit. Pending-body polls use a partial index without completed
history, preserving retry/horizon/keyset rules. Runtime IMAP ingestion uses a
32 ms cooperative work check, 24-message maximum and 256 KiB normalized text/HTML
cap. Every yield follows journal/hash/fsync and SQL commit; freshness checks and
final resume state remain intact. One message or disk call can exceed the targets.

The [paired tuning report](../performance/2026-11-05-issue-520-tuning.md) records
20 raw Linux runs, including counterbalanced 10k/100k comparisons and a repeat.
The primary 10k update pass was 13.7% slower than baseline; two 100k comparisons
were 8–9% faster, while an exploratory 100k pass was 9.4% slower. Primary 100k
maximum callback gaps were near 51 ms versus 261 ms. These are warm updates to
already-owned UIDs, not first downloads, first-sync throughput or native frame
timing. Broad ranking remains synchronous (about 403 ms in the selected 100k
sample), and small-account common search was slightly slower. Artificial bulk-seed
checkpoint setup used a verified native SQLite backup after the unchanged baseline
worker deadline was exceeded; giant initial-journal replay remains unvalidated.

### Validation and distribution

All four final feature heads passed Linux and Windows CI and full local checks.
The combined synthetic run passed 171 cases, including native SQLite/MIME/parser,
whole-content snapshot restore, corruption/FULL/fsync/rename/write failures,
process exits, source/account/consent races, Unicode archive search and actual
preload/picker/renderer routes. Chromium covered Local Folders/MBOX at 1440/390px
light/dark and Case Timeline at 1440/440px, including review, cancellation,
oversized-thread recovery, inert evidence, focus/Escape and rendered Features;
no real mail, credentials, live provider or AI was used.

Release preparation also diagnoses a Windows Gmail-fixture watchdog failure:
one job exceeded its 15-second fixture limit while another job on identical
source completed successfully. Adding 100 ms to each real synthetic-store fsync
reproduced the watchdog at 15.4 seconds; with only the fixture guard extended,
all original assertions completed in 17.9 seconds. Windows now has a bounded
60-second fixture guard and 90-second parent limit, phase/timing diagnostics,
and awaited store cleanup. Other platforms retain their original limits. No
application deadline, read pacing, authentication assertion or write-replay rule
is changed. Controlled Linux disk latency does not replace fresh Windows CI.

The versioned source must also pass exact-source CI and the normal paired Windows
x64/macOS ARM64 packaging and verified publication workflow. Version/source/run
provenance, updater feeds, artifact checksums and the Ed25519 manifest must agree.
Signing roots, credentials, release workflows and security settings are unchanged.

Windows remains unsigned. macOS is ad hoc signed with an authenticated update
manifest, without Developer ID signing or notarization. Native GUI, dialogs,
screen-reader/sleep-wake behavior, live providers/AI, real power loss and installed-
updater transitions remain unverified. Existing macOS manual-bridge and destination-
policy limits still apply.
