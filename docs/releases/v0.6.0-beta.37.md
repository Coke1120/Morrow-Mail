# Morrow Mail 0.6.0-beta.37

This beta widens the native reply composer with previous messages on the right, and fixes macOS mail-row click selection and the custom drag type used by sidebar label/folder drops.

## Changes

- Update existing fictional folder/label catalogs to include management metadata, preventing unintended background refresh of fake provider connections during native acceptance. Preserve the failed beta.35/.36 tags; neither has public downloads. Both platform gates run again for this tag.

- Write replies on the left while reading previous messages on the right. Both panes scroll independently and save/send actions remain visible. Reply All and reopened reply drafts use the same layout; Windows stacks the panes in narrow windows. New-message and forward composers also gain a little width.
- Read the downloaded original and up to 20 explicitly linked local reply ancestors under the draft's owning account. Plain text includes quoted history; missing/cyclic/long history is bounded and clearly marked. Loading errors offer Retry without changing the draft or sending anything. This does not reconstruct complete provider threads or download missing messages.
- Explicitly select the clicked draggable mail row and retain its native List identity on the complete row. The existing reader loads that message under its owning account; keyboard and context actions remain available.
- Export the private `com.morrowmail.mail-row` type as `public.data`. SwiftUI's native sidebar drop destination registers for data/item types; the previously undeclared custom type could not reach it. The opaque token remains confined to its source process.
- Drops open the existing Move screen with the account and destination captured for review. They do not perform an immediate provider write. Existing same-account, current-view/connection, available-folder, permission and single-use guards remain.

Gmail Move adds the destination label and removes Inbox while retaining other labels. Use Labels to keep Inbox. Bulk and cross-account moves remain unsupported. All-downloaded automatic indexing and the searchable managers from beta.34 remain available.

## Validation and limits

The existing paired workflow must pass both platforms' Node-free Rust checks, native builds/acceptance, Windows fresh/owned/restart walkthrough and fictional-mail benchmark before publication. The publisher retains same-run/same-attempt provenance and signed manifests. No waiver applies; tagged CI and public-download verification are recorded in VERIFICATION.md.

Native checks operate the production macOS mail list with AppKit click events and duplicate provider IDs across fictional accounts. Packaging checks require the exported drag type and its data conformance. Existing native drop tests cover owner/destination validation and reviewed routing. Automated events do not establish complete physical-pointer or live-provider acceptance. The earlier Parallels walkthrough covers beta.30, not this release.

Reply checks cover owner-isolated plain-text history, missing/cyclic/limited chains, authenticated read-only routing, new/reply/saved-reply/forward layouts and Windows independent scrolling/wide/narrow panes. A CUA macOS walkthrough in a separate fictional workspace opened Reply, edited and locally saved its body, then reopened the draft with its original history retained. No send was performed.

The intermittent Windows reader initialization timeout remains unresolved; its security gate is unchanged. Full live-account, clean-machine, accessibility and installed-updater restart/rollback acceptance remain outstanding. Tests use isolated fictional workspaces; no real mail, calendar event or paid-model request is submitted, and installed apps are not replaced.

macOS is ad-hoc signed without notarization; Windows is unsigned. This is an experimental prerelease with incomplete live-account acceptance.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs or the explicit in-app update flow. Older macOS versions predating beta.30 may still require one manual Quit during upgrade. Keep the separate mailbox workspace backed up and run one client against it.
