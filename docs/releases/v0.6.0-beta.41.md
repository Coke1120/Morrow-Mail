# Morrow Mail 0.6.0-beta.41

This beta adds an optional setting to load external HTTPS images automatically when reading mail on macOS and Windows.

## Changes

- Settings → General now includes **Automatically load external images (HTTPS)**. It defaults to off, including existing workspaces, and applies to all mailboxes. The adjacent disclosure explains that image servers may learn your IP address and that you opened an email.
- The preference automatically saves with other General settings, survives restart and stays intact when unrelated fields change. Disable it to restore default image blocking.
- Keep the individual message's **Hide external images** and reviewed **Load external images…** controls. An explicit Hide choice remains in effect while reading that message, including Windows reader refreshes. Opening another message follows the saved default. macOS reply-history readers also use the preference.
- Preserve sanitized HTML, isolated native readers, plain-text fallback, HTTPS-only images, disabled email scripts/forms/frames and reviewed links. CID images and attachments remain unsupported.

The downloaded label/server-folder performance improvements from beta.40 remain included. This preference does not download additional messages or grant provider/AI write permission.

## Validation and limits

All 203 locked Rust tests, formatting, strict all-target Clippy, local macOS candidate packaging and full production-service native acceptance passed before release preparation. New regressions cover default blocking, boolean validation, partial saves, account/combined views, encrypted-store restart and revocation. The production macOS reader fixture checks opt-in, the actual Hide control, new-message reset and preference revocation while retaining script blocking, bounded scrolling and network-zero checks. The Windows runtime fixture checks opt-in, HTTPS-only policy, the production Hide action and override retention with inert HTML before its existing hostile-content phases.

The existing paired workflow requires fresh tagged macOS and Windows builds, Node-free Rust formatting, strict all-target Clippy and locked tests, full macOS production-service acceptance, the Windows fresh/owned/restart UI walkthrough and fictional-mail benchmark before either download becomes public. The existing publisher verifies same-run/same-attempt platform artifacts and signs the update manifest against the unchanged pinned public key. No test waiver applies.

Checks use fictional mail/providers and isolated temporary workspaces. No real mail, calendar event or paid-model request is submitted. Real external HTTPS image fetching, full live-account/provider/model, physical-pointer/accessibility and clean-machine acceptance remain incomplete. The previously recorded intermittent Windows reader initialization timeout and installed-updater acceptance limits remain; passing fixtures do not establish real-account acceptance. macOS is ad-hoc signed without notarization; Windows is unsigned. This is an experimental prerelease.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs or the explicit in-app update flow. Keep the separate mailbox workspace backed up and run one client against it. Publication and public-download verification are recorded in VERIFICATION.md.
