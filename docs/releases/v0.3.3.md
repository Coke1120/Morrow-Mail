## Google sign-in and account recovery

Continue with Google remains the primary browser sign-in action. New connections
and Gmail OAuth reconnects keep Other email provider collapsed; manual-provider
reconnects retain their password form and custom servers. A Google password, when
Google requests one, belongs on Google's browser page rather than Morrow's manual
IMAP form.

An existing legacy Gmail OAuth connection offers Review Gmail API migration
instead of advice to retry the blocked provider button. The shortcut opens the
matching mailbox in Settings → Accounts → Permissions & calendar access. Migration
still requires review and Continue with Google confirmation. Removing or changing
the target while Settings is waiting cancels the shortcut instead of directing
the user to another mailbox's migration control. Removing an account is not needed
for migration and deletes local account data; reconnect and migration retain it.

Personal Google Desktop client import is optional under Advanced in Accounts.
The bundled client is used when present and no explicit override is selected.
Developer environment variables still precede an explicit import. Google controls
which users may approve each project; local readiness checks configuration only.

## Google grant preservation

Saved Google grants are bound to their issuing Desktop client. Different-client
and older unknown-client grants require Gmail and separate Calendar
reauthorization; credentials, account ids, cached mail and local drafts remain.
Changing the client does not move or upgrade a refresh token. Pending sign-in and
client import/clear cannot overlap, and obsolete results cannot replace the
current connection.

Enabling Out of Office retains a usable Calendar grant ahead of an identityless
old shared record. Gmail reconnect/reauthorization preserves a usable current-client
primary/shared Calendar fallback before replacing mail credentials. Scope strings
and client identities are not combined. Microsoft retains its existing separate
mail and Graph grant behavior.

Requested Google scopes are unchanged: Gmail API mail/settings and separate
optional Calendar access. Narrower requests do not revoke older broad grants.
This update performs no Console change and does not establish Production/Testing
status, API enablement, verification or allowed-user eligibility. See [OAuth
guidance](../OAUTH.md).

## Mail responsiveness

This version also includes the previously unreleased mail responsiveness changes
from PRs #324 and #328: smaller cached list/header reads, batched metadata and
unchanged-content indexing, body-only notifications, and bounded per-window body
reuse. Newer content and account/selection changes retire stale results. Persistent
mail, drafts and attachment behavior keep their existing protections.

The [offline measurements](../PERFORMANCE.md) and [body-update retention limits](../PERFORMANCE_PHASE_TWO.md)
describe synthetic checks. They do not measure the installed user's Mac or prove
the cause of a particular freeze. Optional development diagnostics remain local
and off by default.
