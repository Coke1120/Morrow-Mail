## Setup and mail navigation

New users get a five-step setup guide: connect a mailbox, connect its calendar,
choose the sender name recipients see, add a signature, and review optional AI.
Settings → General → Open setup guide resumes it. Skip for now, Finish later,
Escape and closing retain progress without inventing completed connections.
Existing configured users are not interrupted. Calendar and AI are optional;
saving AI configuration does not grant AI data permission.

Mail columns can be dragged into a saved order independently of sorting.
Columns → Move left/right, Alt+Left/Right on a header, and Reset column order
provide keyboard controls and a default layout. The order applies across accounts,
folders, search and Outbox; narrow lists scroll horizontally.

All Account Mail adds Starred and Unread rows with counts from the existing
downloaded-mail filters. The Inbox unread chip is removed; per-account unread
counts remain. Existing unread exclusions and the opened-message hold still apply.

## Bot permissions and confirmation

The No expiry review no longer leaves the following Allow sending button inert.
Each confirmation retains the submitted bot identity and exact mailbox selection.
Cancel, Escape and failed creation preserve the form for another review.

Bot access adds three separate default-off capabilities: archive mail, mark read
or unread, and move mail to Trash. A separate review names the selected actions
and mailboxes. Existing grants gain no permissions; sending remains separate.
No live grants are activated by this release.

`mail.archive`, `mail.mark_read` and `mail.trash` each target one explicit cached
server message and require a UUID. Pending is not provider confirmation. Repeat
the identical UUID, operation and params to observe the original receipt rather
than submitting another change. Unknown outcomes require inspection in Morrow.
Separate requests have independent outcomes. Trash never permanently deletes;
arbitrary folder moves, mailbox administration and bot calendar actions remain
unavailable.

The existing mailbox queue, identity checks and confirmed move Undo are reused.
Revocation is checked after asynchronous waits at the provider-write boundary,
but cannot recall a change already submitted. Queued bot changes do not regain
authority after restart or an older-version rollback. See
[Bot bridge](../BOT_BRIDGE.md#archive-readunread-and-trash) for the contract and
unsupported cases.

## Included changes and validation limits

Includes setup guide #457, mail layout/aggregate views #458, confirmation fix
#459, and scoped Bot actions #460. Local aggregate checks and Chromium fixtures
cover the combined behavior, permission reviews, persistence, cancellation,
idempotency, provider adapters, revocation, uncertain results and restart.
These checks use synthetic data and intercepted providers; they do not verify
live OAuth, real mailbox writes or an installed-app updater transition.

The standard GitHub-hosted Windows and macOS ARM64 release jobs verify the
packaged artifacts, paired provenance, hashes, update feeds and Ed25519 manifest
before publication. Windows remains unsigned. macOS remains ad hoc signed for
integrity, without Developer ID or notarization. Authentication of a download
does not establish macOS execution trust; normal platform protections and
installation prompts still apply. Existing manual bridge-install limitations
for old updater versions remain unchanged.
