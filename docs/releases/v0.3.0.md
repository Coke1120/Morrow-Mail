## Sender identities

Settings → Compose previews the recipient-visible sender name for each exact From address. Verified Gmail Send mail as names supply defaults; a Morrow-only override can replace that name. An empty override means address-only sending, and Reset returns to the default. Refresh preserves local overrides and manually configured aliases. Names are keyed by account and exact address, separately from the local mailbox label.

This changes mail sent from Morrow only. It does not update Gmail's settings, add OAuth scopes, grant send-as permission, enumerate Workspace domains or discover every plus address. Existing provider and alias restrictions still apply. Providers or recipients' contacts can affect the delivered display; synthetic MIME checks do not prove live delivery behavior.

The selected name and bare address are saved with drafts and scheduled content. Editing a default does not silently rename an already saved or queued composition; legacy queued mail stays address-only. Draft resume/recovery retains the correct alias for names containing quotes, angle brackets or Unicode. An unresolved legacy sender keeps the draft instead of falling back to primary. Bot mail.send uses the saved defaults without a new name parameter; idempotent receipt replay retains its original result.

Equivalent legacy sender metadata enrichment preserves queued cleanup proofs, including historical unquoted display text. Unchanged drafts clean up once after a confirmed queued send, while genuine later name, From or body edits remain protected. The formatter/parser and real MIME regression fixtures cover these flows. See the [sender identity decision](../adr/2026-10-26-sender-display-names.md).

## Attachment transfers

This release also includes the shared attachment transfers from #310/#311. They were not in the published v0.2.39 artifacts. The planned v0.2.40 was paused before tagging or publishing and is superseded by v0.3.0; no v0.2.40 installation is needed.

Preview, Open and Save share an in-flight read for the same current attachment and can reuse a complete result from a bounded process-memory cache. Save and Save as ZIP show the system picker before fetching; cancelling the picker starts no provider read. Request-specific progress shows phases and received bytes when available, with individual Cancel controls and no fabricated percentage or shell-wide busy lock. There is no measured live-provider speed claim.

Closing Preview or cancelling one consumer leaves another Save or Open using the shared read running. The last consumer cancels queued or active provider work. A system picker may need closing separately. Cancellation cannot recall a completed disk write or external application launch; a crash during the final write can still leave a partial file.

The cache retains complete files only, up to 32 MiB per file, 64 MiB total, 64 entries and five minutes, with LRU eviction. It clears when the process exits. Larger permitted downloads remain uncached; there is no persisted attachment cache or background attachment prefetch. Incoming reads allow 64 MiB per file and 128 MiB combined for a ZIP, subject to Gmail's existing response bound and other provider limits. Outgoing limits are unchanged. Two batches can be active, with 16 pending files and bounded eight-file ZIP batches; larger selections are not truncated to the pending-file bound.

Cache hits recheck account/message/attachment identity; reconnect, removal or migration invalidates retained bytes and pending reads. Failed, incomplete and cancelled reads are not cached, and each consumer gets its own copy. Exact selections, local draft files, IMAP UIDVALIDITY checks and legacy Gmail attachment identity recovery remain supported. Bot byte access, connection pooling, body scheduling, IMAP chunk tuning and PDF workers are unchanged. See the [attachment decision and limits](../adr/2026-10-26-attachment-transfers.md).
