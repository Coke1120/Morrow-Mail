# Morrow Mail 0.7.7

This release includes the native Today and Reply suggestions workspace from
PR32, plus the three delayed review fixes in PR35. Today and reply queues share
account tabs, compact saved decisions, inline original mail and editable replies.
All accounts is a read-only aggregate. Drafts, selections and scroll remain
account-owned, and sending still requires normal explicit review.

Empty Today/reply projections return before conversation-index loading.
Successful Skip clears only the dismissed suggestion's ephemeral workspace state,
preventing a prepared draft from returning as stale on the next poll. Refresh
moves edited workspace state when a newer source changes the target, so saving
the new target leaves no obsolete unsaved guard. Persisted mailbox drafts stay
in storage; failed transfers keep edits and same-target refresh retains identity.

The Windows fixture observer now holds provisional child handles before and
during delayed CIM delivery, in addition to the earlier sibling/row pin changes.
Final ownership, exact creation/identity, counter, exit and deadline checks remain.
The first native87/5 failure stays unknown and blocks complete observation.
Only the same retained handle can prove a signaled zero exit. The observer is
fixture tooling and is not packaged in the app.

## Distribution and coverage limits

macOS is ad-hoc signed without Developer ID notarization; Windows is unsigned.
Manual VoiceOver/Narrator, keyboard/focus/large-text, clean-machine, installed-app
and real-account/model/provider acceptance remain incomplete. Historical reader
timeouts and unknown pre-pin failures remain failures; successful new samples
do not certify error-free operation or repair past observations.

Review uses bounded downloaded mail: up to10,000 recent source/removal metadata
records,10 permitted context messages,200 reply candidates and20 saved summary
jobs as Today entry points. Missing, truncated, withheld and unconfirmed context
stays uncertain. This is not a complete provider mirror or model-quality claim.
Unsaved state lasts for the app session; Save draft provides restart persistence.
Opening mail or saving a draft never sends automatically or completes an event.

Only fictional temporary workspaces were used. No real mailbox DB, credential
change or separate Thunderbird-derived synchronization work enters this release.
