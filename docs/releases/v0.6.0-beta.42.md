# Morrow Mail 0.6.0-beta.42

This beta fixes native reader refreshes, Settings persistence, draft-save races and update preparation after the PR #16 review.

## Changes

- Windows preserves the current message's Hide external images choice through local Read, Starred and Pending changes. Updates to another row keep the reader interactive. If a marker update interrupts a newly selected message's detail read, the reader reloads that owned message after the update instead of leaving the previous message displayed.
- macOS General automatically saves the default send delay. Open Today uses the Settings save/discard review, and stale or cancelled workspace responses cannot replace newer account/settings state. Normal read refreshes retain paging and selection; fresh service-selected OAuth accounts remain supported.
- Draft saves hold the mailbox gate across idle validation and the queued database write, preventing acknowledged edits from racing send preparation. Account ownership, Bcc, reviewed footers and uncertain-send safeguards remain.
- Provider folder changes reconcile only affected account-owned indexed memberships. Creating a folder skips cached message-body reads while preserving import checkpoints and local overrides.
- Windows update preparation copies the app-local CRT companions required by the installer helper. Failed preparation removes only files created by that attempt and keeps the verified download available for retry. Fresh workspaces support updates during their first service session.

The default-off automatic HTTPS image preference from beta.41 remains available on both platforms, with its tracking disclosure, individual Hide/Load controls and existing reader isolation. The pinned update signing key is unchanged.

## Validation and limits

The existing paired workflow requires fresh tagged macOS and Windows builds, Node-free Rust formatting, strict all-target Clippy and locked tests, full macOS production-service acceptance, the Windows fresh/owned/restart UI walkthrough and fictional-mail benchmark before either download becomes public. The existing publisher verifies same-run/same-attempt platform artifacts and signs the update manifest against the pinned public key. No test waiver applies.

Regression checks cover send/save database queue order without provider delivery, empty folder changes without message-table reads, updater helper runtime copying and failure cleanup, macOS preference diff/in-flight edits and controlled workspace-response ordering, and Windows metadata/image consent plus immediate detail GET/marker PATCH interleavings. Tagged CI and public-download verification are recorded in VERIFICATION.md.

Checks use fictional mail/providers and isolated temporary workspaces. No real mail, calendar event or paid-model request is submitted. Full live-account/provider/model, real external HTTPS image fetching, physical-pointer/accessibility, clean-machine and complete installed-updater restart/rollback acceptance remain incomplete. Helper-file fixtures do not establish a complete installed preparation handshake; macOS response fixtures do not establish a physical GUI race/confirmation walkthrough. The previously recorded intermittent Windows reader initialization timeout remains unresolved. macOS is ad-hoc signed without notarization; Windows is unsigned. This is an experimental prerelease.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs or the explicit in-app update flow. Keep the separate mailbox workspace backed up and run one client against it.
