# Morrow Mail 0.6.0-beta.39

This beta reduces repeated Gmail downloads and keeps provider read cooldowns consistent across refresh, history import and folder reads. It also lets a replacement IMAP connection complete verification without inheriting the previous connection's wait.

## Changes

- Persist one quota deadline per saved account/connection across sync, history and folder/label reads. Honor longer Retry-After seconds or HTTP dates, retain the daily-quota minimum and indefinite transient history retries, and preserve waits across restart and import pause/resume. Reconnect/disconnect affects only its target.
- Fetch overlapping Gmail message IDs once per refresh. Reuse cached non-draft bodies with fresh minimal metadata; new messages, drafts and legacy rows without HTML metadata still use full reads. The isolated 150-message fixture uses 160 requests instead of 260.
- Skip only Gmail message-detail HTTP 404s so disappearing messages do not abandon a successful page or its checkpoint. Authentication, quota, other HTTP failures and malformed pages retain their recovery rules.
- Bind legacy cooldown records to the currently saved connection. A replacement IMAP verification read can run before saving clears the target account's old wait.

This remains bounded polling across five scopes, not incremental Gmail history synchronization or provider-deletion reconciliation. Provider writes gain no automatic retry. The reviewed workflows and native selection/model-setting improvements from beta.38 are retained; see that version's release notes for their scope.

## Validation and limits

The existing paired workflow requires fresh tagged macOS and Windows builds, Node-free Rust formatting, strict all-target Clippy and locked tests, full macOS production-service acceptance, the Windows fresh/owned/restart UI walkthrough and fictional-mail benchmark before either download becomes public. The existing publisher verifies same-run/same-attempt platform artifacts and signs the update manifest against the unchanged pinned public key. No test waiver applies.

Regression checks use fictional TLS providers and isolated temporary workspaces. They cover Retry-After timing, shared pacing, account isolation, restart/pause/resume, reconnect/disconnect, cached HTML refill, changed drafts, failure checkpoints and replacement connections. No real mail, calendar event or paid-model request is submitted. Installed apps and user mailboxes are not replaced.

Full live-account/provider/model acceptance, physical-pointer/accessibility and clean-machine acceptance remain incomplete. The previously recorded intermittent Windows reader initialization timeout and installed-updater acceptance limits remain; passing fixtures do not establish real-account acceptance. macOS is ad-hoc signed without notarization; Windows is unsigned. This is an experimental prerelease.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs or the explicit in-app update flow. Keep the separate mailbox workspace backed up and run one client against it. Publication and public-download verification are recorded in VERIFICATION.md.
