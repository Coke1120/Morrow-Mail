## New Inbox mail notifications

Windows and macOS can show native notifications for recent unread Inbox arrivals
while Morrow is running, awake and syncing. Alerts default on with sender and
content hidden. Settings → Mail & Sync can turn them off or choose sender-only
or message previews. Previews can appear on lock screens and in system history.
Bursts share a notification with hidden content; clicking opens the newest
available message in its account, with a safe Inbox fallback.

Initial sync, older-mail backfill, flag changes and old restart backlog stay
quiet. Alerts follow recent server arrival time, so old or missing sender dates
do not suppress a new delivery. Gmail's download horizon also uses provider
receipt time. Slow sync or older server timestamps can still stay silent; a
recent import that looks like a new server delivery can notify. Attempts are
reserved before show, so failed, suppressed or uncertain attempts do not replay. OS permissions and
Focus / Do Not Disturb control delivery. Quitting stops notifications; this
feature adds no startup service or closed-app delivery. Installed Windows builds
use the existing Start menu identity; portable delivery remains unverified.

## Saved connection renewal

Temporary token-service, network and secure-storage failures retain the saved
connection for retry instead of marking the mailbox as needing sign-in. Renewed
tokens must be saved before use; an omitted replacement refresh token preserves
the prior one. Obsolete renewal responses cannot overwrite a newer reconnect or
ask to reconnect its replacement. Account, provider-resource and Google client
guards remain in force, with no additional scopes or credential store.

Provider expiry, revocation and organization policy can still require sign-in.
The owner must review Google project publishing/verification and Microsoft app
registration or tenant policy when applicable. Existing generic stored auth
failures are not automatically cleared after upgrade; an affected account may
still need one deliberate reconnect. See [OAuth](../OAUTH.md).

## Native Hermes webhooks

Proactive notify offers an explicit Hermes HMAC V2 authentication mode using the
existing secure store for its route secret. Existing Bearer webhook settings
keep their mode. Retries retain the exact body and request ID while refreshing
the signature timestamp. Background delivery retains its separate opt-in and
private loopback/Tailscale endpoint restrictions.

HTTP acceptance acknowledges delivery to the endpoint; it does not verify agent
completion or the intended Hermes profile. Hermes route/profile setup remains
an operator action. Keep fallback cron until the intended profile produces a
verified result. See [Bot bridge](../BOT_BRIDGE.md#native-hermes-setup).

## Update discovery and shutdown

macOS checks fresh signed metadata even when it has a cached archive, reuses
unchanged verified bytes and fetches the signature from that version's fixed
release tag. A failed check or install can retain a revalidated download with an
explicit retry action. Existing signature, TLS, hash, quarantine and trust checks
remain in force.

Installed Windows starts NSIS only after explicit install preparation,
scheduled-mail quit confirmation and shutdown cleanup complete. Quitting alone
does not install an update. Background download failures are observed, and an
older install action is retired when a new transfer begins. Portable Windows
copies use the official manual-download page. If installer launch fails after
Windows has quit, reopen the existing installation to retry.

## Included changes and validation limits

Includes Hermes Push #464, OAuth renewal #465, updater lifecycle #466 and native
mail notifications #467. Automated fixtures exercise their combined host,
preload, Settings and renderer behavior using synthetic accounts, providers and
native-process/notification adapters. Chromium checks include keyboard controls,
persistence, narrow layout, safe click routing and accessibility.

Native installed-app notification permission prompts, sound/delivery/activation,
live OAuth and secure-store prompts, Windows NSIS/UAC, macOS authorization,
credential continuity and installed updater transitions remain unverified. macOS
retry has no partial-download resume or user cancellation, retains completed
backups and uses two non-atomic replacement renames. Existing manual bridge
installation requirements for older updater versions remain.

The standard GitHub-hosted Windows and macOS ARM64 release jobs gate publication
on packaged integrity, paired provenance, hashes, update feeds and the signed
macOS Ed25519 manifest. Windows remains unsigned with provider SHA-512 update
verification; it does not gain independent Ed25519 source authentication. macOS
remains ad hoc signed, without Apple Developer ID or notarization. Download
authentication does not establish platform execution trust or promise unattended
installation. No live credentials, Bot grants, proactive delivery, cron or OS
permission settings were activated during implementation and verification.
