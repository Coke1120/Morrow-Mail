# Morrow Mail 0.6.0-beta.28

This beta fixes Gmail Trash requests rejected with HTTP 411 and includes basic mail organization access in Gmail and Outlook sign-in.

## Changes

- **Gmail Trash:** explicitly send `Content-Length: 0` on the empty-body Trash request. Use the system `TRASH` label regardless of whether Gmail displays it as Trash or Bin. The reviewed move retains the message's local identity and account ownership.
- **Mail sign-in:** request Gmail `gmail.modify`, or Outlook `Mail.ReadWrite` and `Mail.Send`, by default. Remove the extra organization-permission checkbox from both native clients. Older read/send-only connections need browser reauthorization once; updating the app does not widen an issued token's permissions. Calendar and Out of Office permissions retain their separate consent flows.
- **Partial consent:** reject incomplete mail grants before importing mail or replacing a connection. Preserve existing connections, cached mail, drafts and other accounts.
- **Provider errors:** retain safe HTTP status and recognized authorization, permission and quota guidance. Keep provider descriptions private and preserve cached messages after failed or uncertain writes. Never retry a provider move automatically.

## Validation and limits

Local Rust formatting, strict all-target Clippy, the complete locked Rust test suite and macOS native acceptance passed. The zero-length Trash-header regression failed before the fix and passed afterward; its fixture also displays the system Trash label as Bin. With explicit user approval, one live Gmail test message was moved to Trash on its existing connection without reauthorization. This narrow check does not establish complete live-account acceptance.

The tagged release must pass Node-free Rust formatting, Clippy and tests on both platforms, native packaging and acceptance, and the Windows fictional-mail benchmark before the existing publisher makes either download public. The publisher checks same-run paired provenance and signs the update manifest with the existing pinned key. No test waiver applies.

Automated acceptance uses isolated fictional workspaces and provider/model fixtures. Full provider delta/deletion synchronization, attachments and CID images remain unsupported. Manual Windows visual/accessibility, clean-machine and complete live-account acceptance remain outstanding.

macOS is ad-hoc signed without Apple notarization; Windows is unsigned. This is an experimental prerelease.

## Install and update

Download the macOS arm64 or Windows x64 ZIP, or use the explicit in-app update flow with its signed manifest. Back up the separate mailbox workspace before updating and do not run two clients against the same workspace simultaneously.
