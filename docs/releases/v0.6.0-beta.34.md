# Morrow Mail 0.6.0-beta.34

This beta adds native mail-list drag/drop to sidebar labels and server folders, and makes reviewed background indexing of downloaded mail the primary Search setup action.

## Changes

- **Drag to organize:** drag one imported message onto a label/server folder belonging to its account. Available provider-backed Inbox, Archive, Spam and Trash also accept drops. The entire macOS row is a drag hit area. The existing Move screen opens with the destination selected; review the account and effect before applying. Gmail Move adds the chosen label and removes Inbox while retaining other labels. Use the existing Labels action when you want to retain Inbox.
- **Safe drop handling:** opaque native drag tokens bind the original owner, connection and view identity, including duplicate IDs in All accounts. External payloads, cross-account transfers, changed views/connections and missing/hidden/unselectable destinations are rejected. Provider permissions and fresh destination validation remain enforced on the server. Keyboard and context-menu actions remain available. Bulk moves are unsupported.
- **Index all downloaded mail:** new Search configurations default to All downloaded mail. Review eligible accounts, folders, permitted content, embedding model/endpoint and estimated daily cost once, then let background indexing continue while the app runs. Existing explicit or legacy recent-history scopes are preserved until reviewed expansion.
- **Clear progress and pause:** show indexed/eligible counts, pending work, size exclusions and daily-limit continuation. Pause preserves unsaved form edits and completed chunk checkpoints. Messages can finish across daily resets without resending completed chunks. New/changed eligible mail is picked up automatically after approval.
- **Advanced controls:** daily/batch limits and manual maintenance are collapsed. Increasing the daily allowance retains waiting checkpoints; lowering it safely requeues automatic work within the new allowance and requires the applicable review. Existing permission, scope, model and connection invalidation guards remain. Uncertain model/provider requests never replay automatically.

Keyword search remains available without an AI index. Semantic retrieval retains its 12,000-chunk/four-million-vector-scalar bound; per-message/chunk limits can leave oversized mail keyword-only. Remote model costs depend on the configured provider, and the indexing daily allowance does not cap query costs. Catalog caching does not mirror every message, deletion or attachment.

## Validation and limits

The existing paired workflow must pass both platforms' Node-free Rust checks, native builds/acceptance, Windows fresh/owned/restart walkthrough and fictional-mail benchmarks before publication. The existing publisher validates same-run/same-attempt provenance, checksums and the manifest signature against the unchanged pinned public key. No test waiver applies. Tagged CI and public-download verification are recorded in VERIFICATION.md.

Local validation includes all 186 locked Rust tests, strict all-target Clippy, macOS packaging/signature/plist and complete production-service acceptance. Native drop checks cover duplicate IDs across accounts, external/random tokens, changed views/connections, unavailable folders, vanished rows, active-work guards and review routing. Windows also tests its native DataPackage token and drag/drop control registration. These automated checks do not establish a successful physical pointer drag or live-provider move. A macOS CUA fixture walkthrough read/filter checks passed. Isolated gesture diagnostics found that the row needed an explicit full-row hit area; the corrected fixture received drag-start and passed owner/source guards. The desktop tool also left a minimal standard-text drag fixture without a completed drop, so a successful end-to-end physical pointer drop remains unverified. Beta.33 was withdrawn before publication; its tag remains and no assets were published. The earlier Parallels walkthrough covers beta.30, not this release.

The previously recorded intermittent Windows reader initialization timeout remains unresolved; its security gate is unchanged. Full live-account, clean-machine, accessibility and installed-updater restart/rollback acceptance remain outstanding. Tests use fictional temporary workspaces and loopback provider/model fixtures; no real mail, calendar event or paid model request was submitted. Installed apps and the owner's workspace were not replaced.

macOS is ad-hoc signed without notarization; Windows is unsigned. Full live-account acceptance remains outstanding. This is an experimental prerelease.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs or the explicit in-app update flow. Older macOS versions predating the beta.30 update-quit fix may still require one manual Quit during this upgrade. Keep the separate mailbox workspace backed up and run only one client against it.
