## Draft attachments and reviewed sends

Provider drafts prepare every attachment before editing for Save, Send or Schedule. Preparation uses the existing shared cache, progress and cancellation, and validates the complete body, draft revision and 25 MiB outgoing file limit. Local file copies are committed together only after all reads succeed. Partial failures or cancellation keep the original draft available for retry. Inline content IDs, sender names/addresses and queued cleanup proofs remain intact.

Save, Send and Schedule wait for active AI writing to finish or be cancelled. A preview freezes the complete payload, composition session and content snapshot. Confirmation submits that captured content through send-delay or scheduling; later changes require a new preview instead of silently substituting unreviewed AI output.

## Gmail charsets and MIME

Gmail decoding keeps both iconv mail aliases and TextDecoder/ICU coverage, including cp932, UTF-7 and ISO-2022-JP. An unknown label rejected by both decoders uses an incomplete UTF-8 fallback with a visible reader warning that persists after restart. Malformed MIME is isolated from other messages and history progress. Network, identity and storage errors keep their original error paths rather than being treated as MIME failures.

## Reply-To and calendar edits

Reply and Reply All prefer structured Reply-To, then From, while filtering the account's own addresses and deduplicating recipients. Sender selection remains separate. Reading complete cached mail stays immediate; reply preparation retrieves unknown remote headers and blocks the reply when those required headers cannot be obtained.

Locally generated Sent copies preserve known empty Reply-To without an unnecessary provider read. Narrow recognition also handles historical v0.3.0 local Sent records, including bot messages sent through different-domain aliases. It does not guess that any zero-UID or matching-From remote message is local: unknown remote metadata still needs retrieval, and authoritative provider adoption remains decisive.

Calendar input-type changes retain the selected dates. An unchanged timed → all-day → timed round trip restores the exact original hours. Editing the all-day range keeps those selected dates and uses explicit 09:00/10:00 timed defaults. A new event editor does not inherit another event's snapshot.
