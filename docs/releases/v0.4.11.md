# Reviewed unsubscribe and PDF preview recovery

This release promotes merged PRs #565 and #566.

## Changes

- **Unsubscribe** appears for supported mailing-list headers in connected Gmail
  API and IMAP readers, including Outlook and Yahoo. A native confirmation names
  the mailbox, sender and destination before any action. Older complete cached
  messages need explicit Reload to obtain missing headers; opening and syncing
  mail do not unsubscribe, and Local Folders and drafts are excluded.
- **RFC 8058 one-click unsubscribe** reads the fresh original and verifies a
  cryptographic DKIM signature covering From and both unique list headers and the
  complete body. It sends a credential-free HTTPS POST only to the verified URL,
  with public-DNS pinning, TLS verification, and no redirects or automatic retries.
  IMAP originals stream up to 64 MiB; Gmail raw JSON/base64 remains bounded-buffered
  with a 35 MiB decoded MIME cap. Header, line, read and DNS budgets fail closed.
  System DNS supplies DKIM keys; this does not establish DNSSEC, DMARC alignment
  or sender reputation. A successful response means the request was accepted,
  not independent proof that the sender removed the subscription.
- Verification failures before any POST offer a separately confirmed manual
  website or email alternative. The browser owns its subsequent DNS, redirects
  and signed-in session. Email alternatives open an editable compose and require
  Send. No fallback or replay follows an uncertain or rejected POST outcome.
- **PDF previews** expose extracted plain text to assistive technology in PDF
  extraction order, progressively admit pages in longer files, stop remaining
  work on close, and retry failed pages. Canvas dimensions and displayed page
  height are limited to 4096 pixels. Scanned pages have no OCR; in-preview text
  selection, links and a print toolbar remain unavailable.

## Validation and distribution limits

The feature PRs passed Linux and Windows CI on their final heads. Their exact
combined dev tree passed the full aggregate check. Synthetic fixtures cover
DKIM tampering and signed messages above 10 MiB, complete-source and provider
bounds, cancellation, unsafe destinations, no-replay behavior, renderer races,
PDF text/progressive loading, Retry, canvas caps and Windows CRLF test inputs.
Release candidate CI and paired native packaging remain release gates.

Real mailbox providers, live sender unsubscribe endpoints, native dialogs,
screen-reader interaction and installed-app updater transitions are not
certified by these synthetic checks. PDF text is not OCR, and individual page
work still uses the renderer's main thread.

Windows remains unsigned. macOS remains ad hoc signed, without Developer ID or
notarization. The paired workflow verifies provenance, downloaded asset hashes,
updater feeds, native Mac archive integrity and the Ed25519 manifest before
publication. These checks do not establish Gatekeeper trust or authorize
installation; destination-Mac checks and normal user prompts still apply.
Existing release assets, signing roots and user data remain unchanged.
