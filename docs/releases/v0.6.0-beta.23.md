# Morrow Mail 0.6.0-beta.23

A simpler daily workflow for summaries, reply review and continuing AI assistance.

## Changes

- Restore the shared Windows history-coverage formatter required by AI Studio. The beta.22 attempt stopped before publication; beta.23 reruns both platform gates.
- **Needs a reply:** Reply Suggestions now shows only mail assessed as needing a reply. Enable automatic checks once with the selected account, model and daily budget; open a row to review/edit the suggested reply in the native composer, then explicitly send, or choose Ignore. Unnecessary replies stay hidden and Ignore survives restart. Reading or starring mail does not repeat an unchanged assessment. Mail is never sent automatically.
- **Continuous semantic indexing:** after explicit scope/model/budget approval, Smart Search continues bounded batches and handles new or changed downloaded mail while Morrow is open. The daily estimated-token allowance survives restart and resets at midnight UTC. Stopping retains valid vectors; changed scope or clearing the index requires review. Failed or uncertain interrupted requests do not automatically replay.
- **Learning and Email Brain:** optional weekly analysis starts with the first eligible sample after enabling. Brain proposes source-linked memories and retains automatic proposals across restarts; select the items to save. Pending review pauses further analysis. A valid approved style is retained as the baseline for incremental learning. Applying memories or a style remains explicit.
- **Better AI context:** interactive assistance, scheduled summaries and reply suggestions share source-validated, account-owned Brain context. Chinese retrieval uses the existing normalization/token logic. Briefings prioritize Pending, starred and unread mail. Explicit instructions and manual writing voice take precedence over approved learned style and defaults.
- **Today and simpler controls:** Today combines all connected mailboxes' summaries and displays saved timing. AI Studio has Assistant, Summaries and Email Brain as its main pages. Settings collapses manual maintenance and shows save controls when needed.

## Validation and limits

This tag requires both existing macOS and Windows CI jobs to pass Rust formatting, strict Clippy, the locked tests, native packaging and platform acceptance. No test waiver applies. Both packages must pass the existing publisher's artifact-provenance, checksum and pinned-key signature gates before either becomes public.

Local preparation passed 168 Rust tests, strict Clippy, formatting, macOS packaging and native acceptance with isolated fictional mail. Tests cover automatic budgets/restart, hidden no-reply results, persistent Ignore, source/permission revocation and reviewed memory ownership. Native layout snapshots use fictional in-memory data. These checks do not establish live-account acceptance, AI relevance or complete unanswered-thread detection.

Automatic features are off until explicitly enabled and run only while Morrow is open. Daily indexing/reply budgets accept 4,000–2,000,000 estimated tokens (default 100,000); memory analyses accept 4,000–64,000 (default 16,000). Estimates are conservative allowances, not provider billing guarantees. Reply checks cover at most the newest 200 downloaded Inbox messages with bounded permitted correspondence. Today shows the latest 20 reports per mailbox; historical imports do not trigger new-mail summaries. There is no model-weight training or automatic memory/style application.

macOS is ad-hoc signed without Apple notarization; Windows is unsigned. Clean-machine, complete accessibility/IME/DPI testing and real-provider acceptance remain incomplete. This is an experimental prerelease. Attachments and CID images remain unsupported.

## Install and update

Download the macOS arm64 or Windows x64 ZIP, or use the explicit in-app update flow with its signed manifest. The updater retains the previous app and preserves the separate mailbox workspace. Back up the workspace before updating; do not run two clients against the same workspace simultaneously.

Windows requires a supported Windows 10/11 x64 environment. HTML mail uses WebView2 when available and otherwise falls back to plain text. Both native platforms use the Rust service without a bundled Node runtime.
