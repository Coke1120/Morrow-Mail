## Mailbox, compose and Timeline refinements

This release proposal covers the reviewed mailbox, compose and Timeline changes
and the separately verified Copy and Gmail-source Move phases:

- **Mailbox display:** address-first headings, consistent folder rows, counts
  and selection styling across Gmail, Outlook, Yahoo, generic IMAP and Local
  Folders. Actual parent folders retain their expansion hierarchy. Gmail system
  categories use readable names without changing their underlying identities.
- **Folders & Labels:** prominent mailbox switching and a shared browser using
  the existing mail connection. Reviewed creation is available from the page
  and account/folder context menus. Server delimiters, read-only flags and
  non-selectable container parents remain meaningful.
- **AI permission:** updates retain unchanged disclosed uses. Thread Timeline
  and cross-thread Case have separate approvals; genuinely new or expanded
  uses still require incremental consent. Saved status is clearer, and choosing
  the already active ChatGPT account keeps its existing permission.
- **Write with AI:** Suggested replies appear inside the popup. The prompt is
  a vertically resizable textarea; Enter inserts a newline and Ctrl/Command+Enter
  generates, with composition-input protection. Choosing a suggestion preserves
  the signature and does not generate or send a message.
- **Spelling corrections:** native compose context menus offer available
  dictionary suggestions and normal editing actions. Corrections follow the
  editor's draft/Undo path, without AI or automatic dictionary additions.
- **Timeline validation:** fixed extraction, consolidation and Case failure
  categories distinguish JSON formatting, fields/text limits, source references
  and incomplete output. A single whole-response JSON fence is accepted while
  schema and evidence checks remain strict. One bounded corrective retry avoids
  echoing raw provider output; failed runs preserve earlier saved timelines.
- **Mail-row context menus:** Move to folder, Labels, read/unread, star/unstar,
  safe Move to trash and supported existing actions target the reviewed row or
  selection. Keyboard menus retain focus. The combined Move / Copy to other
  mailbox dialog preserves Local Folders as a destination.
- **Cross-mailbox Copy:** complete original MIME and attachments move through
  the reviewed Gmail import or capability-checked IMAP path. Complete readback
  must verify before success; the source stays in place. Account, credential,
  Google-client, folder and review ownership remain bound across waits.
- **Gmail-source Move:** verified receiving copies are retained while a separate
  review and explicit confirmation can move Gmail API originals to Gmail Trash.
  Other connected source transports remain Copy-only for connected destinations;
  existing Local Folders transfers are unchanged.
- **Time column:** Date and Time display the same message timestamp in the
  device timezone. Both sort by the complete timestamp. Header context menus
  and Columns control visibility; older layouts gain Time after Date while
  keeping their other order and saved preferences.

### Recovery and provider limits

Gmail API user-label deletion requires typing `confirm` exactly and has a
30-second cancellation window before any provider delete. Email and child labels
remain. Undo cancels the pending action; it cannot recreate original memberships
after the label has been removed. Restart pauses pending deletion, obsolete
pre-write connection intents are cancelled safely, and uncertain writes are never
replayed automatically. Damaged recovery storage disables folder writes while
browsing remains available.

Deleting folders on Outlook, Yahoo, generic IMAP and legacy Gmail IMAP remains
disabled until genuine recovery can be verified. No irreversible fallback is
provided. Local Folders retains its existing empty-folder delete without an Undo
claim. Existing provider-specific tools and permissions remain separate.

Cross-mailbox Copy requires a supported Gmail API or IMAP destination. IMAP
requires a writable selectable folder, observed persistent UIDVALIDITY, UIDPLUS
or IMAP4rev2, APPENDUID and complete readback. Gmail uses the original valid Date
header for sorting, so its receiving time can differ; a local archive may lack
the original server receiving time. Read/unread and star state must match, while
other provider labels, categories and flags are not portable. The review shows
message and byte limits, including 50 messages and 256 MiB per review.

Durable receipts precede upload. A lost acknowledgement or verification failure
may leave a copy at the receiving mailbox, but retains the source and never
reuploads automatically. Known locators can be checked through a fresh explicit
review. Unknown receipts are not pruned; full, corrupt or concurrently altered
recovery storage blocks further writes. No mail is sent to recipients by import.
Actual Local Folders-to-IMAP Copy and verified receipt reuse are covered.

Only Gmail API sources support the new remote Move phase. Move first completes
verified Copy, then requires a separate source-Trash review and confirmation.
The host rereads the complete receiving copy and exact source under both mailbox
lanes. A Copy review never authorizes source removal. Durable source-wide intent
precedes one nonpermanent Gmail Trash request; an unknown outcome blocks replay
through another receiving destination or label alias. Restart expires unused
reviews without uploading, re-Trashing or restoring anything automatically.

Confirmed Gmail evidence updates Inbox, label and Trash cache views without
changing unrelated messages or existing reply/forward/date/flag evidence. If
local refresh fails, the durable confirmed Trash receipt is retained and the UI
reports a refresh warning; it does not repeat the provider operation. Stop or
window closure prevents remaining work but cannot recall an already started
request. All receiving copies are retained, including after partial or uncertain
source removal. Cross-provider atomicity and in-app Move Undo are not promised;
manual Gmail Trash recovery remains subject to provider retention and other
clients' actions.

Legacy Gmail IMAP, Outlook, Yahoo, generic IMAP and Local Folders sources remain
unavailable for connected-destination Move. There is no generic delete, expunge
or unsafe fallback. Existing Local Folders transfers retain their own reviewed
Copy and recoverable source-Trash behavior. Listing a connected destination does
not promise that its server capabilities or source recovery support Move.

The reported Timeline incident's actual cause has not been established. Synthetic
long-thread, malformed, truncated and invalid-reference cases exercise the new
diagnostics; they do not diagnose the original mailbox or AI provider. Call,
usage and time limits still apply. Explicit retry sends the reviewed mail again;
data already delivered to a configured AI provider cannot be recalled. Background
AI permission remains a separate opt-in.

Spelling suggestions depend on the operating system and available dictionaries;
they are not Word-style grammar checking. Native Windows/macOS dictionary,
assistive-technology and power-loss behavior, live mail/AI providers, and installed
updater transitions require separate verification.

### Validation and distribution

Each original feature head and the final Copy head passed Linux and Windows CI.
The enabled Gmail-source Move candidate passed full Node20 and Node24 checks,
production-default source eligibility tests, independent ownership/journal
rechecks and Chromium flows. Final exact-head CI and dev integration remain
required before this proposal is handed to the owner.
Corrected original-stack and Copy full local checks, independent ownership and
recovery reviews, actual engine/preload fixtures and synthetic Chromium flows
passed. No real mail or live providers were used.

Local synthetic checks cover changelog/version consistency, release preflight,
paired Windows/macOS staging and publication failure behavior, signed-manifest
verification, and project/packaging notice consistency. Synthetic keys and mock
publication do not prove that production signing credentials or native packages
are ready. Finalized scope and the exact main source must pass CI before the
normal paired release workflow builds and verifies the distributable artifacts.

Windows remains unsigned. macOS is ad hoc signed, without Apple Developer ID
signing or notarization. The existing signed update manifest authenticates the
download without granting macOS execution permission. Stable asset names,
checksums, provenance checks, update trust and packaging notices remain unchanged.
