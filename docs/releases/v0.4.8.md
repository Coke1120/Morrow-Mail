# Sidebar indent, Gmail text, and Timeline size

Folders under each mailbox heading sit 14 pixels in from the account name,
including Inbox, Sent and Drafts for Gmail, Outlook, Yahoo, custom IMAP and
Local Folders. Nested folders keep their additional indent. Unread badges stay
aligned on the right. All Account Mail’s separate section is unchanged.

Gmail resolves a message when its body is valid non-ASCII UTF-8 but the
declared character set disagrees, using one original-message read instead of
guessing UTF-8. Genuine GBK, Big5, Japanese and Windows-1252 text stays as
before, including legacy bytes that are also valid UTF-8. Shared IMAP decoding
is unchanged. Received Gmail messages without a decoding warning offer Reload
message, which can replace an older cached body. A failed reload keeps the
complete cached copy. Pending drafts are not replaced. Morrow does not rewrite
the whole cache.

Timeline counts included message text in UTF-8 bytes, separately from serialized
requests and provider-reported tokens. Included body text and serialized run
input are each bounded to 512,000 bytes. An exact repeated quotation is shared
only when that complete text is already in the same AI request. Edited,
uncertain and cross-request quotations stay intact. Attachment file contents
stay excluded. The source review shows the planned size, and those counts clear
when the selection, focus or account changes.

## Validation and limits

This release includes PRs #550, #551 and #552.

#550 reported Timeline byte-budget and exact-quote coverage with synthetic
tests, Chromium layout checks and Linux/Windows CI. #551 reported the folder
indent with sidebar regressions, synthetic Chromium screenshots and
Linux/Windows CI. #552 reported Gmail charset recovery with synthetic MIME,
cache and renderer regressions. Those checks used synthetic mail. They did not
use a live mailbox or a live AI provider.

The version bump updates package metadata, What’s New and these notes, and
aligns the existing version assertions. The candidate gate is `npm run check`
plus the repository Linux and Windows CI. This note does not add a new native
installed-app pass.

Windows remains unsigned. macOS remains ad hoc signed, without Developer ID or
notarization. The paired release workflow validates source provenance, asset
hashes, updater feeds, native Mac archive integrity and the Ed25519 manifest
before publication. This does not establish Gatekeeper trust or authorize
installation. Existing releases and signing roots are unchanged.
