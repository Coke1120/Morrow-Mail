## Selected-mail Timeline

The reader adds Message and Timeline tabs. In Separate window layout, Timeline
appears below the list while open; Message restores the full list without changing
the saved layout or ordinary mail-selection behavior. Review selected messages, complete
already-downloaded threads or downloaded keyword-search results, then choose
Generate timeline explicitly. Preparation shows accounts, source coverage,
missing content, the saved AI destination and run limits before generation.
Opening a tab or a saved result does not start AI. Optional missing-body downloads
are explicit and do not mark mail read. Timeline generation does not send mail,
change labels, create Agent tasks or run in the background.

AI data permission advances to disclosure version 2 for this additional purpose.
Existing users must review the saved destination and explicitly grant permission
again in Settings → AI before AI actions resume. Background permission remains a
separate choice. Timeline extraction uses reviewed source text, subjects and
attachment names without Brain or Agent history. Attachment file contents are not
extracted. Generated summaries, requests and uncertainty require human review.

Coverage is limited to downloaded mail: up to 1,000 messages and 200 threads,
subject to bounded input, output, request and total-run limits. Larger selections
are refused rather than silently truncated. Incomplete or unsupported records
require explicit partial-coverage acceptance. Dates use mail timestamp provenance;
unknown dates remain unknown, and cached timestamps do not establish when an
underlying business event occurred.

Saved timelines stay in the local mail store. Reviewed exports support Markdown,
isolated PDF and public JSON schema 1.0.0. Exports may contain personal information;
each export requires a fresh review. Removing an account deletes every related
local timeline, including mixed-account results. Exported files, backups and
historical journal bytes remain. URL/webhook delivery, bot/CLI operations and
scheduled generation are unavailable.

## Outlook connection recovery

Sync validates the saved mail token immediately before connecting after a mailbox
queue wait or a resumed folder pass. An explicitly rejected Outlook OAuth login
can trigger one silent token refresh and one new login attempt before any mailbox
operation. Renewed credentials must be saved before use. Mailbox callbacks and
writes are never replayed. Real revocation, interaction requirements and tenant
policy still require reconnecting; previously recorded authentication errors may
need one deliberate reconnect after upgrading. This fixes a reproduced client
failure but does not establish the cause of a particular account's daily prompts.

## Integration and validation limits

Timeline preserves Right, Bottom and Separate window reading layouts, keyboard
isolation, mail reply/forward metadata, new-mail notifications and Summary's
incomplete-response handling. Chromium synthetic checks cover light/dark themes,
wide/narrow windows and all three layouts. Schema, source selection, extraction,
consent, persistence, exports and rendered tabs use synthetic accounts and AI.

Publication uses the existing Windows-then-macOS pipeline, full checks, native
macOS strict bundle and extracted-ZIP integrity, paired provenance, feed hashes
and the Ed25519 macOS update manifest. Windows remains unsigned; macOS remains ad
hoc signed without Developer ID or notarization. Existing one-time manual bridge
installation requirements still apply. Live Outlook/tenant policy, real AI output,
native PDF dialogs, native notifications and installed updater transitions remain
unverified. No signing roots, secrets or release gates are changed.
