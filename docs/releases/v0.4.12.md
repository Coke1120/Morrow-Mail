# Resizable mail columns and safe HTML reply quotes

This release includes PRs #568 and #569.

## Changes

- **Resizable mail-list columns.** Drag the right-edge handle of Date, Time,
  Recipient, Sender or Subject. On a focused handle, Left / Right changes width
  by 10 pixels, Shift changes it by 50, and Home / End selects the minimum or
  maximum. Escape cancels an active drag; double-click or Delete / Backspace
  restores that column's responsive default. Widths are saved by column ID,
  independently of order, visibility, sorting and reading-pane size. Unchanged
  columns remain responsive; narrow windows retain horizontal scrolling.
- **Safe HTML in editable reply quotes.** Fresh Reply and Reply All retain
  supported formatting from the original and available earlier cached messages:
  headings, emphasis, lists, tables, safe links, colors and embedded raster images.
  Each message is sanitized separately so its styles cannot change another
  quoted message, attribution, signature or the authored reply. Unsupported or
  empty HTML falls back to available escaped body text. This is not pixel-perfect
  reproduction of arbitrary email HTML.
- Remote images and CSS resources remain blocked in editable and outgoing
  quotes, regardless of image permission in the separate reference pane. Active
  markup and unresolved inline-image references are not copied. Excessive CSS
  expansion falls back to available text with a notice. Additional history keeps
  its 100-message / two-million-character budget, including sanitized output.
- The editor remains the sole outgoing body: editing or deleting a quote does
  not restore the original at Save, Preview Send, Send or Schedule. Late history
  reads, signature changes and AI writing retain quote edits. Earlier cached
  history is not added to authored AI input. Saved/recovered drafts retain their
  saved content, and Forward behavior is unchanged. No new provider permission,
  automatic provider read, remote-content grant or bot action is added.

## Validation and distribution limits

Synthetic renderer and host fixtures cover width persistence and normalization,
keyboard and pointer resizing, cancellation and stale settings reads, unchanged
sorting and selection, sanitized reply HTML, style isolation, remote blocking,
quote edits/deletion, late-history races, AI/signature boundaries, saved-draft
recovery and frozen send/schedule previews. The full aggregate check, release
candidate CI and paired native packaging remain release gates.

The cloud environment blocked Chromium's local process socket. A separate Mac
Chrome run used a verified copy of the exact feature tree and synthetic data:
reply HTML editing, safe tables/colors/images, preview/cancellation, quote deletion,
close/reopen and no external requests passed. Stable screenshots at 1280, 800 and
720 pixels were inspected in light and dark themes. The unchanged corrected
column fixture passed actual pointer/keyboard resizing, header/row alignment,
cancellation and persistent widths after hide/reorder/reload. The fixture now
waits for startup layout motion to settle before measuring its drag baseline;
product behavior and assertion tolerances were not changed to obtain a pass.

These are browser fixtures, not packaged Electron, assistive-technology, real
provider or installed-app updater acceptance. Preserved author-specified colors
can have low contrast in dark mode; arbitrary email HTML is not recolored or
promised pixel-perfect rendering.

Windows remains unsigned. macOS remains ad hoc signed, without Developer ID or
notarization. The paired workflow verifies provenance, downloaded asset hashes,
updater feeds, native Mac archive integrity and the Ed25519 manifest before
publication. These checks do not establish Gatekeeper trust or authorize
installation; destination-Mac checks and normal user prompts still apply.
Existing release assets, signing roots and user data remain unchanged.
