# Morrow Mail 0.6.0-beta.20

This prerelease improves recovery from Gmail request limits in the native SwiftUI and WinUI clients, using the shared Rust service.

- Recognized Gmail quota 403 responses and HTTP 429 are treated as request limits, avoiding unnecessary reconnect prompts.
- Recent-mail Sync saves a separate retry time for each account and retries while the app is open, with delays of 1, 2, 5, 15 and then 60 minutes. Hourly retries continue until recovery; Gmail daily quota responses wait 24 hours. Repeated Sync presses respect the cooldown. Success, reconnect and disconnect clear only that account's retry.
- Read-only history import retains its checkpoint and retry time across restarts. Transient network/5xx, HTTP 429 and recognized Gmail 403 rate-limit errors share a maximum of three delayed retries per checkpoint at 30, 120 and 300 seconds. Exhaustion and daily quota errors require explicit Resume. Authentication, invalid pages/cursors and storage failures do not retry automatically.
- macOS Sync notices and Activity display the next scheduled retry time. No automatic sending or calendar creation is added.

## Validation and limitations

Publication requires the existing macOS and Windows jobs to pass Rust formatting, strict Clippy, the locked Rust suite, native package builds and platform acceptance checks. The beta.18 test waiver does not apply. Both archives must pass the publisher's version, checksum and artifact-provenance checks before the pinned-key signed update manifest is published.

Beta.19 was not published: its tagged macOS job hit the existing window-divider fixture race again. Beta.20 re-resolves the displayed native split pane after layout, so assertions inspect the current view when SwiftUI replaces a pane; exact size assertions and deadlines are retained. The focused macOS workflow includes the calendar dependency and repeats the native window checks ten times. Production window behavior is unchanged.

The quota-retry review candidate passed [paired CI](https://github.com/Coke1120/Morrow-Mail/actions/runs/36383807674), with macOS passing after an unchanged rerun. The first macOS attempt failed an existing window-divider fixture assertion; 20 local repetitions at the CI-sized window passed. That intermittent fixture failure remains unexplained; assertions and deadlines were not relaxed.

Regression fixtures cover alternating transient error types, the three-retry limit, checkpoint recovery after restart, quota cooldown, background Sync, safe error messages and reconnect/disconnect isolation. These fixtures do not establish live-account quota behavior.

macOS is ad-hoc signed and is not Apple notarized; Windows is unsigned. Clean minimum-Windows environments, complete accessibility/IME/DPI testing and real-provider acceptance remain incomplete. This is an experimental prerelease. Attachments and CID images remain unsupported.

## Install and update

Download the matching macOS arm64 or Windows x64 ZIP, or use the explicit in-app update flow with its signed manifest. The updater retains the previous app and preserves the separate mailbox workspace. Back up the workspace before updating; do not run two clients against the same workspace simultaneously.

Windows requires a supported Windows 10/11 x64 environment. HTML mail uses WebView2 when available and otherwise falls back to plain text. Both platforms use the Rust service without a bundled Node runtime.
