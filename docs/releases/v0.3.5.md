## AI permission ready state

Settings → AI data permission names why Allow stays unavailable. The status
covers a missing saved API key or model, or a ChatGPT connection, plan step, or
model that is not ready. While the saved connection is not ready, the Allow
tooltip uses that same reason. Saving a key or signing in is still not consent.
Requested data categories and disclosure version stay the same.

## Consent review

Unsaved connection edits, a save in progress, and a pending permission read keep
Allow unavailable and say why. Save & review connection uses the existing save
path and does not grant permission. Choose permission after reviewing the saved
destination. Reopening Settings keeps unsaved connection edits and asks for a
fresh permission choice. Cancel / revoke still stops queued and active AI
requests; data already delivered cannot be recalled.

The material disclosure stays visible. Secondary and full detail sit in an
accordion. Explicit AI actions and background use stay separate choices. A
changed destination, model, or account still needs a new review.

## Gmail read pacing

Gmail API reads for one mailbox are spaced so a folder pass stays under
Google's per-user quota, with headroom. A full message read waits briefly after
it returns; metadata reads wait less. List and history passes still fetch at
most 20 messages. Writes and sends are not delayed and are not retried. Opening
a message still tries once. IMAP page delay and batch size are unchanged.

Quota pauses still honor Retry-After, capped at 15 minutes. The first two
pauses stay 30 seconds when Google does not say how long. Later pauses grow
from 2 minutes up to 15 minutes. A mailbox UID reset still uses the flat 15
minute pause. Permission and sign-in errors are not quota pauses.

This spacing is per mailbox in this app. It does not share one budget across
several Morrow accounts or machines for the same Google user, and it does not
show remaining quota.
