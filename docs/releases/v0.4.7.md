# Forward attachments and reply history

Forward loads the original message’s attachment bytes into the reviewed draft.
File chips remain removable and preview uses the same reviewed attachment set.
A missing or failed attachment keeps the forward closed for retry rather than
opening a partial draft. Cancelling a load or switching compose targets cannot
apply late results to a different draft.
Provider access stays bound to the original mailbox and message.

Reply and Reply All keep the new editable message separate from collapsible
original-message history. The history can be expanded, collapsed or hidden while
composing. Hiding it is a display choice, not removal from the outgoing message.
Preview, drafts and outgoing payloads retain the reviewed quoted content.

## Validation and limits

This release includes PRs #546 and #547 and preserves all previously released
v0.4.5 and v0.4.6 source, test fixes, notes and ancestry.

Focused synthetic tests exercise forwarding provider bytes, MIME/attachment
handling, cancellation and stale results, and production reply renderer/DOM
behavior. Independent review and rendered Chromium checks cover the affected
flows. The native reply-only compose window, actual preload cached-body IPC and
outgoing payload were also exercised with synthetic data.

The older general native UI harness did not complete unrelated shell focus and
settings coverage. An optional older Electron Undo check also fails on unchanged
dev; neither is reported as passing here. Live provider sends, real mailbox
attachment downloads and installed updater transitions remain unverified.

Windows remains unsigned. macOS remains ad hoc signed, without Developer ID or
notarization. The paired release workflow validates source provenance, asset
hashes, updater feeds, native Mac archive integrity and the Ed25519 manifest
before publication. This does not establish Gatekeeper trust or authorize
installation. Existing releases and signing roots are unchanged.
