# Morrow Mail 0.6.0-beta.18

This prerelease switches Windows from Electron to a native WinUI 3 / C++/WinRT interface. macOS remains native SwiftUI. Both packages run the same Rust mail service, without bundling Node, React or Electron.

- Native Windows mail, account/settings, search, AI/learning, reply suggestions, scheduled mail, Pending, calendar and Out of Office pages use the existing account-scoped Rust APIs.
- Reply, Reply All, Forward and provider-draft preparation share the Rust implementation. Existing mail, credentials, drafts and recovery records retain their storage identities.
- Native builds, versioned resources, redistribution notices and paired release signing now use the Rust tooling. The publisher binds both archives to this tag's GitHub build artifacts before signing the update manifest.
- Message HTML stays isolated, with scripts blocked, remote images off by default, reviewed links and plain-text fallback. Attachments and CID images remain unsupported.

The beta.17 attempt was not published: the publisher stopped when GitHub’s releases listing did not immediately show its newly created draft. This version uses the validated creation response directly, retaining the existing signature and artifact-provenance guards.

## Validation disclosure

**At the owner's explicit request, no new automated tests, UI walkthroughs, historical upgrade tests or benchmarks were run for this tag.** Both platform packages are rebuilt; packaging integrity, exact version/checksum checks, artifact provenance and pinned update signing remain mandatory. Successful build jobs are not a claim that the omitted tests passed.

Prior native and fixed-beta.16 compatibility/actual-upgrade checks passed at commit `2f39ade1d65cd60a7ae791c3c7b538b9199fe13d` in [CI 36361496967](https://github.com/Coke1120/Morrow-Mail/actions/runs/36361496967). That evidence predates this release's version, documentation and workflow changes. One earlier macOS reader-fixture timeout remains unexplained; the following run passed at the unchanged deadline.

Clean minimum-Windows environments, complete manual accessibility/IME/DPI testing, real-provider acceptance and comparative whole-app performance remain incomplete. macOS is ad-hoc signed and not Apple notarized; Windows is unsigned. This is an experimental prerelease, not stable-production certification.

## Install and update

Download the matching macOS arm64 or Windows x64 ZIP. Existing compatible installations may use the explicit in-app download/install flow and its pinned signed manifest. Back up the workspace before moving to this native prerelease. The updater retains the previous app and keeps mailbox data outside the app bundle; do not run old and new clients against the same workspace simultaneously.

Windows requires its supported Windows 10/11 x64 environment; HTML mail uses the installed WebView2 runtime and falls back to plain text when unavailable. Windows App SDK and VC runtime files are packaged app-locally. No updater privilege elevation or automatic installation is added.
