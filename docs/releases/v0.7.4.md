# Morrow Mail 0.7.4

This release includes PR30 and PR31: it keeps the Windows reading pane visible
after window/sidebar resizing and improves bounded mailbox synchronization.
The mail list preserves its requested width when space returns. Native layout
fixtures passed fresh/owned/restart in CI and Mac mini Parallels.

Synchronization reduces repeated
database/full-text work. Unchanged messages skip writes; read/star/folder metadata
can update without reindexing the full body. Actual searchable content changes
still refresh the index.

Gmail now persists history and crash-safe page/change checkpoints, resolving
new mail, labels and deletions and recovering expired cursors within reviewed
coverage. IMAP tracks new UIDs by connection/folder/UIDVALIDITY and uses
capability-gated CONDSTORE/QRESYNC for bounded cached flags/deletions, with polling
fallback. Outlook retains its existing delta worker while avoiding overlapping
rolling reads and allowing healthy folders to progress past blocked checkpoints.

Mutable drafts still refetch. Reviewed sent content, owner-bound attachment
bytes, current-page priority TTL, background quotas and user-controlled intervals
remain protected. See [synthetic measurements and bounds](https://github.com/Coke1120/Morrow-Mail/blob/v0.7.4/docs/SYNC_PERFORMANCE.md).
Backend timings do not establish a native UI or real-account latency gain.

The owner explicitly requested merging and publishing with the known Windows
validation failure disclosed. PR30 functional head
`4437f4eab324758a3531d9363c4e9062863a37b9` passed all three UI/persistence cases,
but [run 38231339110, attempt 1](https://github.com/Coke1120/Morrow-Mail/actions/runs/38231339110)

parent 7140, first `nativeAcquire` error 87 and unknown exit code. Relocated
acceptance was skipped. This remains a failed observation, not proof of a normal
exit or a repaired observer. Its documentation head is `0a0fa2b`.

PR31 head `77e8504` includes the complete final synthetic evidence; its candidate
CI was still pending when this release was prepared. Earlier `8fce7fd` Windows
CI failed with an actual CLI stack overflow (`0xC00000FD`). The source fix in
`34a9545` passed both platform Rust suites and the complete Windows native job;
its macOS reader batch was still running at preparation. These original failures
are retained, and no retry was used to relabel them as passes.

Publication still uses the unchanged workflow: both tagged native jobs and the
same-run/same-attempt pinned-key publisher must succeed. A published release
therefore establishes that tagged run's result, while the earlier failures above
remain unresolved historical evidence. Required gates, timeouts, TLS checks,
protections and update-signing keys were not bypassed, relaxed or changed.

macOS remains ad-hoc signed without Developer ID notarization; Windows remains
unsigned. The separate PR30 Parallels layout fixture does not establish strict
resource-collector, clean-machine, full manual accessibility or live-account
acceptance, or acceptance of the final combined release package. Pre-existing
Windows first-acquire error 87/unknown exits and intermittent reader timeouts are
not declared repaired. No real mail database, account credentials or live provider
was accessed by the synchronization/release task.
