## Settings AI data permission controls

Settings → AI could show `Unsupported channel` and leave Allow disabled even when the saved connection and explicit checkbox were ready. The first-party renderer preload now exposes the three existing consent status, grant and revoke invokes, so that Settings can use the existing host handlers. The separate AI Setup preload already supported them and is unchanged. No host validation or window configuration is changed by this fix.

A ready saved API or ChatGPT connection and the explicit manual-use checkbox are still required. Review the saved destination, model, account and disclosed data use before choosing Allow. Background use remains a separate optional choice. Saving a key, signing in or installing this update is not consent and does not create a grant automatically.

Permission remains bound to the saved destination/model/account; changes require fresh review. Existing stale-request, cross-window and revocation behavior remains in place. Revoke stops queued and active requests but cannot recall data already delivered. Unknown channels remain rejected. This release restores the Settings controls without changing those existing rules or acting on anyone's real consent settings.

## Distribution and live-validation limits

Windows remains unsigned. macOS uses ad hoc signing without Apple Developer ID or notarization. The separate Ed25519 manifest authenticates the macOS download, not OS execution trust. Native/rendered windows, live AI/provider behavior, real grants/accounts and native updater transitions remain untested. The existing renderer-navigation restriction was not retried or bypassed. No app installation/execution, real account action, Console or credential change is part of this release preparation.

The [v0.3.1 functional-fix limits](v0.3.1.md), [v0.3.0 sender/attachment behavior](v0.3.0.md) and [v0.2.39 Gmail/AI consent prerequisites](v0.2.39.md) remain applicable.
