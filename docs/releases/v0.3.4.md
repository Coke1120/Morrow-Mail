## Gmail sync failures after login

Gmail sync can still fail after Google login. When the response supplies
recognized evidence, sync activity and Debug log name an allowlisted category:
quota or rate limit, missing mail permission, a disabled API, domain policy, or
unknown. What is kept is a numeric HTTP status, a fixed operation, and
recognized Google reason or status codes. Raw provider bodies, URLs, tokens,
ids, and mail content are not included. A bare HTTP 403 stays unknown. A
successful Google login does not explain a later rejection.

## Debug records

Gmail sync Debug records no longer include the mailbox address, folder name, or
folder id. The mail UI and sync activity still show that mailbox and folder.
Other Debug entries may still include account or folder context and should be
reviewed before sharing.

## Rate pauses

When a Gmail error has a parsed category, that category controls rate pauses.
Auth, permission, and unknown results keep their existing paths even if the
reason text mentions rateLimitExceeded. Only a quota category uses the quota
pause. Errors without a Gmail diagnostic still use the existing rate-limit
heuristic.

## Unchanged connection behavior

This release does not identify or fix the live HTTP 403 reported after login on
v0.3.3. OAuth scopes, saved grants, credential storage, and write retries are
unchanged. The behavior is [PR #345](https://github.com/Coke1120/Morrow-Mail/pull/345).
See [Gmail error diagnostics](../GMAIL_ERROR_DIAGNOSTICS.md).
