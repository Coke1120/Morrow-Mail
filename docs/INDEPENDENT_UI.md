# Independent UI

`npm start` loads `renderer/` through the host IPC that already exists. It does not read `resources/ui.asar`, unless you set `MORROW_ASAR` to an `app.asar` path.

## What this shell does

- Lists accounts, folders, and messages (`mail:listAccounts`, `mail:listFromCache`). Previous and Next browse all cached folder or Starred messages in pages of 200 with a downloaded total. Sync more continues unfinished history at the current horizon. The host list query defaults to and caps each request at 2,000 rows; `offset` reaches subsequent pages. Settings → Mail & Sync also offers an opt-in Compact message list: one 32px row with sender, subject, and date. The default stays the comfortable multiline layout. A filter above the list matches subject, from, and snippet of messages already loaded and does not call `mail:search`
- Message rows show icon buttons on hover and when the row is focused: Star or Unstar (`mail:toggleStar`), Mark read or unread (`mail:markRead`), Reply, Reply All, Forward, and Delete (`mail:delete`). Star uses the same optimistic flag path as the reading pane. Reply, Reply All, and Forward use the open message, or `mail:openEmail`, then the compose dialog
- Syncs the open folder from the toolbar (`mail:listFromNetwork`). The Sync control keeps account, folder, phase, and last-success details in its tooltip and accessible label, with compact progress/error text beside it and a success label that collapses after five seconds (`mail:getSyncStatus`, `mail:syncStatus`). Debug log lists those host lines (`host:getDebugLog`) after passwords, tokens, and API keys are removed. Settings → Mail & Sync chooses the download horizon for every account: last 180 days (default), last 365 days, or All (unlimited). Each folder sync downloads in bounded batches; background sync stays on inbox plus the active folder. A folder that finished a shorter window catches up to the selected horizon on its next sync. Shortening the horizon keeps mail already stored. All removes the date bound for each folder you sync; open other folders to download their history. More history uses more disk space and makes the first sync longer. When the IMAP server advertises IDLE, new Inbox mail also arrives on one push connection and runs that same sync. The background poll stays, and it runs less often while that push connection is up. A rate limit pauses that account, including push.
- Reads a message (`mail:openEmail`) and marks it read (`mail:markRead`). The reading toolbar is icon buttons for Reply, Reply All, Suggest, Forward, Star, Archive, and Trash. Reply All is always there. Suggest sits beside Reply All and is the only control that starts reply suggestions. Opening or selecting a message does not. HTML newsletters keep table structure, alignment, colspan, and a filtered set of colors and CSS so the layout stays together. Plain-text bodies still preserve line breaks; that preformatted whitespace is not applied to HTML. Remote `http` and `https` images, including CSS backgrounds, stay blocked until Load remote content on that message, unless remote images are on in Settings. That allow lasts for the session and is not saved. Raster `data:` images that arrived with the message, including cid parts the parser inlined, still show. Links open in the system browser.
- Connects an IMAP account (`mail:listImapSmtpPresets`, `mail:connectImapSmtp`), including a Custom IMAP / SMTP card
- Starts Google or Microsoft sign-in in the browser (`mail:addAccount`) with one full Google consent or two Microsoft dialogs (Outlook mail, then the Graph feature bundle). IMAP stays the mail baseline. Calendar, organize, Out of Office, and rules reuse the bundle; missing access requests the provider bundle incrementally. The Folders & labels rail page manages Gmail labels and Outlook mail folders from the provider API; the Mail sidebar keeps IMAP folders only. Labels and folders nest when the list already has a parent: a Gmail name containing `/`, or an Outlook `parentFolderId`, including child folders Graph reports. Create, rename, and delete use `mail:createProviderFolder`, `mail:renameProviderFolder`, and `mail:deleteProviderFolder`. A new Outlook folder can sit inside a listed folder. A Gmail name can include `/`. Right-click adds or removes one Gmail label (`mail:modifyMessageLabels`) or moves one Outlook message (`mail:moveProviderMessage`). Dragging a row onto a Gmail label adds that label. Dragging onto an Outlook folder moves the message. Without that grant the sidebar keeps the IMAP folders, the menu says why, and it does not invent labels
- Removes a connected account after a confirm (`mail:removeAccount`). Mail stays on the server
- Compose stub for a connected account: save draft (`mail:upsertDraft`) and send (`mail:send`)
- Searches synced mail on this computer (`mail:searchLocal`): subject, from, and body in the local index. Sync, a downloaded body, a saved draft, and delete update that index. Clearing the box returns to the open folder. The list filter stays on mail already downloaded and does not call `mail:search`. `mail:search` still searches the server and does not use the local index
- Lists a conversation when the host returns `threadMessages` or a `threadId` (`mail:listThreadMessages`)
- Lists attachments and can save or open them (`mail:downloadAttachment`, `mail:openAttachmentExternally`)
- Stars or unstars the open message (`mail:toggleStar`) and a multi-selection (`mail:toggleStarBatch`). The stored flag is IMAP `\Flagged`: Gmail shows that as the star, and other servers, including Outlook, show it as the message flag. The reading-pane star fills gold immediately. A change the mailbox never received returns the outline and explains why in the status line. A change the server may already have keeps the gold star, and the status line tells you to try again. A starred row shows a gold star. Sidebar Starred, next to Inbox, Sent, and Drafts, lists starred messages already downloaded for the active account. It is a filter, not an IMAP mailbox. The chip bar is Inbox, Sent, Drafts, and Unread. Unread is a downloaded-mail filter in the sidebar next to Starred, not a mailbox. All Inbox, above the account rows, lists downloaded Inbox mail from every connected account, newest first, and hides when no account is connected. Right-click an account row and choose Rename to store a list label. Clearing it shows the provider name, or the address when the provider has none. The address and From stay the same.
- Archives, trashes, or moves it (`mail:archive`, `mail:threadArchive`, `mail:delete`, `mail:threadTrash`, `mail:moveToFolder`) and can undo when the host returns `opIds` (`mail:undoRemoval`). Right-click a message in the list or the reading pane, or use Organize, to move that one message to an IMAP folder. Drag a message row onto a sidebar folder to call the same move. Without the organize grant, that IMAP move still works. Shift-click, Cmd or Ctrl-click, and Select all choose loaded rows. A modifier click does not start a drag. The checkbox column stays visible until the selection is cleared. A plain click on a message clears that selection and opens the message, so the checkboxes stay hidden until a modifier click or the row checkbox. The selection bar archives, trashes, moves, labels, stars, and marks read, and a move, archive, or trash asks before any provider call. A drag from a multi-selection applies to every selected message. Right-click a label on Folders & labels, or an IMAP sidebar folder and choose Move… to change where it is nested. The picker filters by the full path and shows ancestors of a match. Confirm names the source and the destination before `mail:moveProviderFolder` or `mail:moveFolder`. Cancel does not call the provider
- Snoozes a thread for 1 hour, tonight, or tomorrow morning, and unsnoozes it (`mail:snoozeThread`, `mail:unsnoozeThread`, `mail:listSnoozed`)
- Translates the open message (`mail:translateStart`, `mail:translateCancel`, `mail:translate:event`). A missing API key is reported in the reading pane. The key is set in Settings or Morrow Mail → AI Setup
- Inserts a host signature in compose (`mail:listSignatures`) for the alias domain when an alias sets one, otherwise the host of From, then the account default (`defaultSignaturePerAccount`), or shows an empty state when that account has none
- Edits those signatures from Settings (`mail:upsertSignature`, `mail:deleteSignature`): name plus text or HTML, an optional default for the selected account, and optional domains. A listed domain uses this signature when that domain is the alias domain, or the host of From when the alias sets none. Otherwise compose uses the account default. Changing From between a Gmail address and an alias swaps the signature while the body still ends with the previous one. Signatures and those domain rows are stored on this computer in `mail.sqlite`, one list per account. `defaultSignaturePerAccount` maps each account to its default signature. They are not stored on the mail server. With no connected account the list is empty and a write asks you to connect one
- Drafts with AI from compose (`aiDraftWrite:start`, `aiDraftWrite:cancel`, `aiDraftWrite:event`). Suggest on the open message lists reply suggestions (`aiDraftWrite:replySuggestions`). Opening or selecting a message does not call it. A missing API key is reported in place
- Calendar (`calendar:status`, `calendar:list`, `calendar:createEvent`, `calendar:updateEvent`, `calendar:deleteEvent`, `calendar:connect`) lists and writes events on Google Calendar or Microsoft Graph for the visible month. The month page has a sidebar (mini month, calendars, agenda) and a grid of all-day banners and timed chips. Choosing an event shows its title, time, calendar, location, and description. Create and edit use a dialog. Delete asks for confirmation. With no mailbox, no token, or when Google Desktop OAuth is not configured, the page says what is missing and does not draw events
- About & updates opens beneath Debug log in the rail. This shared sheet shows a short description of the Electron client, the app version, and checks or installs updates (`app:getVersion`, `host:updateGetState`, `host:updateCheck`, `host:updateInstall`)
- Edits theme, accent, conversation view, remote images, undo send, snooze, AI write on reply, folder chips, and sidebar folder expansion (`config:setTheme`, `morrow:configSet*`). Use Brain → Organize Inbox to file the inbox. Base URL, model id, and API key are set in that same Settings dialog (`host:aiGetConfig`, `host:aiSaveConfig`, `host:aiListModels`, `host:aiTest`) and in Morrow Mail → AI Setup. The key stays in local `ai.json`, not `settings.json`. Settings and the other dialogs scroll their body so Save and the AI fields stay reachable on a short window. Settings shows its shell immediately and fills it after a paint opportunity. Settings uses keyboard-accessible tabs: General, Mail & Sync, Accounts, AI, Out of Office, and Bot access. Bot access has Local, Tailscale, Grants, and Agent setup sections. Arrow Left/Right and Home/End select a tab; Tab enters its panel. The last selected tab stays selected for the renderer session. Only the active panel is visible; AI, Accounts, Out of Office, and Bot fetch lazily, with pending reads coalesced. The mailbox selector appears only for Accounts and Out of Office.
- Inbox rules open from Settings and from the Email Brain Rules tab (`mail:listInboxRules`, `mail:saveInboxRule`, `mail:deleteInboxRule`). A Gmail or Microsoft mailbox uses the bundled permissions for its own filters or inbox rules; `mail:grantRules` requests missing access. Creating, editing, and deleting call those APIs. Other accounts store the rule on this computer and run it when new Inbox mail is downloaded. Mail already stored is left in place. A rule matches From, To, subject, text, or attachments, then marks read, stars, archives, trashes, moves, or adds a Gmail label. It does not forward mail. With no account the page says to connect one. There is no sample mailbox
- Email Brain opens from the leftmost rail, beside Calendar, as its own page in place of the mail shell: Profile, Categories, Skills, and Rules. Profile lists cached sections, persona meta when present, recent updates, and writing rules (`emailBrain:getCached`). A user rule can be added, edited, or deleted. A learned row can be fixed or forgotten. Refresh calls `emailBrain:refresh`. Rebuild calls `emailBrain:rebuild` after a confirm. They say they need an AI key in Morrow Mail → AI Setup when the host returns `accepted: false`. No mailbox or an empty cache is a host error and does not use sample mail. Persona text prefers sent mail. Categories in that page load from `emailBrain:getCategories`, edit locally (including reorder), and save with `emailBrain:saveCategories`, which refreshes the Agent home sections. Add with AI and Fix category need an API key and show the host error when the key is missing
- Email Brain skills library lists home and library skills in that same pane (`emailBrain:getSkills`, `emailBrain:getLibrarySkills`). Each row shows its description. With no schedule it runs on demand. Install and remove persist in the local brain store (`emailBrain:installSkill`, `emailBrain:removeSkill`). A home skill can save, edit, or pause an interval or five-field cron schedule (`emailBrain:setSkillSchedule`, `emailBrain:deleteSkillSchedule`). The same controls are on Agent's skill list. A due schedule runs on the host while the app is open and does not block the window. Pause keeps the saved row from firing. Running a skill (`emailBrain:runSkill`) calls the configured model with cached mailbox context and shows the result in the panel. No API key or no mailbox returns `accepted: false`. Drafts open in compose for review. Organize moves wait for confirm. Nothing is sent
- Agent opens from the leftmost rail (Agent, Mail, Calendar, Brain) and replaces the mail shell. The page is a greeting, category todo stacks (`nativeAgent:home:todosCached`, refreshed with `nativeAgent:triage` when stale), skill chips, Manage Skills, and a composer pinned to the bottom of the Conversation transcript (`nativeAgent:chat`, `nativeAgent:chatHistory`). Standing notes live in `agent-memory.json` (`nativeAgent:memorySet`). Triage files recent inbox mail into Brain categories. Done and Dismiss are local (`nativeAgent:home:todoUpdate`). An Agent row opens `dialog#agent-peek` and stays on Agent. Open in Mail uses the mail reader. Home and library skills use `nativeAgent:home:skills` and `nativeAgent:home:librarySkills`. Home skills show the same interval or cron schedule as Brain, and Save schedule, Pause, and Resume call `emailBrain:setSkillSchedule`. Brief This Person takes the open message or an email address, and a schedule for that skill stores the contact email. Run history uses `nativeAgent:history` and can reopen a saved run in the transcript. A background run announces `emailBrain:scheduleFired` and refreshes history without taking over the composer. Missing key, missing mailbox, and an empty cache stay empty of mail. A draft reply stays in compose until you send it. Opening Agent briefly animates its page sections together. While Agent is loading or answering, a light overlay and spinner sit on that page only and read Working…. The sidebar stays clickable.
- Schedules a send from New Mail (`mail:scheduleSend`) and lists it (`mail:listScheduled`). The queue is stored in `mail.sqlite`. Morrow Mail sends it while the app is open. A time that passes while the app is closed is sent the next time the app is open. `mail:cancelScheduled` removes a pending or failed row. The scheduled list includes every account, whichever mailbox is selected. Cancel asks twice, then Undo calls `mail:restoreScheduled` for about 8 seconds. Send and Schedule send open a preview of recipients, subject, body, and the schedule time when there is one. Confirm commits the send or schedule. Cancel returns to the editor. Settings stores `defaultScheduleDelayMinutes` (`morrow:configGetDefaultScheduleDelayMinutes`). Zero sends immediately. Any other value makes Send schedule that far ahead, and Send now still delivers immediately. Send, save draft, and schedule stay disabled until an account is connected
- The main window writes size, position, maximized, fullscreen, and zoom to `window-state.json`. Relaunch restores them. A first launch uses 1200×800 (1720×1040 for an external shell), zoom level 0, and the system places the window. Folder and list widths are `layoutPanes` in `settings.json` (`morrow:configGetLayoutPanes`), default 260 and 360. The reading pane is the remaining column. View → Actual Size, Zoom In, and Zoom Out use Cmd/Ctrl+0, Cmd/Ctrl++, and Cmd/Ctrl+−
- Replies or forwards the open message in that same dialog. Reply puts the sender in To. Reply All puts the sender in To and the other To and Cc addresses in Cc. Forward names attachments and does not upload them. Compose lays out To, Cc, Bcc, subject, and the body. The picker uses the signature for the alias domain when an alias sets one, otherwise the host of From, then that account's default from `defaultSignaturePerAccount`. Changing From between a Gmail address and an alias swaps the signature while the body still ends with the previous one. Reply, Reply All, and Forward keep the original message in a quoted pane beside the draft. At about 900px of compose width the quote is on the left and the draft is on the right. A narrower dialog stacks the quote on top, where it can collapse. The quoting dialog grows with the draft and the quoted original, up to the window. Quote text scrolls inside it. Collapse hides the quote body so it does not paint over the mail behind the dialog. Reply and Reply All show that pane. Forward leaves it hidden until Show quoted message. The wide divider width is stored in `settings.json` (`morrow:configGetComposeQuoteWidth`). Close does not send. The compose dialog is about 85% of the window width. Close discards; if the message changed since the last save, it asks you to discard or keep editing and does not save. Save draft stays a separate button. The body is HTML: Bold, Italic, Underline, and lists, and a pasted HTML fragment is kept after the same sanitizing used for reading mail. The quoted original is still included when you save, send, or schedule

With no connected account the host returns an empty mailbox. There is no sample inbox. The shell shows a Connect account button. Translate and AI write show the host error when no API key is set. Reply suggestions show that error after Suggest. Email Brain still lists the cached snapshot, with an empty writing list, and refresh says it needs an AI key. Categories still load, edit, and save with no key. Skills list the Morrow Mail catalog and refuse to run until an API key and a connected mailbox are present. Agent triage does the same. Compose has no signatures until an account is connected. Send stays disabled. Connecting an account uses the live IMAP engine for the same channels.

`MORROW_ASAR=/absolute/path/to/app.asar` still boots that external renderer and its preload. That is the only fallback. Leave it unset for the first-party shell.
