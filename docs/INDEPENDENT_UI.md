# Independent UI

Phase-two mail responsiveness batches action generations for lists/thread rows
and reuses account IDs already present in list metadata for prefetch admission.
Body notifications contain availability and scoped versions; open readers and
previews pull current snapshots from local mail without provider fetches. The
per-window body-only cache has 32-entry / estimated 8 MiB string / 2 MiB entry
limits. Active views and compositions retain their own data; eviction deletes no
mail, draft or attachment. Stale connection responses and superseded reads are
ignored, and fresh snapshots retain inline attachment/sender/draft metadata.
See [phase-two evidence and limits](PERFORMANCE_PHASE_TWO.md).

Mail list and header-only thread queries omit body strings from JavaScript rows,
and IMAP sync preserves search entries for unchanged indexed content. Full message
and full-thread responses retain their bodies. Optional `MORROW_PERF=1` local
timings appear in Debug log every 30 seconds with fixed labels and numeric
aggregates, no mail/request/identity/path/credential data or telemetry. On macOS,
routine mail reads and startup checks use the bounded asynchronous Keychain path;
compatibility calls remain synchronous with a per-command deadline.
Durable writes keep their existing semantics. See [Keychain read coverage and
limits](adr/2026-10-27-keychain-read-deadlines.md) and [performance diagnostics
and synthetic measurements](PERFORMANCE.md); native Mac freezes remain unverified.

`npm start` loads `renderer/` through the host IPC that already exists. It does not read `resources/ui.asar`, unless you set `MORROW_ASAR` to an `app.asar` path.

## What this shell does

- Continue with Google stays the primary Google sign-in action and uses the bundled Desktop client when present unless explicitly overridden. New connections and Gmail OAuth reconnects collapse Other email provider; manual reconnects keep their form. All connection entrypoints reset previous form state. A legacy Gmail migration error offers Review Gmail API migration to open the matching Accounts permission section without starting migration or entering a password. Review and confirmation remain required. Personal client import is an optional advanced choice; readiness checks only local configuration.

- Settings → AI can review, allow and revoke AI data permission through the same existing host consent handlers as AI Setup. The exact three invoke channels are allowlisted in the first-party preload; unknown channels stay rejected. A ready saved connection and explicit-action checkbox are required, with separate optional background permission. If Allow stays unavailable, the status names the missing saved API key, model, ChatGPT connection, or plan step. Unsaved edits, saves and pending permission reads also block Allow; Save & review saves without approving data use. Reopening Settings preserves connection drafts, clears checkbox choices and refreshes saved permission without waiting for a closed session's read. Material disclosure stays visible, with full text and secondary connection details in native accordions. Regression tests include the actual preload, Settings mount, config/consent validation and in-memory persistence, without native windows or live AI calls.

- Scheduled cleanup also recognizes historical provider display text with literal quotes, angle brackets and Unicode names. Tests create real MIME and pass synthetic IMAP search results through the production parser/formatter, then verify metadata-only cleanup and protection of later name, From and body edits.

- Resuming or recovering a sender-named draft keeps its bare From address, including names with angle brackets, quotes and Unicode. It does not reparse a display preview as an email address. Equivalent legacy sender metadata refreshes preserve queued cleanup proofs; genuinely edited drafts remain saved after the queued snapshot sends.

- Settings → Compose has a Sender identities editor with an exact-address list, primary / Gmail-verified / Gmail-default / new-mail From states, a Morrow display-name field and recipient-visible preview. Discovery supplies Gmail names, including primary-name inheritance for blank custom names. Local overrides live in `brainCompose.accounts[accountId].senderNames` in `settings.json` and survive refresh; an empty override is address-only and resetting removes the override. Manual aliases remain explicitly unverified. Gmail settings and OAuth scopes are unchanged. Open compositions, saved drafts and scheduled content retain their selected name; choosing another From uses that identity's current name. The send preview shows From, and MIME uses Nodemailer structured addresses for quoting/Unicode. Other providers keep their existing alias restrictions. Provider or recipient contacts can alter the final display. Synthetic DOM/MIME tests do not verify native windows or live delivery.

- An IMAP socket timeout during a pending sync or message fetch follows the operation's error path. Sync reports a connection error and uses its existing retry schedule. Inbox push falls back to polling and reconnects with its existing backoff, including a timeout while selecting Inbox before IDLE starts. Errors during logout do not replace an already completed operation. The client keeps its error listener through close, so late socket events are handled without a global exception dialog. Regression checks use real ImapFlow with a synthetic transport and DOM fixtures; they do not verify a native macOS window or a real mailbox.

Reply, Reply All, and Forward keep the original message in a quoted pane beside the draft. At about 900px of compose window width the quote is on the left and the draft is on the right. A narrower window stacks the quote on top, where it can collapse. The quoting window grows with the draft and the quoted original, up to the window. Quote text scrolls inside it. Collapse hides the quote body so the draft can use that space. Reply and Reply All show that pane. Forward leaves it hidden until Show quoted message. The wide divider width is stored in `settings.json` (`morrow:configGetComposeQuoteWidth`). Close does not send. New Mail, Reply, Reply All, Forward, a resumed draft, and a Bot review draft each open a compose window. More than one can stay open, and the mail window stays usable. Close discards; if the message changed since the last save, it asks you to discard or keep editing and does not save. Save draft stays a separate button. The body is HTML: Bold, Italic, Underline, lists, text color, and highlight, and a pasted HTML fragment is kept after the same sanitizing used for reading mail. The quoted original is still included when you save, send, or schedule

Signature saves show Saving… and ignore repeated submits in the current editor until the save finishes. Switching signatures, clearing the form, or reopening the dialog starts a new editing session. Earlier save completions and errors do not change its target or feedback. A failed current save keeps the text and enables Save again.

Mail → Bodies is a small disclosure in the list header, separate from list/header synchronization. It reports body activity for all connected mailboxes: downloading, waiting for mail work, idle/last download finished, rate-limit or connection hints, and bounded error reasons. It uses `mail:getBodySyncStatus` / `mail:bodySyncStatus`; snapshots have a process session and sequence so stale reads cannot overwrite newer events. Account removal/replacement and process restart discard old activity. These in-memory observations contain no message IDs, subjects, senders, bodies or raw provider errors. There is no global body total, remaining estimate, percentage, or claim that all mail is cached.

The existing slow fill runs only inside the running app's background poll, from 00:00 until 07:00 local time (exclusive). A nominal 45-second tick can be delayed by preceding folder work. Each pass chooses at most one body from up to 200 newest indexed candidates in the All/365/180-day horizon; drafts, trash and spam are excluded. Message opens and visible-page prefetch can fetch bodies throughout the day, ahead of the slow fill. A source read is capped at 3 MiB, so large messages can remain incomplete. Separate attachment-file downloads stay on demand; raw MIME source may include attachment portions. Sleep/quit cannot download or trigger a wakeup; there is no independent OS overnight job or guarantee of full overnight coverage. Offline/connection hints report observed availability and do not cancel requests or change the existing polling/retry policy. On macOS, hiding the main window can leave the app running; quitting stops it.

Calendar form validation and save errors appear inside the event dialog. The error receives keyboard focus, the entered values remain available, and a failed save releases the pending state. A response for a dismissed or replaced editor does not change the new event's feedback.

Timed calendar events appear on every local date they overlap, including across months and daylight-saving changes. The ending instant is exclusive. An invalid date range is reported before read-only description restrictions. Cancel closes the editor; it does not cancel a save already submitted. A successful save invalidates that mailbox's cached months and pre-save list responses even after Cancel. The visible calendar refreshes when no newer event editor is open; a newer editor, mailbox, or status keeps its ownership.

With no connected account the host returns an empty mailbox. There is no sample inbox. The shell shows a Connect account button. Translate and AI write show the host error when no API key is set. ## AI authentication

Both settings surfaces include **AI data permission** for API/custom endpoints and ChatGPT. The initially unchecked action and background choices follow a destination/data/purpose disclosure. Existing settings are not grandfathered; key entry, Save, catalog fetch and sign-in are not consent. A changed provider/endpoint/model/account needs fresh permission. Cancel / revoke aborts pending requests and prevents queued work from resuming after reapproval. Automatic reply suggestions on compose open also need background permission. See [AI data use](AI_DATA_USE.md); this draft does not deploy a policy or change Google scopes.

Settings → Accounts → Advanced: personal Google OAuth client (optional) imports a Desktop client JSON into this computer's app data. That file is preferred over a bundled client. Environment variables still win. The client secret is not shown. Clear removes only the imported file. Changing clients, or an older grant with no recorded client, requires Gmail and separate Calendar reauthorization; cached work and old credentials stay until successful consent. Import/clear and Google sign-in cannot overlap. Invalid environment overrides are identified as environment errors. See [Bring your own Google Desktop client](bring-your-own-google-oauth.md). Settings → Accounts → Permissions & calendar access keeps Google OAuth login and offers reviewed Gmail API migration/reauthorization on the existing OAuth account. New Google connections request gmail.modify + gmail.settings.basic; Calendar grants are separate. Account ids, cached mail and local draft edits stay. Requested and actual saved grants are shown separately; a narrower request does not revoke older broad grants. Cancel blocks late pre-commit login results; unconfirmed cancellation keeps another authorization blocked. Migrated mail uses history/polling and never falls back to IMAP/SMTP. Gmail ordinary Delete and batch Delete from Trash preserve Trash; old remote draft cleanup moves to Trash. Other providers retain existing deletion behavior. See [the separate migration draft's coverage](GMAIL_API_MIGRATION.md).

Settings → AI and Morrow Mail → AI Setup now share an explicit API key/custom endpoint or ChatGPT account choice. Existing API values are retained. Saves apply the submitted snapshot: edits made while saving remain in the form with an unsaved notice, and repeated saves wait for the pending save. Connection tests and model reads discard obsolete results after another operation or a change to the relevant settings/account. Cancelling sign-in retires the old UI operation and aborts its discovery wait; after cancellation returns, a fresh attempt can start immediately and ignores late responses from the old attempt. ChatGPT uses the official open-source registration flow, browser loopback with optional one-time paste-back, account-specific model choices, and a separate Responses adapter. Background use requires express account consent; no API/provider fallback is automatic. Tokens stay in a main-process encrypted record, and the CLI/bot does not expose them. See [the design and synthetic/live validation boundary](adr/2026-10-25-chatgpt-model-provider.md).

Resuming a provider draft prepares its files through `mail:prepareDraft` before opening compose. The existing attachment transfer panel reports preparation and offers Cancel. All required files must be available within the 25 MiB outgoing limit. Errors keep the source draft for retry; nothing is silently omitted. Hydration keeps the source revision unchanged, and saved/scheduled content owns local bytes and inline content IDs. Save, Send and Schedule wait for AI writing to finish or be cancelled. Send/Schedule confirmation uses the complete reviewed payload; changed content requires a new preview.

Gmail text parts use mail charset aliases, including cp932 and UTF-7. Network, account-identity and storage failures retain their existing error paths.
