# Independent UI

`npm start` loads `renderer/` through the host IPC that already exists. It does not open Genspark Super App, and it does not read `resources/ui.asar`, unless you set `GENMAIL_ASAR` to an `app.asar` path.

## What this shell does

- Lists accounts, folders, and messages (`mail:listAccounts`, `mail:listFromCache`). A filter above the list matches subject, from, and snippet of messages already loaded and does not call `mail:search`
- Message rows show icon buttons labeled Mark read or unread (`mail:markRead`), Delete (`mail:delete`), Reply, and Reply All on hover and when the row is focused. Reply uses the open message, or `mail:openEmail`, then the compose dialog
- Syncs the open folder from the toolbar (`mail:listFromNetwork`). Each folder sync keeps about the last 180 days, paged, and background sync stays on inbox plus the active folder. A folder that already finished a shorter window catches up to 180 days and keeps the mail already stored. When the IMAP server advertises IDLE, new Inbox mail also arrives on one push connection and runs that same sync. The background poll stays, and it runs less often while that push connection is up. A rate limit pauses that account, including push. It does not download the whole mailbox
- Reads a message (`mail:openEmail`) and marks it read (`mail:markRead`). The reading toolbar is icon buttons for Reply, Reply All, Forward, Star, Archive, and Trash. Reply All is always there. Remote `http` and `https` images stay blocked until Load remote content on that message, unless remote images are on in Settings. That allow lasts for the session and is not saved
- Connects an IMAP account (`mail:listImapSmtpPresets`, `mail:connectImapSmtp`), including a Custom IMAP / SMTP card
- Starts Google or Microsoft sign-in in the browser (`mail:addAccount`) for the IMAP baseline. A second consent (`mail:grantOrganize`) loads Gmail labels or Outlook mail folders from the provider API. Labels and folders nest when the list already has a parent: a Gmail name containing `/`, or an Outlook `parentFolderId`, including child folders Graph reports. Create, rename, and delete use `mail:createProviderFolder`, `mail:renameProviderFolder`, and `mail:deleteProviderFolder`. A new Outlook folder can sit inside a listed folder. A Gmail name can include `/`. Right-click adds or removes one Gmail label (`mail:modifyMessageLabels`) or moves one Outlook message (`mail:moveProviderMessage`). Dragging a row onto a Gmail label adds that label. Dragging onto an Outlook folder moves the message. Without that grant the sidebar keeps the IMAP folders, the menu says why, and it does not invent labels
- Removes a connected account after a confirm (`mail:removeAccount`). Mail stays on the server
- Compose stub for a connected account: save draft (`mail:upsertDraft`) and send (`mail:send`)
- Searches mail on the server (`mail:search`). Clearing the box returns to the open folder. The list filter stays on mail already downloaded
- Lists a conversation when the host returns `threadMessages` or a `threadId` (`mail:listThreadMessages`)
- Lists attachments and can save or open them (`mail:downloadAttachment`, `mail:openAttachmentExternally`)
- Stars or unstars the open message (`mail:toggleStar`)
- Archives, trashes, or moves it (`mail:archive`, `mail:threadArchive`, `mail:delete`, `mail:threadTrash`, `mail:moveToFolder`) and can undo when the host returns `opIds` (`mail:undoRemoval`). Right-click a message in the list or the reading pane, or use Organize, to move that one message to an IMAP folder. Drag a message row onto a sidebar folder to call the same move. Without the organize grant, that IMAP move still works. Shift-click, Cmd or Ctrl-click, and Select all choose loaded rows. The selection bar archives, trashes, moves, labels, stars, and marks read, and a move, archive, or trash asks before any provider call. A drag from a multi-selection applies to every selected message. Right-click a sidebar label or folder and choose Move… to change where it is nested. The picker filters by the full path and shows ancestors of a match. Confirm names the source and the destination before `mail:moveProviderFolder` or `mail:moveFolder`. Cancel does not call the provider
- Snoozes a thread for 1 hour, tonight, or tomorrow morning, and unsnoozes it (`mail:snoozeThread`, `mail:unsnoozeThread`, `mail:listSnoozed`)
- Translates the open message (`mail:translateStart`, `mail:translateCancel`, `mail:translate:event`). A missing API key is reported in the reading pane. The key is set in Settings or GenMail → AI Setup
- Inserts a host signature in compose (`mail:listSignatures`), or shows an empty state when that account has none
- Edits those signatures from Settings (`mail:upsertSignature`, `mail:deleteSignature`): name plus text or HTML, and an optional default for the selected account. Signatures are stored on this computer in `mail.sqlite`, one list per account. `defaultSignaturePerAccount` maps each account to its default signature. They are not stored on the mail server. With no connected account the list is empty and a write asks you to connect one
- Drafts with AI from compose (`aiDraftWrite:start`, `aiDraftWrite:cancel`, `aiDraftWrite:event`) and lists reply suggestions on the open message (`aiDraftWrite:replySuggestions`). A missing API key is reported in place
- Calendar (`calendar:status`, `calendar:list`, `calendar:createEvent`, `calendar:connect`) lists and creates events from Google Calendar or Microsoft Graph for the visible month. The grid and agenda show the provider's title, time, and location. With no mailbox, no token, or when Google Desktop OAuth is not configured, the page says what is missing and does not draw events
- Shows the app version and checks or installs updates (`app:getVersion`, `host:updateGetState`, `host:updateCheck`, `host:updateInstall`)
- Edits theme, accent, conversation view, remote images, undo send, snooze, AI write on reply, folder chips, one-click tidy, and sidebar folder expansion (`config:setTheme`, `genmail:configSet*`). Base URL, model id, and API key are set in that same Settings dialog (`host:aiGetConfig`, `host:aiSaveConfig`, `host:aiListModels`, `host:aiTest`) and in GenMail → AI Setup. The key stays in local `ai.json`, not `settings.json`. Settings and the other dialogs scroll their body so Save and the AI fields stay reachable on a short window
- Email Brain opens from the leftmost rail, beside Calendar, as its own page in place of the mail shell: Profile, Categories, and Skills. Profile lists cached sections, persona meta when present, recent updates, and writing rules (`emailBrain:getCached`). A user rule can be added, edited, or deleted. A learned row can be fixed or forgotten. Refresh calls `emailBrain:refresh`. Rebuild calls `emailBrain:rebuild` after a confirm. They say they need an AI key in GenMail → AI Setup when the host returns `accepted: false`. No mailbox or an empty cache is a host error and does not use sample mail. Persona text prefers sent mail. Categories in that page load from `emailBrain:getCategories`, edit locally (including reorder), and save with `emailBrain:saveCategories`, which refreshes the Agent home sections. Add with AI and Fix category need an API key and show the host error when the key is missing
- Email Brain skills library lists home and library skills in that same pane (`emailBrain:getSkills`, `emailBrain:getLibrarySkills`). Each row shows its description and that it runs on demand. Install and remove persist in the local brain store (`emailBrain:installSkill`, `emailBrain:removeSkill`). Running a skill (`emailBrain:runSkill`) calls the configured model with cached mailbox context and shows the result in the panel. No API key or no mailbox returns `accepted: false`. Drafts open in compose for review. Organize moves wait for confirm
- Agent opens from the leftmost rail (Agent, Mail, Calendar, Brain) or the toolbar Agent button, and replaces the mail shell. The page is a greeting, category todo stacks (`nativeAgent:home:todosCached`, refreshed with `nativeAgent:triage` when stale), skill chips, Manage Skills, and a composer (`nativeAgent:chat`, `nativeAgent:chatHistory`). Standing notes live in `agent-memory.json` (`nativeAgent:memorySet`). Triage files recent inbox mail into Brain categories. Done and Dismiss are local (`nativeAgent:home:todoUpdate`). Each row can open that message in Mail. Home and library skills use `nativeAgent:home:skills` and `nativeAgent:home:librarySkills`. Brief This Person takes the open message or an email address. Run history uses `nativeAgent:history` and can reopen a saved run in the transcript. Missing key, missing mailbox, and an empty cache stay empty of mail. A draft reply stays in compose until you send it. Skills stay on demand
- Schedules a send from New Mail (`mail:scheduleSend`) and lists it (`mail:listScheduled`). The queue is stored in `mail.sqlite`. GenMail sends it while the app is open. A time that passes while the app is closed is sent the next time the app is open. `mail:cancelScheduled` removes a pending or failed row. Send, save draft, and schedule stay disabled until an account is connected
- Replies or forwards the open message in that same dialog. Reply puts the sender in To. Reply All puts the sender in To and the other To and Cc addresses in Cc. Forward names attachments and does not upload them. Compose lays out To, Cc, Bcc, subject, and the body. The picker uses that account's default from `defaultSignaturePerAccount`. Reply, Reply All, and Forward keep the original message in a quoted pane beside the draft. At about 900px of compose width the quote is on the left and the draft is on the right. A narrower dialog stacks the quote on top, where it can collapse. Reply and Reply All show that pane. Forward leaves it hidden until Show quoted message. The wide divider width is stored in `settings.json` (`genmail:configGetComposeQuoteWidth`). Close does not send. The quoted original is still included when you save, send, or schedule

With no connected account the host returns an empty mailbox. There is no sample inbox. The shell shows a Connect account button. Translate, AI write, and reply suggestions show the host error when no API key is set. Email Brain still lists the cached snapshot, with an empty writing list, and refresh says it needs an AI key. Categories still load, edit, and save with no key. Skills list the GenMail catalog and refuse to run until an API key and a connected mailbox are present. Agent triage does the same. Compose has no signatures until an account is connected. Send stays disabled. Connecting an account uses the live IMAP engine for the same channels.

`GENMAIL_ASAR=/absolute/path/to/app.asar` still boots that external renderer and its preload. That is the only fallback.
