# Shell parity

First-party `renderer/` chrome for the three-pane mail shell. Layout follows the host IPC already in this repo. The look follows the GenMail plum shell: dark rail, aubergine canvas, white floating list and reading cards. The Genspark `app.asar` is not vendored and was not required to boot.

## Look

- Light theme uses the plum tokens: rail `#410c42`, canvas `#572658`, white cards with a 16px radius and a soft shadow, a 56px toolbar, a 260px folder column, and 32px folder rows. Unread counts are a `#e8bcf9` pill.
- Message rows are 68px: an initial avatar, the sender, the subject with the date on that line, and one snippet line. Unread rows are heavier and show an accent dot. The open row uses the selected wash.
- The toolbar is a white New Mail pill, light action labels, and a translucent search field. The version and updater sit at the bottom of the folder column, so the list and reading cards start under that bar.
- An empty reading pane shows an envelope and “No conversation selected”.
- Settings, Brain, Studio, Compose, Connect, and Signatures share that font, paper surface, 16px radius, and accent primary buttons.
- `data-theme="dark"` switches the canvas to `#141414` and the cards to `#1f1f1f`. The saved accent sets `--accent` on unread text, the unread dot, stars, focus, and dialog primary buttons. The plum chrome stays put.
- Motion fades the first screen of message rows, the mail, calendar, and agent panels, and open dialogs. New Mail, the rail, and dialog primary buttons scale slightly on hover and press. `prefers-reduced-motion: reduce` skips that motion. Row height stays 68px.

`shortcut: accent does not reskin the chrome into the other GenMail skins, upgrade when a skin map is worth it.`

## Matched

- Folder sidebar from each account's `folders.primary` then `folders.more` (Inbox, Sent, Drafts, and any other folder the host returns). A non-zero `unreadCount` is shown on the row.
- Message list: sender, subject, date, snippet. The open row sets `aria-current`. Unread rows are bold, with a dot. ↑ and ↓ move a cursor; Enter opens that row (a focused row uses the button's own click). Hover and keyboard focus show icon buttons labeled Mark read or Mark unread (`mail:markRead`), Delete (`mail:delete` for that message), Reply, and Reply All. Reply uses the open message or `mail:openEmail`, then the compose dialog.
- Reading pane: subject, from, date, To and Cc when the message has them, then the body. Empty state when nothing is open. Opening an unread message still calls `mail:markRead`. The reading toolbar is icon buttons for Reply, Reply All, Forward, Star, Archive, and Trash. Reply All is always shown. Move and Snooze stay menus on that bar.
- Toolbar actions: Sync (`mail:listFromNetwork`), New Mail (`mail:upsertDraft`, `mail:send`), and One-click tidy (`mail:tidyInbox`) on Inbox when that preference is effective. Signatures, Connect account (`mail:connectImapSmtp`, `mail:addAccount`), and Remove account (`mail:removeAccount`) sit in Settings.
- Search: the toolbar box submits `mail:search` with `query`, `limit`, and `filters` and searches mail on the server. Results replace the message list. Clearing the box, or choosing a folder, loads that folder again. Choosing a folder syncs its 30-day window and clears the list filter. The filter above the list matches subject, from, and snippet of messages already loaded. It does not call `mail:search`. Background sync stays on inbox and the active folder. A rate limit pauses that account. Older than 30 days is not downloaded.
- Conversation: when conversation view is on, the reader uses `threadMessages` from `mail:openEmail` when the host sends any. If that list is empty and the message has `threadId`, it calls `mail:listThreadMessages`. Two or more members are listed; the message you opened stays the body. When conversation view is off, the reader shows that message alone and does not call `mail:listThreadMessages`.
- Attachments: the reader lists `attachments` from the open message (name and size). Save calls `mail:downloadAttachment`. Open calls `mail:openAttachmentExternally`. A message that only sets `hasAttachments` shows that fact with no buttons.
- Star on the open message (`mail:toggleStar`). A starred row shows a star.
- Archive and Trash. One message uses `mail:archive` or `mail:delete`. A conversation uses `mail:threadArchive` or `mail:threadTrash`.
- Move (`mail:moveToFolder`) picks a folder from the open message's account. IMAP folders indent when one path sits inside another that is already listed. Right-click the message list or the reading pane, or use Organize on the reading bar, for Move to folder. Dragging a message row onto a sidebar folder moves that one message. The reading pane still has the Move menu.
- Snooze presets are 1 hour, tonight, and tomorrow morning (`mail:snoozeThread`). Unsnooze (`mail:unsnoozeThread`) shows when `mail:listSnoozed` says that thread is snoozed. Tonight is 18:00, then 22:00, then the next 18:00. The control is hidden when snooze is off.
- Undo (`mail:undoRemoval`) appears when archive, trash, or move returns `opIds`.
- The folder and message panes drag-resize. Each folder row has an icon. At about 1100×700 the three panes stay side by side.
- Translate sits in the reading pane: a short language list, Translate, and Cancel. Visible body paragraphs go to `mail:translateStart` as `{ node_id, text }` nodes. `mail:translate:event` fills the result under the original text. A missing AI key shows the host error. Cancel calls `mail:translateCancel`. AI Setup stays on the GenMail menu and edits the same local config as Settings.
- Compose calls `mail:listSignatures`. An empty list shows “No signatures.” A row is `{ id, name, text }` or `{ id, name, html }`, plus `accountId`. The picker inserts the account default (`defaultSignaturePerAccount`, otherwise `defaultSignatureId`) and can switch or clear it. The signature text is part of the message body. The Signatures dialog lists, adds, edits, and deletes those rows (`mail:upsertSignature`, `mail:deleteSignature`). It opens from Settings. New Mail has its own Signatures button, because compose covers Settings. Saving updates the picker that is already open. Name plus text, or name plus HTML, and an optional default for the selected account. Signatures are stored on this computer in `mail.sqlite`, one list per account. `defaultSignaturePerAccount` maps each account id to that default. They are not stored on the mail server. With no connected account the list is empty and a write asks you to connect one.
- Compose schedules a send for 1 hour, tonight, tomorrow morning, or a chosen date and time (`mail:scheduleSend` with the compose fields and `sendAt`). Tonight uses the same 18:00, then 22:00, then next 18:00 rule as snooze. The dialog lists `mail:listScheduled` (subject, recipient, time) and can cancel a row (`mail:cancelScheduled`). The queue is stored in `mail.sqlite`. GenMail sends it while the app is open. A time that passes while the app is closed is sent the next time the app is open. A failed send stays in the list with the error until you cancel it. Send, save draft, and schedule stay disabled until an account is connected.
- Reply and Forward on the open message use that same compose dialog. Reply fills To with the sender, Subject with `Re:`, and a quoted body. Reply All is always on the reading toolbar. It puts the sender in To and the other To and Cc addresses in Cc. New mail shows To, Cc, Bcc, and subject as one field stack above the body. Forward leaves To empty, sets Subject to `Fwd:`, quotes the message, and names attachments without uploading them. A subject that already starts with `Re:` or `Fwd:` / `Fw:` is not prefixed again. Save, send, and schedule still call `mail:upsertDraft`, `mail:send`, and `mail:scheduleSend`. On a live account, a reply also sends `inReplyTo` and `threadId` when the open message has them. Send and Save draft stay disabled until an account is connected.
- Compose drafts with AI (`aiDraftWrite:start`, `aiDraftWrite:cancel`, `aiDraftWrite:event`). Rewrite and Custom replace the body. Continue appends. The start body sends `mode`, `user_prompt`, `existing_draft_content`, and `subject`. Chunks stream into the message field. A missing AI key or other host error shows under the prompt. Cancel stops that request. The dialog stays open.
- The open message loads `aiDraftWrite:replySuggestions`. Each suggestion opens Reply with that text above the quote. A missing AI key shows on that row. The message still opens with no key.
- Updater, at the bottom of the folder column: the running version from `app:getVersion`, Check (`host:updateCheck`), and Install (`host:updateInstall`) when `host:updateGetState` reports a downloaded update. The same snapshot supplies the idle, checking, downloading, and error lines. An unpackaged build stays on the host stub (`enabled: false`). With no account, that column says to connect one.
- Settings edits theme (`config:setTheme`), accent (`genmail:configSetAccent`), conversation view (`genmail:configSetConversationViewEnabled`), remote images (`genmail:configSetAutoLoadRemoteImages`), undo send delay (`genmail:configSetUndoSendDelaySeconds`), and snooze (`genmail:configSetSnoozeEffective`). It also edits AI write on reply (`genmail:configSetAiWriteAutoOpenOnReply`), folder chips (`genmail:configSetShowFolderChips`), one-click tidy (`genmail:configSetShowOneClickTidy`), Gmail folders expanded (`genmail:configSetSidebarGmailFoldersExpanded`), and Outlook folders expanded (`genmail:configSetSidebarOutlookFoldersExpanded`). The matching getters return those stored values. The host keeps them in `settings.json`. The shell reads them again when Settings closes. Theme sets `data-theme` to light or dark, and accent sets `--accent` from the saved `#RRGGBB` value, including when the control changes. Remote images on shows `http` and `https` images from the message HTML. Off leaves them out until Load remote content on that message. That allow lasts for the session and is not saved. Undo send waits the saved 0–30 seconds before `mail:send`, and Undo send cancels that wait. Zero sends immediately. The host cannot recall a send after `mail:send` starts. Folder chips show Inbox, Sent, and Drafts above the message list when that preference is on, and hide when it is off. A Gmail or Outlook account heading expands or collapses that provider's folders from the two expanded preferences; other accounts stay open. Reply and Reply All open the compose AI write controls when AI write on reply is on. One-click tidy is saved with `genmail:configSetShowOneClickTidy`. `genmail:configGetShowOneClickTidyEffective` is false. The toolbar hides One-click tidy. `mail:tidyInbox` answers `accepted: false` and does not move mail. Live tidy rules are not in this build. The preference is still saved. Settings also edits the OpenAI-compatible base URL, model id, and API key. Fetch models fills a picker from `GET {baseUrl}/models`. Test connection uses the saved config. The key stays in local `ai.json` (and `GENMAIL_AI_*` overrides), not in `settings.json`. GenMail → AI Setup writes that same file.
- Email Brain opens from the leftmost rail, beside Calendar, as a full page with Profile, Categories, and Skills. The toolbar Brain button opens that same page and the mail shell is hidden. The folder column stays folders and labels on Mail. Opening it loads `emailBrain:getCached`, `emailBrain:getCategories`, `emailBrain:getSkills`, and `emailBrain:getLibrarySkills`. Profile shows persona meta when the host sends it (`ownerName`, `emailsAnalyzed`, `factsLearned`, `updatedAt`) and lists sections from `emailBrain:getCached`, including writing rules. Add calls `emailBrain:addWritingRule`. A user rule with an id can be edited (`emailBrain:setWritingRule`) or deleted (`emailBrain:deleteWritingRule`). A learned or auto row can be fixed (`emailBrain:fixItem`) or forgotten (`emailBrain:forgetItem`). Refresh calls `emailBrain:refresh` with source `manual`. Rebuild confirms, then calls `emailBrain:rebuild`. A fresh open calls refresh with source `open` and can return the cache. Voice sampling reads sent mail before inbox mail. User writing rules stay across both. Progress comes from `emailBrain:refreshState` and `emailBrain:rebuildState`. With no API key each returns `accepted: false` and the panel says it needs an AI key in GenMail → AI Setup. No mailbox or an empty cache shows the host error and does not use sample mail. The pane listens for `emailBrain:updated`, `emailBrain:refreshState`, and `emailBrain:rebuildState`. No IMAP account and no API key still show the cached sections and an empty writing list.
- Categories sit on that Brain page. The list shows id, name, description, and whether the row is collapsed. Add, edit, and delete stay in the pane until Save (`emailBrain:saveCategories`), which replaces the stored list. The panel says the list is unsaved until then. Open loads `emailBrain:getCategories` and shows the host defaults. Use defaults copies those into the list. Add with AI calls `emailBrain:addCategoryViaPrompt` and keeps the result local until Save. Fix calls `emailBrain:fixCategory` and also stays local until Save. With no API key those calls show the host error, and the list still saves. No IMAP account and no API key can still edit categories in the local store. The next Agent triage uses the saved categories.
- The Email Brain skills library sits on that Brain page. Home skills load from `emailBrain:getSkills` and library skills from `emailBrain:getLibrarySkills`. Each row shows its description and that it is on demand (`runMode: on_demand`, schedule disabled). Install calls `emailBrain:installSkill`. Remove calls `emailBrain:removeSkill` and puts the skill back in the library. Run calls `emailBrain:runSkill` and keeps the result in the panel: a summary, sections, and reviewable drafts. Nothing is sent. Organize Inbox returns proposals; Confirm calls `emailBrain:confirmProposal` and Dismiss calls `emailBrain:dismissProposal`. With no API key or no connected mailbox the call returns `accepted: false` and does not use sample mail. An empty list says there are no skills. A host error stays in the pane. See [BRAIN_AGENT.md](BRAIN_AGENT.md).
- Agent opens from the leftmost rail (Agent, Mail, Calendar, and Brain) or the toolbar Agent button and takes the primary space. Mail is folders, the message list, and the reader. Calendar and Email Brain are primary pages the same way. The Agent page leads with category todo stacks from `nativeAgent:home:todosCached` and `nativeAgent:triage`, then the transcript and composer (`nativeAgent:chat`, `nativeAgent:chatHistory`). The composer placeholder is Ask GenMail Agent. Manage Skills opens the Brain skills page. Saving categories calls `nativeAgent:home:refreshTaxonomy`. Done and Dismiss call `nativeAgent:home:todoUpdate` and do not archive or mark mail read. Turns are stored in `agent-chat.json`. Standing notes are `agent-memory.json` and are sent with a question. A question uses the cached inbox and calendar only, and does not invent messages. Naming a skill runs it. Triage runs from the button or from "Triage inbox". It files the inbox into the Brain categories (`nativeAgent:getTriage`, `nativeAgent:triage`), which start as Needs You, Upcoming Today, Worth a look, FYI, and Other. It lists home skills (`nativeAgent:home:skills`) and library skills (`nativeAgent:home:librarySkills`) and run history (`nativeAgent:history`). Needs an AI key, needs a mailbox, and an empty inbox cache are stated in the thread. Each triage row can open the message. Brief This Person uses the open message or an email typed in the panel. A history row reopens that run's summary, sections, and drafts in the thread. Follow-ups open compose or the message for review. Drafts are not sent. Auto-run is off. Refresh while this pane is open reloads the transcript, triage, and skills.
- Provider labels sit under the selected Google or Microsoft mailbox. `mail:listProviderFolders` calls Gmail or Graph when `gmail.modify` or `Mail.ReadWrite` was granted. Gmail nests a label when its name is `Parent/Child` and `Parent` is also in the list. Outlook nests a folder when `parentFolderId` points at another listed folder, and the host also asks Graph for child folders when `childFolderCount` is greater than zero. Create, rename, and delete call the same APIs. Rename keeps the full Gmail name, so `Work/Travel` is not saved as `Travel`. A new Outlook folder can be created at the top level or inside a listed folder. A new Gmail label accepts a slash in the name. The open message can add or remove a Gmail label (`mail:modifyMessageLabels`) or move an Outlook message (`mail:moveProviderMessage`) from the reading bar, and from a right-click menu on the message list or the reading pane. Dragging a message row onto a Gmail label adds that one label and does not remove the others. Dragging onto an Outlook folder moves that one message. The menu and the drag act on one message. Multi-select is a follow-up. Without the grant, the sidebar and the menu explain that and keep the IMAP folders. They do not add stand-in labels. IMAP folder move still works.
- Calendar is the rail button next to Mail. `calendar:status` reads whether the selected mailbox already has a calendar grant. `calendar:list` loads calendars and that month's events from Google Calendar or Graph after `calendar:connect`. The grid and agenda render those events only, with the start time and location. An all-day event covers each day from its start date up to the exclusive end. Today returns to the current month. Choosing an event shows that same title, time, and location. No mailbox, a non-Google or Microsoft account, a missing Google Desktop JSON, a missing grant, a provider error, and an empty month each say what is missing. `calendar:createEvent` writes one event, including a location when one was typed, and reloads the provider list. Refresh on this tab reloads the month.

- Settings, Brain, Signatures, Connect, and Compose scroll the dialog body. The dialog stays inside the window (`max-height: calc(100vh - 32px)`), so Save, the AI fields, and the other bottom controls can be reached on a short window.

## Deferred

- Unattended skill schedules. Skills stay on demand. Scheduled send of a message you queued is separate: it runs while the app is open, and it is not a skill.
- Host preferences still unread: `genmail:configGetDogfoodPrefs`, `genmail:configGetShowJevClassification`, `genmail:configGetShowJevSemanticSearch`, `genmail:configGetShowJevSemanticSearchEffective`, `genmail:configGetSidebarFolderOrder`, `genmail:configGetCalendarSidebarOrder`, `genmail:configGetAiWriteAgenticEnabled`, `genmail:configGetAiWriteV2Enabled`, `genmail:configGetAiWriteV2Effective`, `genmail:configGetCalendarGenTeamGroupChatEnabled`, `genmail:configGetCalendarGenTeamGroupChatEffective`.
- Still not the same pixels: no Gmail category row (All, Primary, Social, Promotions, Updates). Folder chips stay Inbox, Sent, and Drafts. Archive, trash, snooze, and move stay on the open message, not the top toolbar. No bulk selection (the organize menu and drag act on one message) or date-group headers. Multi-select stays a follow-up. The rail is Agent, Mail, Calendar, and Brain. Agent, Calendar, and Brain each replace the mail shell. Folder marks are emoji. Settings is a wider two-column dialog for preferences, AI, and mailbox actions, not GenMail's full settings page. The folder column is folders and labels, and it shows on Mail.
