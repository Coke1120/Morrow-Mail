# Shell parity

First-party `renderer/` chrome for the three-pane mail shell. Layout follows the host IPC already in this repo. The look follows the Morrow Mail logo: forest-green rail and canvas (`#102822` / `#193c34`), white floating list and reading cards. An external `app.asar` is not vendored and was not required to boot.

## Look

- Light theme uses the logo green tokens: rail `#102822`, canvas `#193c34`, white cards with a 16px radius and a soft shadow, a 56px toolbar, a 260px folder column, and 32px folder rows. Unread counts are a `#b9d5ad` pill. The default accent is `#193C34`. Focus and unread text use `--accent-ink`, which is that same green in the light theme and the logo leaf `#b9d5ad` in the dark theme. Stars use `--star` (`#e2a100` in light, `#f6c445` in dark) and stay that gold when the accent changes.
- Comfortable message rows are 60px: an initial avatar, the sender, the subject with the date on that line, and one snippet line. Unread rows are heavier and show an accent dot. The open row uses the selected wash. Settings → Mail & Sync can switch to Compact message list: 32px rows with sender, subject, and date on one line, without the avatar or snippet. It retains stars, unread markers, selection, row actions, keyboard navigation, and paging. The `compactMessageList` boolean in `settings.json` defaults to false; `morrow:configGetCompactMessageList` / `morrow:configSetCompactMessageList` read and write it.
- The toolbar is a white New Mail pill, light action labels, and a translucent search field. Sync feedback is compact beside Sync and success collapses after five seconds. Version and update controls live in About & updates, opened beneath Debug log in the rail.
- An empty reading pane shows an envelope and “No conversation selected”.
- Settings, Brain, Studio, Compose, Connect, and Signatures share that font, paper surface, 16px radius, and accent primary buttons.
- `data-theme="dark"` switches the canvas to `#141414` and the cards to `#1f1f1f`. The rail stays a darker forest `#0c1c19`. The saved accent sets `--accent` on fills (unread dot, avatars, dialog primary buttons). Unread text and focus use `--accent-ink`. Stars stay on `--star`. A custom accent replaces the accent tokens. The default logo green leaves those tokens to the stylesheet so the dark theme can use the leaf.
- Motion fades the first screen of message rows, the mail, calendar, and agent panels, and open dialogs. New Mail, the rail, and dialog primary buttons scale slightly on hover and press. `prefers-reduced-motion: reduce` skips that motion. Rows stay at the chosen comfortable or compact height. Settings tab panels, and the Agent, Calendar, and Brain sections, use that same motion.

`shortcut: accent does not reskin the rail or canvas, upgrade when a skin map is worth it.`

## Matched

- Email Brain Profile → Compose defaults and aliases configures local CC and BCC lists by domain, mailbox aliases and optional alias-to-domain mappings, preferred From, and a new-mail fallback CC domain. The fallback selects only the CC list. BCC and signatures use the alias domain when the alias sets one, and otherwise the host of From. Compose has a From picker. Reply, Reply All, and Forward select an owned received alias before primary Gmail delivery hops. CC and BCC seed on open and on From changes until you edit that field. The two fields lock separately. Resumed drafts retain From and the saved recipients, including empty CC and empty BCC. Save, send, and schedule carry the selected From. See [BRAIN_AGENT.md](BRAIN_AGENT.md#compose-defaults-and-aliases) for recipient precedence and provider limits.

- Folder sidebar from each account's `folders.primary` then `folders.more` (Inbox, Sent, Drafts, Starred, Unread, and any other folder the host returns). Starred sits with Inbox, Sent, and Drafts and lists messages whose IMAP `\Flagged` flag is set. It is not a mailbox and not a folder chip. Unread sits next to Starred and is a downloaded-mail filter, not a mailbox. A non-zero `unreadCount` is shown on the folder row. A folder that contains other folders shows a disclosure caret. The caret's accessible name is Collapse or Expand plus the folder name, and it sets `aria-expanded`. Activating the caret hides or shows that folder's descendants. Choosing the folder name still opens it, and the row keeps that folder's own unread badge. Collapsed folder ids are stored per account in `settings.json` as `sidebarCollapsedFolders` (`morrow:configGetSidebarCollapsedFolders`, `morrow:configSetSidebarCollapsedFolders`). A filter under Scheduled and Out of Office matches folder and label display names in every account. A match stays visible with its ancestor folders. Clearing the field, including with Escape, restores the full tree. The folder list scrolls vertically. Nested indents, unread badges, and disclosure carets stay inside the column, and the list does not scroll horizontally. On a Gmail mailbox, All Mail is the IMAP `\All` mailbox, usually `[Gmail]/All Mail` or `[Google Mail]/All Mail`, and it is listed above Inbox. Choosing it lists that mailbox. Gmail All Mail contains everything except Trash and Spam. A non-Gmail account lists All Mail only when the server already advertises the `\All` special-use mailbox. The Unread row uses that count for the filter. All Account Mail sits above the account rows when at least one mailbox is connected, and it is hidden when none are. It lists downloaded Inbox messages from every account, newest first, and it is not an IMAP folder. An Unread chip on that row uses the same green count pill as folder badges and filters this view to unread Inbox messages. The chip shows the sum of those Inbox unread counts when the sum is above zero, and it still says Unread at zero. Choosing an account folder leaves All Account Mail and clears that filter. The per-account Unread row stays a downloaded-mail filter for that mailbox. Right-click an account row and choose Rename to store a list label on that mailbox (`mail:setAccountLabel`). Clearing the name uses the provider name, or the address when the provider has none. The address, sign-in, and From header stay the same.
- Message list: sender, subject, date, snippet. Previous and Next use `offset` to browse all cached messages, including Starred, in pages of 200. A count shows the displayed range and downloaded total. Sync more continues incomplete history without changing pages. Folder/search changes reset the page; background refreshes keep it, and a removed last page falls back to the last available page. The host defaults to at most 2,000 rows per query. The open row sets `aria-current`. Unread rows are bold, with a dot. ↑ and ↓ move a cursor; Enter opens that row (a focused row uses the button's own click). A message row uses the pointer cursor. The grabbing cursor shows only while that row is being dragged. Hover and keyboard focus show icon buttons labeled Star or Unstar (`mail:toggleStar`), Mark read or Mark unread (`mail:markRead`), Reply, Reply All, Forward, and Delete (`mail:delete` for that message). Star uses the same optimistic flag path as the reading pane. Reply, Reply All, and Forward use the open message or `mail:openEmail`, then the compose dialog.
- Multi-select: Shift-click and Cmd or Ctrl-click select rows in the loaded list and do not start a drag. A checkbox shows on hover and on a selected row, and every loaded row keeps its checkbox visible while any selection is active. A plain click opens that message and clears the list selection, so the checkboxes and the selection bar stay hidden. Cmd, Ctrl, Shift, and the row checkbox still select. Select all, and Cmd or Ctrl+A, choose the visible filtered rows only and do not call `mail:search`. Escape clears the selection. The selection bar and the right-click menu mark read or unread (`mail:markReadBatch`), star (`mail:toggleStarBatch`), archive, trash, move, edit Gmail labels, and clear the selection. Gmail label edits use one Labels dialog: a filter, checkboxes for the labels already on the messages, and Apply sends `addLabelIds` and `removeLabelIds` together. A label on only some of the selected messages starts mixed and stays unchanged until it is checked or cleared. Archive, trash, and move ask in the confirm dialog and name the count. Cancel sends no provider call. Removing a Gmail label asks only when that label is the open folder, because those messages leave the list. Adding a label does not ask. Undo appears when the host returns `opIds`. A rate limit pauses the rest of the batch. A selected row is that message. Archive and trash use `mail:threadArchive` or `mail:threadTrash` when conversation view is on and that thread already has another loaded message, the same rule as the reading pane. Otherwise one message uses `mail:archive` or `mail:delete`, and several use `mail:archiveBatch` or `mail:deleteBatch`. Move uses `mail:moveToFolder` for one message and the same channel with `items` for several. Dragging a selected row onto a sidebar folder or label applies that action to every selected message. A move still confirms. A drag that starts on a row outside the selection still moves that one message.
- Reading pane: subject, from, date, To and Cc when the message has them, then the body. Empty state when nothing is open. The mail reader still calls `mail:markRead` for an unread message. Agent peek does not. The reading toolbar is icon buttons for Reply, Reply All, Suggest, Forward, Star, Archive, and Trash. Reply All is always shown. Suggest sits beside Reply All and is the only control that starts reply suggestions. Opening or selecting a message does not. Move stays its own action. Snooze stays a menu on that bar. Translate sits beside Star. Gmail Labels is one button for the checkbox dialog, including from Organize and the message right-click menu. Outlook does not get that dialog; it keeps Move in Outlook.
- Toolbar actions: Sync (`mail:listFromNetwork`) and New Mail (`mail:upsertDraft`, `mail:send`). Sync names the account, folder, and phase, plus the last success or the last error, and the button stays on Syncing while that work is in progress. Use Brain → Organize Inbox to file the inbox. Signatures, Connect account (`mail:connectImapSmtp`, `mail:addAccount`), and Remove account (`mail:removeAccount`) sit in Settings. Settings is the last button on the app sidebar, under Log. That sidebar stays on the left, including when the window is narrow, and it collapses to icons. A collapsed icon shows its title on hover and on keyboard focus. When the sidebar is expanded, Morrow Mail sits beside the logo. Collapsed, the rail shows the icon, and the name stays on the hover title. Debug log is its own page (`host:getDebugLog`) and drops passwords, tokens, and API keys.
- Search: the toolbar box submits `mail:searchLocal` with the query and a limit of 100. That reads the local full-text index of synced mail in `mail.sqlite`. The index stores subject, from, and body. Body is the downloaded plain text, otherwise the downloaded HTML with tags removed, otherwise the stored snippet. The indexed body is capped at 200,000 characters. A query word matches that token or a longer token that starts with it, and every word must match. At most 16 words are used. Results replace the message list, with subject and from ranked ahead of body, then by date. Sync, a downloaded body, a saved draft, and a deleted message update that index in the same write. Clearing the box, or choosing a folder, loads that folder again. Choosing a folder syncs its Settings → Mail & Sync horizon (180 days by default, 365 days, or All) and clears the list filter. The filter above the list matches subject, from, and snippet of messages already loaded. It does not call `mail:search`. It does not read the local index. `mail:search` still searches mail on the server and does not read this index. Background sync stays on inbox and the active folder. A folder that finished a shorter window catches up to the selected horizon on its next sync. Shortening the horizon keeps mail already stored. All removes the date bound for folders as they are synced; it does not start syncing every folder at once. A rate limit pauses that account. Download batches and per-tick time limits still apply. A full history takes longer and uses more disk and host snapshot work.
- IMAP push: an account whose server advertises IDLE keeps one extra IMAP connection on Inbox. EXISTS, EXPUNGE, and FETCH notifications run the same incremental folder sync, debounced. The IDLE command is sent again about every 25 minutes. A dropped connection waits on exponential backoff, capped at a few minutes. A rate limit pauses that account and drops this connection until the pause ends. Quit and system sleep close it. Wake and coming back online open it again. Removing the account closes it. With no IDLE capability, or while the connection is down, background sync stays on the 45 second poll. While push is up, that poll still runs as a safety net on a longer interval, for Inbox and the open folder. Settings lists each mailbox as Push: on or Push: polling from that live state. Gmail labels and Outlook mail folders still use their own APIs.
- Conversation: when conversation view is on, the reader uses `threadMessages` from `mail:openEmail` when the host sends any. If that list is empty and the message has `threadId`, it calls `mail:listThreadMessages`. Two or more members are listed; the message you opened stays the body. When conversation view is off, the reader shows that message alone and does not call `mail:listThreadMessages`.
- Attachments: the reader keeps `attachments` from the open message in a card above the body (name and size). Save calls `mail:downloadAttachment`. Open calls `mail:openAttachmentExternally`. Save as ZIP calls `mail:downloadAttachmentsZip` and writes one `.zip`. Images and PDFs open an in-app preview from `mail:fetchAttachmentBytes`; other types keep Save and Open. A message that only sets `hasAttachments` shows that fact in the card with no buttons.
- Star on the open message (`mail:toggleStar`) and on a multi-selection (`mail:toggleStarBatch`). The button is an outline until the message is starred, then a filled gold star. The list row shows that same gold star. A rejected flag change is named in the status line and the previous star state returns.
- Archive and Trash. One message uses `mail:archive` or `mail:delete`. A conversation uses `mail:threadArchive` or `mail:threadTrash`.
- Move (`mail:moveToFolder`) picks a folder from the open message's account. IMAP folders indent when one path sits inside another that is already listed. Right-click the message list or the reading pane, or use Organize on the reading bar, for Move to folder. That picker is a filterable tree. Dragging a message row onto a sidebar folder moves that one message. The drag preview is a small translucent chip offset below the pointer so the folder name stays readable. The reading pane still has the Move menu.
- Snooze presets are 1 hour, tonight, and tomorrow morning (`mail:snoozeThread`). Unsnooze (`mail:unsnoozeThread`) shows when `mail:listSnoozed` says that thread is snoozed. Tonight is 18:00, then 22:00, then the next 18:00. The control is hidden when snooze is off.
- Undo (`mail:undoRemoval`) appears when archive, trash, or move returns `opIds`. The status line stays readable for a few seconds, then collapses to a bottom-right chip. Errors stay longer and keep an error-colored chip. Click the chip, press Escape, or press outside the notice to show or hide the line. Undo, Undo send, and Undo cancel stay on the chip.
- The folder and message panes drag-resize. Each folder row has an icon. At about 1100×700 the three panes stay side by side. The last folder, list, and reading widths are `layoutPanes` in `settings.json` (`morrow:configSetLayoutPanes`). A relaunch restores the main window size, position, and zoom from `window-state.json`. A first launch is 1200×800 at zoom level 0, with folder 260 and list 360. Cmd/Ctrl++ , Cmd/Ctrl+− , and Cmd/Ctrl+0 change zoom and the next launch keeps it.
- Translate sits beside Star on the reading toolbar: a short language list, Translate, and Cancel. Visible body paragraphs go to `mail:translateStart` as `{ node_id, text }` nodes. The translated text still appears in the reading pane. `mail:translate:event` fills the result under the original text. A missing AI key shows the host error. Cancel calls `mail:translateCancel`. AI Setup stays on the Morrow Mail menu and edits the same local config as Settings.
- Compose calls `mail:listSignatures`. An empty list shows “No signatures.” A row is `{ id, name, text }` or `{ id, name, html }`, plus `accountId`. The picker inserts the signature for the alias domain when the alias sets one, and otherwise the host of From, then the account default (`defaultSignaturePerAccount`, otherwise `defaultSignatureId`), and can switch or clear it. The signature text is part of the message body. An HTML signature keeps its text color and highlight when compose inserts it. The Signatures dialog lists, adds, edits, and deletes those rows (`mail:upsertSignature`, `mail:deleteSignature`). It opens from Settings. New Mail has its own Signatures button, because compose covers Settings. Saving updates the picker that is already open. Opening the dialog checks HTML. The signature field uses the compose formatting bar, including text color, highlight, and paste. Name plus text, or name plus HTML, and an optional default for the selected account, and optional domains. Under the account-default checkbox, Domains takes exact domains separated by commas, semicolons, or spaces. A leading @ is optional. A subdomain does not match. The host stores those rows in `mail.sqlite` table `signature_domains`, keyed by account and domain. A bound id that is missing from the signature list uses the account default too. Saving a domain that another signature on the same account already uses fails, and the previous rows stay. An empty Domains field clears that signature's rows. Changing From between a Gmail address and an alias swaps the signature while the body still ends with the previous one. A body that no longer ends with that signature is left as written. Choosing No signature removes it from the body, and the next From change leaves the body alone. Opening a draft does not append a signature when From changes. Signatures are stored on this computer in `mail.sqlite`, one list per account. `defaultSignaturePerAccount` maps each account id to that default. They are not stored on the mail server. With no connected account the list is empty and a write asks you to connect one.
- Compose schedules a send for 1 hour, tonight, tomorrow morning, or a chosen date and time (`mail:scheduleSend` with the compose fields and `sendAt`). Tonight uses the same 18:00, then 22:00, then next 18:00 rule as snooze. The dialog lists `mail:listScheduled` (subject, recipient, time) for every account, whichever mailbox is selected, and can cancel a row (`mail:cancelScheduled`). Cancel asks twice. Undo then calls `mail:restoreScheduled` for about 8 seconds and puts that row back, including a failed row. The queue is stored in `mail.sqlite`. Morrow Mail sends it while the app is open. A time that passes while the app is closed is sent the next time the app is open. A failed send stays in the list with the error until you cancel it. Send and Schedule send open a preview of recipients, subject, body, and the schedule time when there is one. Confirm commits. Cancel returns to the editor and does not call `mail:send` or `mail:scheduleSend`. Settings `defaultScheduleDelayMinutes` makes Send schedule that many minutes ahead when it is above zero. Send now still sends immediately. Send, save draft, and schedule stay disabled until an account is connected.
- Reply and Forward on the open message use that same compose dialog. Reply fills To with the sender, Subject with `Re:`, and a quoted body. Reply All is always on the reading toolbar. It puts the sender in To and the other To and Cc addresses in Cc. New mail shows To, Cc, Bcc, and subject as one field stack above the body. Forward leaves To empty, sets Subject to `Fwd:`, quotes the message, and names attachments without uploading them. Compose can attach new files on a new message, reply, or forward. Attach files accepts several files, lists each name and size, and can remove one before send. Dropping files on the message field attaches them the same way. A drag that is not files is ignored. Save draft, Send, and Schedule send include those files. `mail:uploadAttachment` stores each file on this computer, and the message keeps that `local:` id. A file over 25 MB, files that together pass 25 MB, and an empty file are refused with the provider limit. Preview names the files before confirm. A saved draft and an edited scheduled send keep the files. Forward still does not copy the original files. A subject that already starts with `Re:` or `Fwd:` / `Fw:` is not prefixed again. Save, send, and schedule still call `mail:upsertDraft`, `mail:send`, and `mail:scheduleSend`. On a live account, a reply also sends `inReplyTo` and `threadId` when the open message has them. Send and Save draft stay disabled until an account is connected. The quoted original is the open message, rendered with the same text and remote-image rules as the reading pane. When the compose dialog is at least 900px wide, that quote sits on the left and the draft on the right. A narrower dialog stacks the quote on top and the draft below, and the quote can collapse. The quoting dialog grows with the draft and the quoted original, up to the window. Quote text scrolls inside it. Collapse hides the quote body so it does not paint over the mail behind the dialog. Reply and Reply All show the quote. Forward keeps it hidden until Show quoted message. Hide quoted message only hides the pane. The quote is still part of the body that save, send, and schedule submit. Close and the dialog cancel do not call `mail:send`. The compose dialog is about 85% of the window width. Close discards unsaved edits after a confirm and does not call `mail:upsertDraft`. Save draft remains the separate control that writes the draft and leaves compose open. The message field is an HTML editor (Bold, Italic, Underline, lists, text color, highlight, and paste HTML) and the sent body is that HTML plus the quoted original. The wide divider remembers its width in `settings.json` through `morrow:configSetComposeQuoteWidth` (220 to 720, default 420). A wide reading pane uses that split when the compose width is not known yet and the window can hold it.
- Compose drafts with AI (`aiDraftWrite:start`, `aiDraftWrite:cancel`, `aiDraftWrite:event`). A sparkle button in the formatting toolbar opens a popover with Rewrite, Continue, Custom, and Reply from thread. Rewrite and Custom replace the body. Continue appends. Reply from thread replaces the draft with a comprehensive reply that uses the original message subject, from, and body, and it stays disabled when that message is missing. An empty prompt in that mode still asks for a full reply; a prompt steers it. The signature already on the draft stays. The start body sends `mode`, `user_prompt`, `existing_draft_content`, and `subject`. Chunks stream into the message field. A missing AI key or other host error shows under the prompt. Cancel stays visible, stops that request, and closes the popover. Escape closes the popover. The dialog stays open. Send later stays its own control. Reply and Reply All also request `aiDraftWrite:replySuggestions` and show those lines as chips in the draft. Choosing one fills the reply above the signature and leaves AI write open when that preference is on. The same Settings and AI Setup key is used. There is no separate key store.
- Suggest, beside Reply All, loads `aiDraftWrite:replySuggestions`. Opening or selecting a message does not. Each suggestion opens Reply with that text in the draft, and the saved message still places that text above the quote. A missing AI key shows on that row. The message still opens with no key. An empty result says there are no reply suggestions.
- About & updates, beneath Debug log in the app sidebar: a short description of the Electron client, the running version from `app:getVersion`, Check (`host:updateCheck`), and Install (`host:updateInstall`) when `host:updateGetState` reports a downloaded update. The same snapshot supplies the idle, checking, downloading, and error lines. An unpackaged build stays on the host stub (`enabled: false`).
- Settings edits theme (`config:setTheme`), accent (`morrow:configSetAccent`), conversation view (`morrow:configSetConversationViewEnabled`), remote images (`morrow:configSetAutoLoadRemoteImages`), undo send delay (`morrow:configSetUndoSendDelaySeconds`), default schedule delay (`morrow:configSetDefaultScheduleDelayMinutes`, hours and minutes, 0 to 10080, stored as `defaultScheduleDelayMinutes`), and snooze (`morrow:configSetSnoozeEffective`). It also edits AI write on reply (`morrow:configSetAiWriteAutoOpenOnReply`), folder chips (`morrow:configSetShowFolderChips`), Gmail folders expanded (`morrow:configSetSidebarGmailFoldersExpanded`), and Outlook folders expanded (`morrow:configSetSidebarOutlookFoldersExpanded`). Theme sets `data-theme` to light or dark, and accent sets `--accent` from the saved `#RRGGBB` value, including when the control changes. Remote images on shows `http` and `https` images from the message HTML. Off leaves them out until Load remote content on that message. HTML in the reading pane keeps table layout and safe colors; plain-text line breaks stay on plain-text bodies only. That allow lasts for the session and is not saved. Undo send waits the saved 0–30 seconds before `mail:send`, and Undo send cancels that wait. Zero sends immediately. The host cannot recall a send after `mail:send` starts. Folder chips show Inbox, Sent, Drafts, and Unread above the message list when that preference is on, and hide when it is off. A Gmail or Outlook account heading expands or collapses that provider's folders from the two expanded preferences; other accounts stay open. Reply and Reply All open the compose AI write controls when AI write on reply is on. That preference defaults to on. Use Brain → Organize Inbox to file the inbox. Inbox rules opens the Brain Rules tab. Settings also edits the OpenAI-compatible base URL, model id, and API key. Fetch models fills a picker from `GET {baseUrl}/models`. Test connection and Fetch models use the values in this form; a blank API key uses the saved key. The key stays in local `ai.json` (and `MORROW_AI_*` overrides), not in `settings.json`. Morrow Mail → AI Setup writes that same file. Settings has General, Mail & Sync, Accounts, AI, Out of Office, and Bot access tabs, with one visible panel. General opens first; subsequent opens remember the selected tab for this renderer session. The tablist uses roving focus, Arrow Left/Right, Home, and End. Tab enters the active panel. AI/provider/Bot reads remain lazy and coalesced. The mailbox selector is visible for Accounts and Out of Office. Panels keep their existing motion.dev transition and reduced-motion behavior. Sync history uses `morrow:configGetSyncHorizonDays` / `morrow:configSetSyncHorizonDays`, persisted in `settings.json` as `syncHorizonDays` (180, 365, or 0 for unlimited). Each host sync captures this value once; completed folders record it in `sync_horizon_days` (NULL means unknown).
- Email Brain opens from the leftmost rail, beside Calendar, as a full page with Profile, Categories, Skills, and Rules. Rules lists inbox rules for the selected account (`mail:listInboxRules`). A rule does not forward mail. The toolbar Brain button opens that same page and the mail shell is hidden. The folder column stays folders and labels on Mail.
