# MOVE response identity and calendar PATCH presence

A destination UID and UIDVALIDITY are a pair supplied by the same COPYUID response to MOVE. Use both values from ImapFlow's result. A later STATUS describes the mailbox at a different instant and cannot provide a replacement generation for that UID. Missing or invalid response identity leaves the move unknown, without an Undo ticket or automatic replay. A later write or read still checks the cached response generation against its selected mailbox, so destination recreation causes a recoverable refusal.

Calendar updates preserve absent fields. The editor remembers the original description and location and omits those fields when unchanged. An unchanged Outlook body preview is display data, not a replacement for the full body. `writeEvent` and both provider serializers retain field presence: absent description/location leaves the remote value alone; an explicit empty location clears it, including all-day events.

An intentional Outlook description replacement includes the editor's original description for comparison. Before writing, fetch the full event and require that its complete plain-text projection matches that baseline, fits the 8,000-character editor, and is not an online meeting. Also require its ETag and send If-Match, converting HTTP 412 to a refresh/review conflict. Missing body/revision, partial previews, changed bodies and online meetings are refused before PATCH, with instructions to edit the description in Outlook or leave it unchanged when saving other fields. This conservative path avoids guessing how to rewrite a meeting blob or the unseen remainder of a preview. New event creation and ordinary complete descriptions retain their existing editing flow. An interrupted body replacement is not automatically retried; a repeated request must pass the fresh body comparison again.

The regression suite `scripts/check-move-calendar-patches.js` exercises real engine/SQLite and provider serialization with fake IMAP/Graph/Google servers. It covers response generation changes, missing identities, repeated deletion/Undo, restart without replay, absent versus cleared fields, timed/all-day location clearing, preserved long/HTML/meeting content, read/write failures, concurrent revisions and lost responses. Renderer VM and native Electron navigation fixtures verify dirty-field omission before IPC. No provider credentials or real account data are used.
