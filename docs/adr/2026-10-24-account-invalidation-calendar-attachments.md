# Account invalidation, complete calendar baselines and attachment identity

Disconnect invalidates the account's in-process generation before removing its credentials and cache. Sync/search work carries that generation across awaits; queued jobs and delayed replies cannot commit into a removed or reconnected account, including a reused ID. Cache insertions require a connected account, invalidated actions cannot restore removed data, and search/AI-context queries exclude legacy orphan rows. Other accounts retain their data. Existing orphan bytes are not automatically purged by this change.

Google descriptions exceeding the editor's 8,000-character limit are marked as incomplete read-only previews. Other fields can still be saved while omitting the description. Changed descriptions require a matching complete baseline and ETag, for Google as well as Outlook; conditional PATCH rejects concurrent changes and uncertain retries. Oversized writes are refused instead of silently truncated. Google conditional modification behavior follows its [resource version guide](https://developers.google.com/workspace/calendar/api/guides/version-resources).

Individual and ZIP downloads share one byte resolver. An explicit attachment ID must identify exactly one current file; a stale ID never chooses another attachment. Legacy callers may omit the ID to select the default. Local blobs resolve without IMAP, including UID-0 messages. Mixed archives fetch only remote parts under one guarded connection, checking the message/attachment snapshot before and after awaited work. Missing blobs or selected IDs, read failures and changed snapshots refuse the whole download instead of silently saving different or incomplete files.

Synthetic regression coverage uses temporary SQLite, fake providers and fake file dialogs. It exercises removal during listing/search/fetch/refresh, same-ID reconnect, queued and in-flight actions, restart and legacy orphans; complete/truncated/concurrent calendar updates; and local/remote/mixed archives, stale IDs, read failures, metadata races and disconnect during a part read. Native Electron fixtures verify the incomplete-description UI and safe title-only save. No real account or provider data is used.
