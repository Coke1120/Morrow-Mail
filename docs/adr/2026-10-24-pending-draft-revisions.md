# Pending draft revisions and submitted-source cleanup

Saving a local edit marks it as pending before any I/O and gives it a distinct RFC Message-ID. Pending content is protected from sync overwrite, pruning, body fetch and UIDVALIDITY reset; a reset only forgets its obsolete server UID. A confirmed replacement APPEND is durably recorded before retiring the old UID, whose validity is still checked under the mailbox lock. Missing replacement identity or a failed retirement retains the older copy. Interrupted or superseded uploads may leave separate copies, rather than risking the only newer content. Retry requires an explicit Save draft; drafts never send automatically.

Compose carries a hash of the saved draft content/identity as its source revision. A stale save is refused without replacing the stored revision. Queued and direct submissions carry that revision too. Delivery cleanup checks account and revision again under the mailbox lane, before remote removal and after awaited I/O. A newer local save is retained. Legacy queued payloads without revision evidence retain their source draft instead of guessing. Accepted scheduled sends with a retained-source/cleanup warning remain nonqueued review records so the outcome is visible. Sync-only UID/flag changes do not invalidate the content revision.

Undo send closes compose when the message is queued into Outbox ([Compose closes into Outbox](2026-10-28-compose-outbox-undo.md)). A partial SMTP result still reopens the read-only receipt. A compose-session generation binds asynchronous results to their originating surface. If a newer composition exists, its fields and pending state stay untouched; the old partial receipt opens in a separate compose window, or an independent read-only dialog for older/modal preloads. Accepted recipients remain excluded from explicit partial recovery as before.

Temporary SQLite, crash/restart processes, fake transports and renderer/native Electron fixtures cover upload failures, stale server data, reset, concurrent saves, replacement ordering, confirmed and legacy delivery cleanup, edits during deletion, delayed receipts and stale compose results. No real provider data is used.
