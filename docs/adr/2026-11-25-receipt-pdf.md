# Export a single Reader message as a receipt PDF

File → Save message as PDF… applies to the focused standalone Reader. The host binds the registered window and its main document to the seeded message and to the account epoch from the original successful open. A fixed query returns the message identity and the HTML or plain-text presentation from first-party Reader state. The host reads the complete message through the local cached-body API and uses the selected variant. The preview requires readable text in that variant. The host revalidates identity, presentation and receipt content before showing the preview, before asking for a destination, and after the dialog returns.

Two isolated in-memory sessions handle printing and preview. The print window disables JavaScript and loads only host-generated markup. The document keeps readable body text, headings and table structure within explicit size limits. It omits images and active content. The stored address and timestamp appear in the header. Retained numeric offsets are shown explicitly, and normalized timestamps use UTC.

The preview uses the bundled PDF.js renderer and a dedicated sandboxed preload. The host retains the generated bytes until the preview closes. Saving commits those same bytes to the path chosen in the native dialog. Navigation or closure invalidates the source document, and cancelling the dialog leaves the preview available for another attempt.
