# Corrected drafts from delivery status notifications

Issue #646 adds a manual review in the Inbox reader. Only a top-level `multipart/report` with `report-type=delivery-status` supplies correlation evidence. The host requires one recipient block with `Action: failed` and exact `Status: 5.1.1`, a single `rfc822` recipient, and one syntactically valid Message-ID in the returned original headers. If both recipient fields are supplied, they must agree. The report must be addressed to the mailbox or the original still-configured From address. Diagnostic text and the returned message body are display material only. Read receipts use a separate report type. [Delivery status format](https://www.rfc-editor.org/rfc/rfc3464) · [Enhanced status codes](https://www.rfc-editor.org/rfc/rfc3463)

IMAP source parsing and Gmail normalization record nullable evidence on existing message rows. Gmail reads bounded raw MIME for a recognized Inbox report. The ordinary body-fetch path can complete IMAP report evidence after a capped preview. The original must be the unique matching cached Sent delivery under the same account, with a verified time, From identity, complete decoded body, and empty attachment list. Parsed MIME recipient addresses provide the match independently of cached display names. A newly filed local Sent copy uses the SMTP acceptance result for its address evidence. The match is scoped to Sent. Copies in other folders and accounts do not participate, and two Sent rows with the same ID require manual review. A single structured temporary delivery status asks the user to wait, even when the notification omits returned original headers. Legacy rows can gain evidence on a fresh download. Delivery reports outside these checks require manual review.

The renderer receives a read-only review and a host-generated proof tied to the Reader owner, account generation, report, Sent original, and reviewed content. The save handler rechecks these sources and accepts one explicit, valid, different To address after the directory confirmation. It commits through the existing local Drafts store with the original sender name, subject, plain body and any verified HTML alternative. The Reader review and reopened Compose use the existing mail HTML sanitizer with remote images disabled. An HTML-only original also gets a plain-text fallback. Recipient lists, attachments, reply threading, and transport receipts stay outside the draft. A deterministic draft ID keeps retries and simultaneous Reader windows on the same existing draft, including after restart. The existing Resume draft path handles further manual editing.

`scripts/check-dsn-redraft.js` exercises synthetic MIME through production ingestion, native temporary SQLite, and the actual preload and Reader and Features DOM. It covers malformed and delayed reports, mailbox and recipient mismatches, ambiguous Sent rows, partial source downloads, missing aliases, live cache changes during review, attachment exclusion, local persistence, and duplicate submission.
