# Local links to a single message

A saved note or calendar event can point back to the exact mail that supports it. The destination only needs an opaque link. Keep the subject, sender and message body inside Morrow, and leave any link in the message for the reader to open separately. A subject search can return a different message, and an external provider URL needs a different account and access path. [Issue #653](https://github.com/Coke1120/Morrow-Mail/issues/653)

## Link identity and lifetime

Use `morrow-message://open/v1/<token>`. The token is canonical base64url for an AES-256-GCM envelope containing a fresh nonce, authentication tag and encrypted account ID, message ID and identity digest. The host keeps a 32-byte key in `local-message-link.key` beside the mailbox database and authenticates the canonical profile directory as part of the envelope. A link survives a restart in that profile while the key and proof still match. Copying the database and key to a different profile path does not carry the link over. The parser accepts only the versioned URL shape and a bounded token. [Codec](../../host/local-message-link.js)

The host recalculates the identity from the local store when it opens the link and again when the Reader asks for the body. For connected mail, the digest binds the account incarnation and message to the cached folder path, UID and UIDVALIDITY. IMAP checks the folder's current local UIDVALIDITY. Gmail API checks the local account generation and UID mapping, as well as current label membership outside All Mail. The host requires a complete cached body without a body warning and denies recorded authentication errors, excluded folders or drafts, and unresolved actions that make the identity uncertain. For Local Folders, the digest binds the verified archive message to its folder ID and body, and the host excludes Trash. Deleted or changed sources, a missing key, and malformed tokens leave the message closed. These checks use the latest locally known state. A server change the local store has yet to observe is outside their scope. [Host source proof](../../host/mail/engine.js) · [Context action identity](2026-11-06-message-context-actions.md)

## Copy and open boundaries

The bundled preload permits `reader:copyLocalMessageLink` through its existing invoke allowlist. In the first-party shell, the host checks the main frame and binds `{ accountId, messageId, bodyEpoch }` to the current Reader open. Reads made for other actions cannot replace that binding, and clearing the Reader retires it. In a detached Reader, the host requires a visible, unminimized window and matches the tuple and main frame to the current document's first open of the seeded message. It verifies the current cached source and epoch again before minting. Linked Readers also check the epoch when reading the cached body. The epoch stays outside the restart-stable link proof. The host writes the URL to the clipboard, and the IPC success response contains only `{ ok: true }`. [Preload](../../renderer/preload.js) · [Reader frame binding](../../host/reader-window.js) · [Host handler](../../host/main.js)

The macOS package declares the scheme, and the host listens early for `open-url`. The host also checks initial launch arguments and parameters from later invocations through `second-instance`. On packaged Windows, Copy checks or registers the protocol before writing the link. The portable case accepts an association to its outer executable or registers that executable if the scheme has no handler. An existing different handler is preserved and Copy reports failure before writing to the clipboard. A valid URL opens the exact cached message in a detached first-party Reader without marking it read, refreshing provider folders or opening an embedded web link. The host rejects an unavailable reference with a generic notice without reopening the shell or looking for same-subject mail. ## Integration

The Reader command uses the existing toolbar and feedback, and Features describes the same-profile and availability limits. Opening a URL with an explicitly selected development bundle checks native delivery to the host. Verify default handler resolution and packaged cold and warm opens separately. The Notes and Calendar cases exercise a saved link after quitting Morrow, distinguish same-subject mail and test deletion and profile switching. The paired timing test includes setup and retrieval and uses the fastest eligible baseline for each case. Windows installation and portable association also need platform verification.
