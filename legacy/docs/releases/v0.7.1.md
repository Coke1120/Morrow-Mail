# Morrow Mail 0.7.1

This release fixes cached Read/Unread states that could disagree with the server indefinitely and an IMAP folder failure that could stall reconciliation of other cached messages.

## Changes

- **Repair stale read states:** fetched Gmail/IMAP Read/Unread values now replace obsolete local flags even when the provider value is unchanged from the last snapshot. This works in both directions and after restart, matching Outlook's existing behavior. Confirmed star-write responses also apply the returned read state. Unrelated local stars, Pending, folder choices and account ownership remain protected.
- **Continue past missing IMAP folders:** after an EXAMINE rejection, a successful complete LIST must confirm the folder is absent before it is marked unavailable. Other folders in the batch continue, cached content stays intact, and future rounds can detect a restored folder. Failed LIST responses, connection errors and failures on existing folders remain errors.
- **Keep unknown state unknown:** missing/deleted messages retain their last known flags and provider snapshot instead of treating cached local values as fresh server metadata. No cached mail is deleted by these repairs.

## Validation and limits

Regression fixtures cover both read-state directions, unchanged snapshots, restart, partial metadata, account collisions, local markers, confirmed flag writes, missing/restored IMAP folders and rejected folder-list responses. The existing paired tagged workflow requires Node-free formatting, strict Clippy, locked Rust tests, macOS and Windows native packaging/acceptance, and same-run/same-attempt artifact provenance before the pinned-key publisher exposes either download. No test waiver applies. See VERIFICATION.md for completed checks and public-download evidence.

Sync remains bounded polling: Gmail/IMAP check up to 50 cached messages per round; Outlook checks up to 25 plus a delta page. Use another manual Sync or enable a regular interval for larger caches. Gmail History API and IMAP IDLE/CONDSTORE/QRESYNC are not implemented. Failed provider writes are never automatically replayed.

**macOS is ad-hoc signed without Apple notarization; Windows is unsigned.** Full live-provider/model acceptance, a separately provisioned clean Windows VM, complete keyboard/screen-reader/physical-pointer coverage and installed-updater restart/rollback remain unverified. Passing fixtures does not establish live-account acceptance or resolve the previously observed intermittent Windows reader initialization timeout. Tests use isolated fictional mailboxes, without real sends, calendar events or paid model calls.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs and checksums, or the explicit in-app update flow. Extract the whole Windows folder. Keep the separate mailbox workspace backed up and run one client against it. Older clients using the retired repository URL need a manual download.
