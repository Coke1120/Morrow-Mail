## Gmail history authorization correction

PR #47 restores manual recovery after a history-download authorization failure.
Routine access-token expiry still permits a refresh **before** the page request.
Once a history resource API returns HTTP 401, the import instead stops with the
existing safe authorization/reconnect error: it preserves its checkpoint and
cached mail, discards the uncommitted partial page, and makes no forced token
refresh or automatic repeat of that page. Background ticks and app restarts do
not retry that authorization failure. Existing backoff for eligible transient
history read failures is unchanged.

After authorization recovery, explicit **Resume** can retain the checkpoint only
while the saved connection identity is unchanged. Browser reconnect replaces
that identity, so start a **new import** afterward; cached mail remains. A failed
routine token exchange also requires the existing manual recovery action before
another exchange attempt. This distinction prevents normal expiry refresh from
being confused with retrying a rejected resource request.

PR #46 had incorrectly extended its read-recovery wrapper to history pages.
Its passing history test encoded that incorrect policy expectation. PR #47
removes only that wrapper from history; the earlier test and CI results remain
historical evidence, not proof that the old history behavior was correct. The
correction is absent from the preserved v0.8.0 tag.

## Other Gmail reconnect fixes retained

- An owned Gmail sync, folder/catalog read or raw-message read for an attachment
  can refresh once after a resource HTTP 401 and retry the read operation once.
  A second 401 or failed token exchange ends recovery. Other resource statuses,
  Outlook, Calendar, sending and provider mutations do not enter this wrapper.
  The saved connection is checked before refresh and result commit. Sync uses
  its last durable checkpoint and a fresh fetch cache, without duplicate arrival
  jobs; two bounded attempts can exceed one attempt's total request count.
- When successful browser reauthorization omits a nonblank refresh token, retain
  the saved token only for the same verified mailbox, provider, OAuth client
  credentials, grant purpose and granted-scope set. Keep the new access token
  and expiry; a newly supplied refresh token takes precedence. Incompatible
  credentials, including an Out-of-Office scope expansion without a new refresh
  token, reject replacement while retaining the existing connection and cache.

Other mailbox connections, cached messages and drafts remain account-owned.
These fixes do not renew revoked grants, change Google OAuth project settings,
prove that Google still accepts a retained token, or establish the cause of a
particular user's repeated sign-in prompts. Shutdown after provider-side token
rotation but before durable local storage remains an existing recovery limit.

## Writing, Today and Inbox Agent

- **Mailbox writing rules:** create, edit, enable, disable and remove explicit
  mailbox rules shared by permitted writing actions, including Agent drafts.
  Native editors retain their own unsaved text and edits made during saves;
  navigation, quit and update guards protect that work.
- **Today and categories:** ordered categories are local labels, not a new AI
  classifier. Confirm completion or reopening of suggestions; retained summary
  suggestions survive a newer queued or failed job. Completing unread suggestions
  admits older eligible mail without marking it read. The capacity, history-view
  and ordering limits below remain.
- **Skill review schedules:** due local schedules queue account-owned review
  items; they do not call a model, send mail or silently change Email Brain.
- **Local Inbox Agent:** mailbox-owned conversations use the configured
  OpenAI-compatible model and permitted downloaded correspondence. The service
  checks ownership, permissions, connection identity and aggregate message limits.
  Actions and delivery require confirmation; send review includes the complete
  body, From/To/Cc/Bcc, attachment identities and effective footer. Changed source
  or reviewed payload requires renewed approval. Stop discards unpublished staged
  drafts; saved drafts remain, and confirmed actions or delivery cannot be undone.
  Interrupted turns recover through read-only fetches without replaying writes.
  Read/star changes can reach supported providers; folder and Pending shortcuts
  are local. All accounts remains an aggregate view, not an agent or sender.
- **Windows diagnostics:** bounded acquisition provenance and reader timelines
  preserve observation failures. They do not repair or waive unknown native
  error 87, unknown exits or WebView failures.

## Distribution and known limits

**macOS is ad-hoc signed without Developer ID notarization; Windows is unsigned.**
The update signature binds version and archive integrity; source binding comes
from separate publisher CI/artifact/tag checks. It is not OS code signing.
Manual keyboard, VoiceOver/Narrator, large-text/focus, physical-device and clean-
machine acceptance remain incomplete, along with live-account/provider/model
use and complete installed-updater restart/rollback acceptance.

Today keeps at most 200 completion markers per mailbox; eviction can make older
still-eligible unread mail appear again. Only the latest 20 completed items per
mailbox are exposed for reopening. Unread suggestions do not carry category
priority into final task ordering and can fall behind lower-priority summary
items. The separate Today retention/pagination/priority follow-up is excluded.

Historical Windows first-acquire error 87/unknown-exit and shutdown-inventory
failures remain unresolved. Intermittent macOS adversarial-reader and Windows
reader-initialization failures are not declared fixed by another passing run.
Existing IMAP namespace and bounded-content limits remain. Tests used fictional
workspaces and loopback model/provider fixtures, not customer mail, real delivery,
paid models or Google Console changes. Version numbering does not certify
error-free operation or production readiness.

Use the paired macOS 13.5+ Apple silicon / Windows 10/11 x64 ZIPs with their
SHA-256 files, or the explicit in-app update flow. Extract the whole Windows
folder. Back up the separate mailbox workspace, quit the old app before replacing
it, and run one client against that workspace. Older clients using the retired
repository URL require a manual download.
