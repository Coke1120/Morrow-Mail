# Morrow Mail 0.7.0

Morrow Mail now uses ordinary version numbers, starting with **0.7.0**. This release adds native attachments, newest-first mail imports and agent CLI synchronization, and improves Today and update restart behavior.

## Changes

- **Attachments on both platforms:** add/remove files, explicitly download/save received attachments with OS quarantine, and include owned attachments in reviewed sends, forwards, copied drafts and scheduled messages. The local limit is **100 files / 50 MiB total per message**, with an 80 MiB raw MIME download ceiling. Provider sending limits and encoding overhead still apply. Outlook uses Graph upload sessions for larger files. Only explicitly downloaded raster CID images render inline; attachment bytes stay out of AI context.
- **Recent mail first:** new history imports fetch the latest seven days across the selected folders before older mail. Existing imports keep their saved checkpoint and scope. Gmail and IMAP reconcile cached metadata in bounded batches and write read/star changes back with the required provider permissions. Remote deletion retains cached content; IMAP validates UIDVALIDITY before acting on a location.
- **Agent CLI:** explicit `sync --dry-run`, `sync`, `status`, MIME `fetch`, `attachment-add` and `attachment-read` join cached reading and reviewed draft/send commands. Partial sync returns exit code 4. The CLI shares the app’s account boundaries and single Rust/SQLite writer; it never automatically retries an uncertain delivery.
- **Today:** one stable summary card per mailbox/local date updates from the latest validated jobs instead of adding repeated daily cards. Individual jobs remain in Summary History; a failed new attempt retains earlier valid summary content.
- **Install & Restart during activity:** new work freezes while accepted requests drain within the existing 65-second shutdown deadline. Historical downloads and safe indexing checkpoints resume with the original scope/budget; interrupted manual sync can continue once even with periodic sync off. Unsaved edits remain protected. Uncertain sends/calendar writes and incomplete paid requests never replay automatically.
- **Windows reliability and documentation:** reader lifecycle checks reject obsolete unload events and provide a bounded startup fallback. PowerShell 5.1 relocated-package checks exercise fresh, owned and restarted workspaces from a Unicode path without developer tools. The shorter README links to dedicated user and CLI guides.

## Validation and limits

Both tagged platform jobs must pass Node-free Rust formatting, strict Clippy and locked tests, native packaging and acceptance before either download becomes public. Windows also runs the relocated-package check and the 1,000/10,000/50,000-message fictional-mail benchmark. The publisher verifies same-run/same-attempt artifacts and signs the update manifest with the existing pinned key. No test waiver applies. Test evidence and public-download verification are recorded in VERIFICATION.md.

**macOS is ad-hoc signed without Apple notarization; Windows is unsigned.** Numbered releases do not claim that signing or all production acceptance is complete. Full real-provider/model use, a separately provisioned clean Windows VM, complete keyboard/screen-reader/physical-pointer coverage and installed-updater restart/rollback remain unverified. The earlier intermittent Windows reader initialization timeout is not declared resolved solely by passing fixtures. Tests use fictional providers and isolated workspaces; they do not send real mail, create real calendar events or make paid model requests.

Sync is bounded polling, not a complete mailbox mirror or push synchronization. Gmail History API and IMAP CONDSTORE/QRESYNC are not implemented. Larger local attachment limits do not override provider mail-size limits. Automatic orphan-attachment cleanup, antivirus and arbitrary embedded file previews are not included. Interrupted larger Outlook sends can leave a provider draft and require review.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs and checksums, or the explicit in-app update flow. Extract the whole Windows folder. Keep the separate mailbox workspace backed up and run one client against it. Older clients using the retired repository URL need a manual download. Existing clients can discover 0.7.0 through either update channel.
