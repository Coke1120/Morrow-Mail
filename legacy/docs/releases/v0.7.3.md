# Morrow Mail 0.7.3

This release includes merged PR28 and PR29: visible-mail synchronization takes priority while older cached mail still receives its normal checks, and Windows restores the sidebar selection when an attachment save blocks navigation.

## Changes

- **Sync the selected message and visible page first:** native clients publish at most 51 account/local-ID pairs, with the selected message first. Hints expire after 90 seconds and bind to the current account connection. Existing Gmail/IMAP 50-row and Outlook 25-row background quotas, import checkpoints and user-controlled sync intervals remain. Combined views retain account ownership and duplicate-ID isolation.
- **Reuse proven immutable content:** recent IMAP/Outlook pages still fetch current metadata and flags, but reuse complete cached bodies only when the owner, connection and provider identity match. IMAP also checks folder, UIDVALIDITY, UID, Message-ID, size and complete headers. Drafts, incomplete content and uncertain identities fetch normally. Provider draft-to-Sent transitions fetch the final body; reviewed local sent payloads and owned downloaded attachments remain intact.
- **Keep Windows navigation consistent during attachment saves:** rejected real sidebar invocations restore WinUI's canonical selected account/folder, matching the retained mailbox, page, cursor and reader. Navigation resumes after save completion or failure. Captured ownership, saved-file integrity and quarantine protections remain.
- **Retain native mail context:** macOS search results keep their current page and rows after reading or saving a reply, with one bounded last-page recovery when needed. Attachment-removal names identify the file, and the macOS footer removal identifies the footer.
- **Keep strict native evidence:** the bounded original-pin zero-exit proof uses the same verified handle, identity, live parent and shared deadline. First-acquire failures, unknown/nonzero exits and incomplete observations still fail. The existing 180-second UI/collector and 30-second reader gates are unchanged.

## Validation and known limits

[PR28 paired CI 38136009365](https://github.com/Coke1120/Morrow-Mail/actions/runs/38136009365) passed its reviewed candidate. The subsequent [merged-main CI 38137948551](https://github.com/Coke1120/Morrow-Mail/actions/runs/38137948551), at `277c9ccf17b285587ec07be8fc77729d418d904e`, passed macOS but **failed the Windows strict observation gate**. Owned and restart cases each contained a first-acquire `nativeAcquire`, native error **87**, unknown/null-exit record. Functional fixture results do not establish normal process exits or repair those missing observations. Windows relocated-package acceptance was skipped in that failed run.

The release tag must separately pass the existing macOS and Windows jobs before either download becomes public. The existing publisher verifies same-run/same-attempt provenance and signs the update manifest with the pinned key. **No test waiver applies.** See VERIFICATION.md for the tagged run and publication outcome.

**Windows first-acquire observer failures remain unresolved, and the Mac mini Parallels Windows acceptance is incomplete.** Native picker/dialog cancellation, complete physical keyboard/VoiceOver/Narrator coverage, manual same-source cross-platform UX and real-account/model acceptance remain unverified. Intermittent macOS adversarial-reader and Windows reader-initialization timeouts are not declared fixed by passing fixtures. Point sampling does not establish complete process-lifetime coverage or lifetime resource peaks.

Sync remains bounded polling while the app runs; this release does not add Gmail History, IMAP IDLE or push notifications. Existing content/import limits, the IMAP reconnect namespace limitation and Windows non-paging async error-detail limitation remain. Failed provider writes and uncertain sends are never automatically replayed.

**macOS is ad-hoc signed without Apple notarization; Windows is unsigned.** Separate clean-machine and installed-updater restart/rollback acceptance remains incomplete. Tests use isolated fictional mailboxes and generated fixture credentials, without real sends, calendar events, paid model calls or customer data. Version numbering does not certify production readiness.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs and SHA-256 files, or the explicit in-app update flow. Extract the whole Windows folder. Back up the separate mailbox workspace and run one client against it. Older clients using the retired repository URL require a manual download.
