# Morrow Mail 0.6.0-beta.40

This beta speeds up opening downloaded Gmail labels and Outlook/IMAP server folders by replacing full cached-message JSON scans with an account-scoped SQLite membership index. Search within those folders uses the same lookup.

## Changes

- Index exact provider label/folder membership separately from the keyword index, avoiding repeated scans of every cached body when counting messages and loading a page.
- Build membership for existing cached mail once on first open. A large cache can add startup time during this initial upgrade; cached messages, drafts, settings and the original encryption key are preserved.
- Maintain membership atomically when messages are imported, moved, relabeled or deleted. Overlapping Gmail labels and folder IDs do not duplicate a message; local folder overrides remain separate from provider membership.
- Keep downloaded folder pages complete while the keyword index is rebuilding, and preserve account isolation, six sorting choices, unread filtering and cursor/offset pagination.

Browsing still shows downloaded messages only. Folder discovery does not download all server mail or establish a complete mirror. Provider write permissions, review and uncertain-write recovery remain unchanged.

## Validation and limits

All 201 locked Rust tests, formatting, strict all-target Clippy, local macOS candidate packaging and full production-service native acceptance passed before release preparation. New regressions cover cross-account duplicate IDs, label deduplication, updates/deletion/rollback, legacy membership compatibility, first-open migration, keyword-index recovery, restart/backup, paging, sorting and folder-scoped search.

In an isolated SQLite fixture with two mailboxes and 50,000 cached messages containing 8 KB fictional bodies, median SQL count-plus-first-page time fell from 536.53 ms to 1.65 ms across five warm requests, with identical totals and returned rows. These are SQL measurements, excluding HTTP, Rust decoding, full startup and UI rendering; they do not establish real-account or cold-cache latency. The one-time membership creation/backfill took 493.36 ms in that fixture. See VERIFICATION.md for the method and smaller dataset.

The existing paired workflow requires fresh tagged macOS and Windows builds, Node-free Rust formatting, strict all-target Clippy and locked tests, full macOS production-service acceptance, the Windows fresh/owned/restart UI walkthrough and fictional-mail benchmark before either download becomes public. The existing publisher verifies same-run/same-attempt platform artifacts and signs the update manifest against the unchanged pinned public key. No test waiver applies.

Checks use fictional mail/providers and isolated temporary workspaces. No real mail, calendar event or paid-model request is submitted. Full live-account/provider/model, physical-pointer/accessibility and clean-machine acceptance remain incomplete. The previously recorded intermittent Windows reader initialization timeout and installed-updater acceptance limits remain; passing fixtures do not establish real-account acceptance. macOS is ad-hoc signed without notarization; Windows is unsigned. This is an experimental prerelease.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs or the explicit in-app update flow. Keep the separate mailbox workspace backed up and run one client against it. Publication and public-download verification are recorded in VERIFICATION.md.
