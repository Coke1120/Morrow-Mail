# Morrow Mail 0.6.0-beta.46

This beta includes PR #21's reply routing, account recovery and delivery review fixes.

## Changes

- Incoming Reply and Reply All use Reply-To supplied by Gmail, Microsoft or MIME/IMAP, falling back to From when absent. Reply All retains owner and original Bcc exclusions; forwards keep blank recipients and no reply thread.
- Reconnecting a disconnected mailbox with different address casing reuses its cached account identity, keeping messages and drafts visible. Conflicting legacy identities are rejected without deleting or merging cached data.
- Both native composers offer reviewed **I found it in Sent** and **Close without retrying** decisions for an unconfirmed delivery. They move the retained local copy to Sent or Archive, preserve the original request/payload ledger and decision across restart, and block replay, including uncertain scheduled sends. These are local user decisions; they make no provider write and do not establish provider-verified delivery.
- Readers, reply history and prepared forwards/provider-draft copies disclose truncated downloaded text. The existing 100,000-character download limit remains; forward/copy disclosures respect the composer UTF-16 limit. Legacy Gmail metadata is repaired when messages are fetched within the existing bounded scopes.
- macOS falls back to downloaded plain text when HTML navigation or the reader process fails, with external images blocked. Selecting another message restores the isolated reader.

## Validation and limits

Fresh tagged macOS and Windows builds, Node-free Rust formatting, strict all-target Clippy and locked tests, full macOS production-service acceptance, the Windows fresh/owned/restart UI walkthrough and fictional-mail benchmark must pass before either download is public. The existing publisher verifies same-run/same-attempt platform artifacts and signs the update manifest against the pinned public key. No test waiver applies.

Regression checks cover Reply-To and Bcc routing, duplicate account IDs, reconnect/cache casing ambiguity, truncation boundaries and multipart text, Gmail metadata backfill, explicit delivery-resolution confirmation/account guards, durable idempotent closure, blocked replay and scheduled restart recovery. Native checks exercise reader failure recovery, composer resolution controls and incomplete-text disclosure. Tagged CI and public-download verification are recorded in VERIFICATION.md.

Checks use fictional mail/providers and isolated temporary workspaces. No real mail, calendar event or paid-model request is submitted. Full attachments, continuous provider delta/deletion sync, full live-account/provider/model, real external HTTPS image fetching, physical-pointer/accessibility, clean-machine and complete installed-updater restart/rollback acceptance remain incomplete. The previously recorded intermittent Windows reader initialization timeout remains unresolved. macOS is ad-hoc signed without notarization; Windows is unsigned. This is an experimental prerelease.

## Install and update

Use the paired macOS arm64 / Windows x64 ZIPs or the explicit in-app update flow. Keep the separate mailbox workspace backed up and run one client against it.
