# Morrow Mail 0.7.8

This release follows published [v0.7.7](https://github.com/Coke1120/Morrow-Mail/releases/tag/v0.7.7)
and adds the IMAP and AI Studio changes below. Published v0.7.7 assets stay unchanged.
Product source is main `b5d049802b24bcd32397e4987f25038fc1924046`. This
preparation changes only the common `package.json` version and release
documentation.

## IMAP flag progress

[PR #34](https://github.com/Coke1120/Morrow-Mail/pull/34) discovers changed
cached IMAP UIDs in bounded MODSEQ windows and applies their flags inside the
existing 50-message background budget. At most 1,000 UIDs are queued, each
discovery window spans at most 1,000 UIDs, and a discovery response is capped at
128 KiB. Pending UIDs and scan bounds survive restart. Message updates, the
queue, the scan, and the row cursor commit in one transaction. Unchanged MODSEQ
reads use the saved provider snapshot, so a local-only star is not treated as
remote truth; a missing snapshot rereads flags. Valid legacy proofs can seed
folder progress once. Capability loss, a UIDVALIDITY or connection change, and a
regressed MODSEQ drop incremental proof while cached content stays.

This is still polling. Sparse UID space and large change bursts need more
rounds. Servers without a usable MODSEQ keep ordinary flag checks. Push/IDLE is
not included. Cached bodies, attachments, Pending, stable local IDs, Gmail
history, and Graph progress stay on their existing paths.

The design was informed by Thunderbird desktop
[`30cdf5a03b41253e744bc058a699c1947a2b8123`](https://github.com/thunderbird/thunderbird-desktop/tree/30cdf5a03b41253e744bc058a699c1947a2b8123)
(`nsImapProtocol.cpp`, `nsImapMailFolder.cpp`) and RFC 7162 / RFC 9051. Those
MPL files were read for design only; no Thunderbird code was copied. See
[the implementation note](https://github.com/Coke1120/Morrow-Mail/blob/v0.7.8/docs/THUNDERBIRD_IMAP_SYNC.md).

One Linux cloud comparison of a 50,000-message synthetic cache, with UID 25,000
changing read/star state, went from 500 background rounds / 3,000 IMAP commands /
25,000 SQLite message updates to 1 round / 34 commands / 50 updates, with no
body or indexed-text changes. Elapsed time on that shared host was 342.66s
versus 1.86s. That single observation excludes seeding, polling delay, WAN,
provider limits, and native UI. It is not a live-account or interface speed claim.

## Reconcile stalls

[PR #39](https://github.com/Coke1120/Morrow-Mail/pull/39) repairs four IMAP
background stalls found in the Astra review:

- Folder rotation wraps to the first cached folder, including a name that sorts
  before INBOX, instead of always returning to INBOX.
- Mail retained from an older UIDVALIDITY no longer clears the live folder's
  MODSEQ, scan, or pending queue.
- During discovery, VANISHED without EARLIER is accepted when the UID FETCH ends
  tagged OK. VANISHED (EARLIER) still fails that round.
- When a full changed queue omits the rotation cursor, one batch slot stays with
  that cursor so expunge checks can advance. A queue that already contains the
  cursor still uses the full 50-message budget.

Cached bodies stay in place. Gmail reconciliation, send retry, and live-account
acceptance are unchanged.

## AI Studio and navigation

[PR #40](https://github.com/Coke1120/Morrow-Mail/pull/40) changes both native
clients:

- AI Studio no longer lists Summaries. Today already shows saved summaries, and
  the Summary history link is removed. The old summaries route opens Assistant.
  Scheduled summary results are described on Today.
- Studio mailbox tabs follow the same All/account control as Today and Reply
  suggestions (`ReviewAccountTabs` / `review.scope`). Choosing a tab filters
  Studio only. It does not call `selectAccount` and does not replace the mailbox
  being read. Inbox-wide Assistant actions still need one mailbox tab. A selected
  message can still run on that message's account. Studio, Today, and Reply
  suggestions share this scope, so a tab change in one place changes the others.
- Sync, the 30-second refresh, Studio generate and memory suggestions, style
  preview/generate/Learn Now, Today summary generation, and local-rule
  preview/apply/remove no longer lock sidebar or account-tab navigation. Buttons
  that start that work stay disabled while it runs. Selecting an account still
  uses the short navigation lock, as do Windows account patch/trash/undo and
  calendar event submit. Unsaved Studio notes still block sidebar navigation
  through the existing unsaved-form guard.

## Distribution and coverage limits

macOS is ad-hoc signed without Developer ID notarization. Windows is unsigned.
Manual VoiceOver/Narrator, keyboard/focus/large-text, clean-machine, installed-app,
real-device UI smoke, and real-account/model/provider acceptance remain
incomplete. Hosted fixture UI checks are not that device acceptance.

Residual Windows observation failures recorded with v0.7.7 stay failures,
including preceding main first-acquire native error 87 / unknown-exit and
shutdown-inventory gaps. Later green samples do not establish that every main
run is green or that native error 87 is universally solved. See
[v0.7.7 publication evidence](https://github.com/Coke1120/Morrow-Mail/blob/v0.7.8/docs/releases/v0.7.7-verification.md).

IMAP progress is bounded polling, not a complete mailbox mirror. The synthetic
MODSEQ comparison is one Linux observation and does not establish live-account
or native UI latency. AI Studio still requires explicit review before model
calls, and navigation remaining available does not send mail or apply an unsaved
form. Only fictional temporary workspaces were used for the recorded checks. This
release does not claim error-free operation.
