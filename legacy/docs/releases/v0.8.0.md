## Gmail reconnect recovery

PR #46 addresses two reproduced reconnect failures:

- **Recover a rejected Gmail access token during eligible reads.** An owned
  Gmail sync, import page, folder/catalog read or raw-attachment download that
  receives a resource HTTP 401 may force one token refresh and retry that read
  operation once. A second resource 401 or a failed token exchange ends this
  recovery attempt. Resource 403/429/5xx responses do not trigger this refresh
  path. Outlook and Calendar do not receive the new read-retry wrapper.
- **Preserve compatible refresh credentials after browser sign-in.** If a
  successful mailbox reauthorization omits a nonblank refresh token, the saved
  token is retained only for the same verified mailbox, provider, OAuth client
  credentials, grant purpose and granted-scope set. The new access token and
  expiry remain from the successful callback. A newly returned refresh token
  takes precedence. Missing or incompatible saved credentials reject the change
  while retaining the existing connection and cached mail. An Out-of-Office
  scope expansion without a new refresh token also fails without replacing the
  old connection.

The service checks that the saved connection has not changed before refresh
and before committing its result. Other mailbox connections and account-owned
cached messages and drafts are retained. A sync retry starts from the last durable
checkpoint with a fresh fetch cache; revisited messages do not enqueue duplicate
arrival jobs. Each attempt keeps the existing page/detail bounds. A late 401
can therefore make one sync perform up to two bounded read-operation attempts;
this is not a promise of an unchanged total request count.

Sending and provider mutations are not replayed by this recovery path. Token
exchange failures retain their existing reconnect/configuration/transient-error
classification. History authentication failures still require the existing
manual reconnect/resume handling. These fixes do not renew a revoked grant,
change Google OAuth project settings or expiry policies, or establish the cause
of any particular user's repeated sign-in prompts. Preserving a compatible
refresh token does not independently prove that Google will still accept it.
An abrupt shutdown after provider-side token rotation but before durable local
storage remains an existing recovery limitation.

## Writing, Today and Inbox Agent

- **Mailbox writing rules:** create, edit, enable, disable and remove explicit
  rules for a mailbox. Permitted writing actions share the existing writing
  context, including Inbox Agent draft generation. Each native rule editor
  preserves its own unsaved text, including edits made while a save is in flight.
  Account, page, quit and update guards retain unsaved work.
- **Today and mailbox categories:** save an ordered category list per mailbox,
  and complete or reopen local suggestions with confirmation. Valid saved
  summary suggestions remain available while a newer job is queued or failed.
  Completing unread suggestions makes room for older unread Inbox mail without
  changing its read state. A bounded indexed query and compatible completion
  identities preserve retained progress across restarts and long provider IDs.
  Categories are local labels selected by priority and order, not a new AI
  classifier. The completion-capacity and ordering limits below still apply.
- **Skill review schedules:** install or edit local library skills and queue
  account-owned reviews at the configured interval. A due schedule queues an
  item; it does not call a model, send mail or silently change Email Brain.
- **Local Inbox Agent:** keep mailbox-owned conversations on this device and
  use the configured OpenAI-compatible model. The agent can inspect permitted
  downloaded correspondence, prepare drafts and propose actions. The server
  rechecks source ownership, current permissions, connection identity and the
  aggregate message limit before accepting results.
- **Explicit action and send review:** mailbox changes and delivery require
  confirmation. Send review includes the full body, From/To/Cc/Bcc, attachment
  identities and the effective footer. Changed action sources or permissions
  invalidate mailbox-action approval; changed drafts, senders or connections
  require a fresh send review. Reply drafts preserve Reply-To. Stop cancels the
  local turn and discards unpublished staged drafts; saved drafts remain. It
  cannot undo an action or delivery already confirmed. Interrupted Inbox Agent
  turns and confirmations recover through read-only conversation fetches without
  replaying writes. Confirmed read/star changes can update supported providers
  through existing controls; folder and Pending shortcuts are local.
- **Windows diagnostics:** preserve bounded process-acquisition evidence and a
  reader lifecycle timeline without weakening complete-observation requirements.
  This is diagnostic evidence, not a claim that native error 87 or WebView
  process-failure causes have been repaired.

These changes use the existing downloaded-mail and account-scoped mutation
paths. They do not add push synchronization, a full mailbox mirror, autonomous
mail delivery or hidden external AI requests. All accounts remains an aggregate
view, not a sending or agent identity.

## Distribution and coverage limits

**macOS is ad-hoc signed without Developer ID notarization; Windows is unsigned.**
The update-manifest signature covers the version and paired archive integrity;
source commit binding comes from the publisher's separate CI artifact, tag and
run checks. Neither is Apple notarization or Windows Authenticode signing.
Manual keyboard, VoiceOver/Narrator, large-text/focus, physical-device and
clean-machine acceptance remain incomplete, as do live-account/provider/model
use and complete installed-updater restart/rollback acceptance.

Known Today limits remain: each mailbox retains at most 200 completion markers;
completing another suggestion evicts the oldest marker, and its still-eligible
unread mail can appear again. Only the latest 20 completed items per mailbox are
exposed in the current history view, so older retained items cannot be reopened
there. Unread-mail suggestions do not carry their category's priority into final
task ordering and can fall behind lower-priority summary items. The separate
retention/pagination/priority follow-up is not included in 0.8.0.

Previously recorded Windows first-acquire native error 87/unknown-exit and
shutdown-inventory failures remain unresolved observations. Intermittent macOS
adversarial-reader and Windows reader-initialization timeouts are not declared
fixed by a passing run. The failed v0.7.9 tagged walkthrough remains failed;
its specific failure evidence must be retained without inferring a root cause
from a successful earlier run. Existing IMAP namespace and bounded-content
limitations remain. Only isolated fictional workspaces and loopback model/provider
fixtures were used; no customer mailbox, real delivery, paid-model request or
Google Console change was used. Version numbering does not certify error-free
operation or production readiness.

## Install and update

Use the paired macOS 13.5+ Apple silicon / Windows 10/11 x64 ZIPs with their
SHA-256 files, or the explicit in-app update flow. Extract the entire Windows
folder and keep its files together. Back up the separate mailbox workspace,
quit the old app before replacing it, and run one client against that workspace.
Older clients using the retired repository URL require a manual download.
