# Morrow Mail 0.8.3

This release brings together the IMAP synchronization, recovery, Downloads and
native action work from PRs #51–#59. Existing release tags and assets remain
unchanged.

## Before upgrading

**Back up before first opening an existing workspace with this version.**
Use the previously installed service to make a verified backup, or copy the
complete closed workspace together with its matching `encryption.key`.
The new service migrates workspace schema 1 to schema 2 before its own backup
operation. Older clients reject schema 2. Downgrading requires restoring the
complete pre-upgrade copy; changing the schema marker is not a recovery method.
See the [migration guide](https://github.com/Coke1120/Morrow-Mail/blob/v0.8.3/docs/IMAP_SERVER_IDENTITY.md#before-upgrading).

## Mail synchronization and recovery

- IMAP cache identity now includes the server endpoint, login and mailbox
  identity. Reconnecting an address to a different server cannot silently reuse
  the old server's UIDs. Proven legacy messages keep their local identity;
  insufficiently proven copies remain readable locally and cannot authorize
  operations on the new server.
- Bounded read sessions reuse one owned connection within a synchronization
  round, retaining account, connection, UIDVALIDITY, cancellation and deadline
  checks. This is not persistent pooling or a complete mailbox mirror.
- **Folders to sync…** can select up to 20 eligible custom IMAP folders. Each
  Sync finishes foreground reads before visiting at most four selected folders
  with 50-message pages. Progress, coverage and recovery remain explicit.
  Older mail still uses history import; larger bursts can require several rounds.
- With automatic mail sync enabled, read-only IMAP IDLE notifications can hint
  that an ordinary bounded Sync is useful. At most four accounts and one folder
  per account hold rotating watches. Selected folders require a proven current
  baseline. **Manually** disables periodic Sync and these watches. Notifications
  neither advance checkpoints nor authorize provider writes, and continuous
  coverage or real-time delivery is not promised.
- Downloads controls expose local coverage and explicit account-owned repair
  actions. After content repair, both native clients refresh the shared page,
  committed search and selected reader without another mark-on-open write.
  Stale responses are rejected; page position and unsubmitted search edits are
  retained. Local move Undo persists across restart until later import or
  confirmed adoption invalidates its receipt.
- Reviewed IMAP moves prefer MOVE with UIDPLUS. UIDPLUS-only servers may use
  journaled COPYUID, a targeted deletion flag and UID EXPUNGE. Each stage records
  intent before transmission; uncertain work is never replayed automatically.
  Recovery checks the exact recorded copies and needs fresh confirmation.
  Interrupted moves can leave two copies requiring explicit review.

## Native actions and review

Reader commands are grouped around Reply, organization and optional AI actions.
Selection actions appear when mail is selected; Today can open an owned reply
suggestion for review in place. Empty Compose Cc/Bcc fields and advanced Studio
details can be revealed when needed. Existing account ownership, AI permissions,
evidence approval and explicit sending review remain required.

Summary activity uses bounded safe diagnostics and retains cancellation,
connection and stale-result protections. These changes do not enable automatic
sending, new provider writes or unreviewed model work.

## Verification and distribution limits

Controlled verification uses fictional mail and isolated workspaces. Native
mailbox timing measures event-to-layout/display requests with intercepted
responses, not compositor presentation or real service, SQLite or WAN cost.
Protocol fixtures and native measurements are separate evidence; synthetic
results do not establish an approved performance threshold or live acceptance.
Earlier failed, cancelled and incomplete native observations remain recorded.
The supplemental unprivileged macOS process-ownership probe cannot establish
ownership when system metadata requires root; its failed status is not a pass.

The unchanged paired tagged workflow requires both native platforms to pass in
the same run and attempt before either download becomes public. The existing
publisher validates paired artifacts and signs their update manifest. The
pinned Ed25519 signature binds version and archive integrity; source identity
is established separately by tag and CI provenance.

**macOS is ad-hoc signed without Developer ID notarization; Windows is unsigned.**
Live-provider/model, clean-machine, physical-device, full manual keyboard and
VoiceOver/Narrator, and installed-updater restart/rollback acceptance remain
incomplete. Numbered releases do not certify error-free operation.

Today still retains at most 200 completion markers per mailbox and exposes the
latest 20 for reopening. Evicted eligible suggestions can reappear; unread
suggestions do not inherit category priority for final ordering.

Use the paired macOS 13.5+ Apple silicon and Windows 10/11 x64 ZIPs with their
SHA-256 files, or the explicit in-app updater. Extract the entire Windows folder.
Quit the old app before replacing it, retain the separate mailbox workspace and
run only one client against that workspace. Clients using the retired repository
URL require a manual download.
