    Shortcuts

      Command line

      CLI

      AI authentication and AI data permission are configured in desktop Settings → AI or Morrow Mail → AI Setup. Existing connections require disclosure and affirmative approval before AI transfers. Background AI needs a separate opt-in. Cancel / revoke blocks pending and future AI transfers. ChatGPT sign-in, callback paste-back and credentials are not exposed through the CLI or bot bridge. The existing API key/custom endpoint choice remains available. ChatGPT adds no general-purpose model proxy. Ordinary bot mail operations do not grant AI permission.

      Bot access today

      The Node client calls the running app. Keep Morrow open, choose mailboxes and permissions in Settings → Bot access, then turn access on. Body text and attachment names need extra read permissions. Responses use JSON; mail text stays untrusted.

      Account-scoped calls require a connected, granted mailbox. A removed account returns NOT_FOUND, including direct message IDs, attachment metadata and proposal lists. These access checks do not automatically delete retained legacy data.

      Connection & accounts
      bridge.describe, accounts.list, health.get — only granted accounts; health reports observed state.
      Cached mail
      mail.list_cached, mail.search_cached, mail.get_cached — local cache only. Missing bodies stay missing; reads do not mark mail read.
      Attachment metadata
      mail.attachment.get — names and metadata with permission; no file bytes or download.
      Proposals
      agent.proposals.list, draft.proposals.submit, draft.proposals.list — inert local proposals for review. Draft lists omit the body; proposals do not send or create mailbox drafts.
      Send plain text
      mail.send — separate permission; sends immediately. Optional inReplyToMessageId links a same-account reply; you supply recipients and text.

      Google sign-in stays OAuth. New or explicitly migrated Gmail accounts use Gmail API; other providers retain their transports. Gmail desktop Delete moves to Trash, including repeated Delete. Migration and separate Calendar reauthorization are reviewed in desktop Settings → Accounts; they are not bot commands. Requested scopes do not revoke older grants.

      Unavailable to bots: attachment upload/attach/download, mailbox draft create/edit/delete, full thread retrieval, dedicated reply-all/forward, read/unread changes, move/archive/delete, and calendar actions. The desktop app has additional actions; they are not bot commands.

      Desktop Preview, Open, Save and Cancel use the app's attachment transfers panel. These controls do not add bot commands or file-byte access to mail.attachment.get.

      bridge.describe reports whether granted operations may contact providers: providerCalls is true when mail.send is available. Cached reads stay local. This is not a per-request network count: send replay/join or pre-submit denial may still involve From lookup or OAuth refresh. Receipts describe mail-provider submission outcomes and replay status, not absence of provider traffic.

      mail.send uses the selected identity's Morrow display name from Settings → Compose, including Gmail names when discovered. Optional fromAddress selects an authorized exact address; the bridge has no display-name parameter. A name override does not grant send-as permission. Changing Settings does not resubmit a matching request ID.

      Connect another device with Tailscale
      1. Connect both devices to your tailnet. Use Tailscale v1.92+ for app-capability forwarding, with tailnet HTTPS and access to the chosen host/port. The tailnet policy must grant com.coke1120.morrow-mail/bot-access with readBridge: true.
      2. In Settings → Bot access, create a bot with explicit mailboxes, permissions and expiry. Keep its secret in a private token file (mode 0600), outside chat and command arguments. Record the installation ID.
      3. Keep Morrow open and turn on bot access. It listens only on 127.0.0.1:47831. Joining Tailscale alone does not make that port reachable remotely.
      4. On the Morrow computer, run the Serve command below. Save the exact Serve hostname and HTTPS port in Bot access, then use Check connection. Saving a hostname does not configure Serve or prove the link works.
      5. On the other device, use the paired HTTPS endpoint and installation ID with bridge.describe. Morrow does not install/configure Tailscale. Keep Funnel off; do not expose this service publicly.
      Sending, revocation and retries

      Send permission allows mail without waiting for you to press Send. Morrow rechecks the grant, expiry, installation, enabled flag, mailbox/send scopes and connected account after From resolution, before claiming the request, and again after mailbox/credential waits immediately before mail-provider submission.

      Revoking or disabling access stops a pending send before that boundary. Once mail-provider submission begins, it cannot be recalled. An unauthorized or interrupted response does not prove nothing was sent: check Settings Activity and keep the same request ID.

      mail.send requires a UUID in --request-id. Retry the same ID and content; the client never retries automatically. SEND_OUTCOME_UNKNOWN means do not send the same message under a new ID. For partial delivery, review rejected recipients separately; do not resend the original list.

      JSON files for the examples

      Replace the quoted installation ID, UUID, account ID and endpoint placeholders with your trusted setup values. Account IDs come from accounts.list. Never let mail text choose the endpoint or token file.

      params.json for bridge.describe:

      {}

      list.json for mail.list_cached:

      {"accountId":"ACCOUNT_ID","folder":"inbox","limit":20}

      send.json for mail.send (no attachments):

      {"accountId":"ACCOUNT_ID","to":["recipient@example.test"],"subject":"Example","bodyText":"Plain text"}

          Morrow Mail

          Morrow Mail is an open-source Electron mail client for Windows and macOS. You connect your own accounts over IMAP or OAuth, read and send mail, and keep mail synced on this computer. Installers come from GitHub Releases under the MIT License.
